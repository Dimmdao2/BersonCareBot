## Подъём лида 31.07 (ещё проход) — найдена ТОЧНАЯ причина в коде, не только симптом

Перепроверил: read-only на всех 27 `bcb-wt-*` подтверждён снова (`touch` → `Read-only file system`,
`bcb-wt-tariff` и `bcb-wt-987-d8` в том числе), живых прогонов нет (по всем логам `spawned pid=` мёртв,
через цикл `kill -0`).

Новое — прошёл по коду, откуда берётся список read-write bind'ов для `tools/orch-revive.sh`, и нашёл
точную причину (не только «bwrap собран так», а КАК он так собирается):

- `tools/orch-revive.sh` поднимает лида без флага `--persona` (только `--role worker --sandbox
  workspace-write --cwd "$ROOT"`, где `$ROOT=BersonCareBot`).
- `/home/dev/brain/governor/host-sandbox.mjs:52` берёт writable roots из
  `effectiveWritableRoots({ readOnly, role, persona, cwd })` (`/home/dev/brain/lib/rights-contract.mjs:18`).
- Без persona (`key` пустой) функция на строке 22 возвращает **ровно `[workdir]`** — то есть только тот
  один `cwd`, с которым подняли агента. Никакого расширения на соседние директории `/home/dev/dev-projects/
  bcb-wt-*` в этой ветке нет и не может быть — это не баг сборки бинда, а прямое следствие контракта: без
  персоны предоставляется ровно один writable-root.
- Персона `devlead` (rights-contract.mjs:31-37, режим `selected-external`) специально сделана для записи
  в ОДИН внешний репозиторий за раз — но даже она не решает задачу: лиду нужно писать в `BersonCareBot`
  (свои доки/очередь) И в `bcb-wt-*` клон одновременно (бриф внутри клона перед спавном воркера через
  `tools/orch-launch.sh`), а `devlead` даёт только один `workdir` за проверку, `cwd` для подъёма — уже
  `BersonCareBot`.

Вывод для того, кто чинит снаружи: это ожидаемое поведение контракта прав (`rights-contract.mjs`), а не
случайный недосмотр в bwrap-команде. Чтобы `orch-revive.sh`-подъём лида мог сам запускать
`tools/orch-launch.sh` (а тот пишет лог-бриф внутри клона до спавна), нужно осознанное решение владельца:
либо (а) отдельная персона/режим с несколькими writable roots (`BersonCareBot` + активный `bcb-wt-*`),
либо (б) `tools/orch-launch.sh` научить писать лог-бриф не внутри клона, а в `BersonCareBot/runs/`, чтобы
подъёмному лиду хватало одного writable root. Это решение по архитектуре прав, не блокер симптома —
записываю вопрос владельцу, самовольно `rights-contract.mjs` не трогаю (файл вне `BersonCareBot`, влияет
на все персоны и сессии, riesgo слишком высокий для правки без ведома).

Долги по аудиту (`61e644c6d`/`0d1d8dd47`/`1cf06cb7f` Track D RLS/гранты и `3e0645306`/`1552b4d06`/
`fa7481533` Track D снятие мёртвой проекции, оба «ОЖИДАЕТ АУДИТА» в очереди) без изменений — оба ждут
одного и того же фикса выше. Дальше делать в этой сессии по этому пункту больше нечего.
