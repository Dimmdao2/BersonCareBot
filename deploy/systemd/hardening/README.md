# systemd sandboxing drop-ins

Ограничения ядра для служб BersonCare. Лежат **отдельно от юнитов**: юниты описывают, что запускать, эти
файлы — что процессу разрешено. Так ограничения переживают правку юнита и наоборот, а список исключений
собран в одном месте, как требует `IS-I1-06`.

Ставятся скриптом [`../../host/install-systemd-sandbox.sh`](../../host/install-systemd-sandbox.sh) в
`/etc/systemd/system/<unit>.d/10-bcb-sandbox.conf`.

## Что закрыто у всех служб

| Настройка | Что предотвращает |
| --- | --- |
| `User=`/`Group=` | своя учётка на службу: перекодировщик видео не читает окружение веб-приложения |
| `NoNewPrivileges` | процесс не может получить права через setuid-бинарь |
| `ProtectSystem=strict` | вся файловая система только на чтение, кроме явно перечисленного |
| `ProtectHome` | домашние каталоги невидимы |
| `PrivateTmp` | свой `/tmp`, чужие временные файлы недоступны |
| `PrivateDevices` | нет доступа к блочным устройствам — в том числе к самому зашифрованному тому |
| `ProtectProc=invisible`, `ProcSubset=pid` | не видно чужих процессов и их окружения |
| `ProtectKernel*`, `ProtectControlGroups`, `ProtectClock` | нельзя менять параметры ядра, модули, cgroup и часы |
| `RestrictAddressFamilies` | только Unix-сокеты и IP: ни raw-сокетов, ни netlink |
| `RestrictNamespaces`, `RestrictRealtime`, `RestrictSUIDSGID`, `LockPersonality` | закрывают типовые пути повышения привилегий |
| `CapabilityBoundingSet=` пустой | у процесса нет ни одной привилегии ядра |
| `SystemCallFilter=@system-service` | системные вызовы вне обычного набора службы отклоняются |
| `UMask=0077` | созданные файлы недоступны никому, кроме владельца |

## Осознанные исключения

Их два, оба вынужденные — и оба записаны здесь, а не спрятаны в конфиге:

1. **`MemoryDenyWriteExecute` не включается.** Node компилирует JavaScript в машинный код на лету, ему нужна
   память, одновременно доступная на запись и исполнение. С этой настройкой процесс не стартует вообще.
2. **`SystemCallFilter` дополнен `@resources` для media-worker.** ffmpeg управляет приоритетами и лимитами
   потоков; без этого перекодирование падает по SIGSYS.

## Особое у media-worker

- `CPUQuota=50%` — ffmpeg запускается без ограничения числа потоков и одной задачей занимает все ядра. Без
  квоты загрузка видео врачом подвешивает интерфейс всем остальным.
- `Environment=TMPDIR=…` на дисковый каталог с известным размером. По умолчанию временные файлы уехали бы в
  `/tmp`, а он на части систем в оперативной памяти — двухгигабайтный ролик тогда кладёт машину.
