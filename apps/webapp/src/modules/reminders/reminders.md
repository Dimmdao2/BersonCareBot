# reminders

Сервисные правила напоминаний в **webapp** (`public.reminder_rules` — единственный источник истины для CRUD и scheduler-read), журнал действий (`reminder_journal`), API пациента и integrator M2M. **Фактическая отправка push** и технический lifecycle occurrence для правил **с ботом** (`integrator_user_id` задан) выполняются в **integrator**; `getEnabledReminderRules` читает канонические правила только в exact organization principal и учитывает `platform_users.reminder_muted_until`. `integrator.user_reminder_occurrences` / `user_reminder_delivery_logs` сохраняют техническую историю, а их `rule_id` ссылается на стабильный `public.reminder_rules.integrator_rule_id` с `ON DELETE RESTRICT`.

`integrator.user_reminder_rules` не является runtime-источником и не получает новых записей. Таблица сохранена как legacy: в репозитории есть ещё one-shot backfill/reconcile-инструменты, поэтому условие zero consumers для её удаления не выполнено; отдельный retirement удалит её лишь после снятия этих инструментов.

**Web Push без бота** (`integrator_user_id IS NULL`, есть `platform_user_id` и подписка): единое правило хранится в `public.reminder_rules`; штатный integrator scheduler создаёт канонические occurrence, а delivery worker отправляет канал Web Push через общий delivery pipeline.

## Наблюдаемость (admin)

- **Краткий срез в «Здоровье системы»:** [`GET /api/admin/system-health`](../../app/api/admin/system-health/route.ts) → поле **`remindersPipeline`** в теле ответа (в т.ч. **`patientReminderM2mIdempotencyKeysActive`** — активные ключи idempotency M2M push/email) и проба **`reminders_pipeline`** в **`meta.probes`** (реализация: [`collectAdminSystemHealthData.ts`](../../app-layer/health/collectAdminSystemHealthData.ts), [`adminReminderPipelineMetrics.ts`](../../app-layer/health/adminReminderPipelineMetrics.ts)); UI — аккордеон «Напоминания» в [`SystemHealthSection.tsx`](../../app/app/settings/SystemHealthSection.tsx).
- **Детальная статистика за окно (`windowHours`, пресеты UI **24 ч** / **7 дн.** / **30 дн.**):** [`GET /api/admin/reminder-stats`](../../app/api/admin/reminder-stats/route.ts) (admin mode) и **`GET /api/doctor/content-stats`** (doctor/admin без admin mode) — один загрузчик **`loadContentEngagementStats`** ([`loadAdminReminderStats.ts`](../../app-layer/stats/loadAdminReminderStats.ts)); audience — **`loadDoctorAnalyticsAudience()`** → `excludedUserIds` (тестовые аккаунты исключены без **`dev_mode`**; см. [`DOCTOR_DASHBOARD_METRICS.md`](../../../../../docs/ARCHITECTURE/DOCTOR_DASHBOARD_METRICS.md)). UI напоминаний — **`/app/doctor/analytics/notifications`**, компонент [`ReminderStatsSection.tsx`](../../app/app/settings/ReminderStatsSection.tsx); дашборд контента на **`/app/doctor/material-ratings`** — [`MaterialContentStatsClient.tsx`](../../app/app/doctor/material-ratings/MaterialContentStatsClient.tsx). Контракт — [`api.md`](../../app/api/api.md) (**admin/reminder-stats**, **doctor/content-stats**); канон KPI — [`MATERIAL_RATINGS.md`](../../../../../docs/ARCHITECTURE/MATERIAL_RATINGS.md) §«Дашборд content-stats». Ключевые поля: **`peopleWithNotifications`**, **`displayTimezone`**, **`pushOpensSummary`** (`opened` — `product_analytics_events_recent`; **`sent`** — `product_push_notifications`), **`warmupVideoEstimatedWatchMinutes`**, **`videoPlaybackEstimatedWatchMinutes`**, **`videoPlayback`**; устар. **`reminderRulesEnabledCount`**.
- **M2M fan-out после `dispatchDue`:** `POST /api/integrator/patient-reminders/notify-channels` — реализация [`integratorNotifyChannels.ts`](integratorNotifyChannels.ts) (web push + transactional SMTP; **List-Unsubscribe** при валидном `From`; сглаживание частоты email — `email_send_cooldowns`, ключ **`!reminder_txn_v1`**). Тексты Web Push строит [`pushNotificationCopy.ts`](../web-push/pushNotificationCopy.ts) по `linkedObjectType` / `reminderIntent` / `occurrenceCategory` (разминка, тренировка, custom для legacy-строк в БД, skip `water`/`breathing`/`supplements_medication`).
- **Failed occurrence history (D6):** обычный `markFailed` и перевод просроченных `planned/queued` в `failed` публикуют один и тот же `reminder.occurrence.finalized`; webapp пишет его в `reminder_occurrence_history` идемпотентно по `integrator_occurrence_id`. Исторические пропуски добирает миграция `0282_failed_reminder_occurrence_history` внутри штатного migration-owner window; существующие строки не обновляются. Проекции доставки/контента этим шагом не снимаются.
- **Legacy custom-напоминания:** UI создания/редактирования (`linkedObjectType=custom`) снят с пациентского экрана; существующие правила продолжают dispatch и push copy `custom`. Новые custom через API не создаются.
- **Рассылки врача (Push):** канал `push` в `/app/doctor/broadcasts` → `fanOutBroadcastWebPush` (`intentType: news`, тема `news`). См. `modules/doctor-broadcasts/fanOutBroadcastWebPush.ts`.

## Бот (Telegram / MAX)

- Inline-клавиатура диспатча напоминания: [`reminderInlineKeyboard.ts`](../../../../../integrator/src/kernel/domain/reminders/reminderInlineKeyboard.ts): **Начать разминку/занятие** (web_app), **Через 20 минут | Пропущу**, **Тишина до завтра | Расписание**, **Не напоминать в боте** (`rem_bot_off:<occurrenceId>`), **Установить мобильное приложение** (web_app → `/app/patient`). Отдельной строки **«Выполнить»** на клавиатуре нет (отметку `done` пользователь делает через основной CTA в mini-app / целевой экран); **`rem_done:<occurrenceId>`** и сценарии `telegram.reminder.done` / `max.reminder.done` остаются для **старых сообщений**, где кнопка ещё есть.
- Скип одним нажатием: **`rem_skip`** → script `telegram.reminder.skip.open` / `max.reminder.skip.open` → **`reminders.skip.applyPreset`** — **без кода причины**, интегратор всегда шлёт `postOccurrenceSkip({ reason: null })`; текст ответа — шаблон **`reminder.skip.saved`** (+ fallback в `handlers/reminders.ts`). Вопрос причины, пресеты (`rem_skip_r:*`) и состояние ожидания ответа убраны целиком решением владельца (D21a, 2026-07-31) — старых клавиатур с этой кнопкой в живых чатах не было (см. `docs/_TODO/runs/integrator-cleanup/D21A_AUDIT.md`).
- **Не напоминать в боте:** **`reminders.messengerTopic.disable.callback`** вызывает principal-derived capability `app.patient_disable_reminder_messenger_topic`. Она валидирует точную организацию и пациента, сохраняет тему × мессенджер в `user_notification_topic_channels` и возвращает готовые абзацы ответа; без темы — тот же короткий MVP-текст и deeplink-кнопки профиля/приложения.
- **Integrator** (`reminders.done.callback`, сценарии `telegram.reminder.done` / `max.reminder.done`): готовый результат `app.patient_done_reminder_occurrence` после exact-org проверки ведёт к `callback.answer` → **`message.delete`** исходного сообщения (у MAX `message_id` — строка). Если **`firstDoneForOccurrence`**, **`dayFullyDone`**, **`daySentTotal > 0`** — отдельное **`message.send`** с шаблоном **`reminder.dayAllDone`** (`{{done}}`, `{{total}}` в `apps/integrator/src/content/{telegram,max}/user/templates.json`). При отказе capability колбэк завершается **failed**, удаления нет.
- **Webapp:** день для агрегатов считается по локальной дате **`reminder_occurrence_history.occurred_at`** в IANA-зоне **`app_display_timezone`** (`getAppDisplayTimeZone`), в той же транзакции что запись `done` в `reminder_journal` — `pgReminderJournal.recordDone`, вызов из `doneOccurrence` в `service.ts`.
- Готовые поля **`firstDoneForOccurrence`**, **`dayDoneCount`**, **`daySentTotal`**, **`dayFullyDone`** возвращает capability `app.patient_done_reminder_occurrence`; пациентский маршрут [`patient/reminders/[id]/done/route.ts`](../../app/api/patient/reminders/[id]/done/route.ts) сохраняет свой session path.

- `service.ts` — бизнес-логика; порты: `ReminderRulesPort`, опционально `ReminderJournalPort`.
- `resolveReminderIntentForLinkedObject.ts` — при создании object-reminder: `content_section` с `system_parent_code = warmups` → `reminder_intent = warmup`; `rehab_program` → `exercises`; иначе `generic`. Вызывается из `createObjectReminder` (deps `contentSections`).
- `buildReminderDeepLink.ts` — deeplink для payload integrator и web-push open URL. Для `reminder_intent` **`warmup`** / **`exercises`** / **`stretch`** — `/app/patient/go/daily-warmup` и `/app/patient/go/plan-start-lesson`. **Fallback:** `content_section` + slug `warmups` при `generic` (legacy) → тот же go URL. Миграция **`0077_reminder_warmup_intent_backfill`**: backfill `reminder_intent` для правил на разделы кластера warmups.
- `scheduleSlots.ts` — формат `slots_v1`, дефолт реабилитации `DEFAULT_REHAB_DAILY_SLOTS` (09:00 и 19:00, `weekly_mask` 7/7). Дефолты формы «офисный день» для не-rehab — `reminderFormDefaults.ts` (окно 12–18, интервал 180 мин, маска Пн–Пт). При **первом** включении push в PWA — `ensureWarmupsReminderOnFirstPwaPush` (`DEFAULT_WARMUP_PWA_PUSH_ONBOARDING_SLOTS`: 12:00 / 15:00, будни), если правила на разминки ещё нет. Существующее правило не перезаписывается.
- Репозитории: `infra/repos/pgReminderRules.ts`, `pgReminderJournal.ts`; проекция для integrator GET: `infra/repos/pgReminderProjection.ts` (поля `schedule_data`, `reminder_intent`, `display_*` в ответе списка правил).
