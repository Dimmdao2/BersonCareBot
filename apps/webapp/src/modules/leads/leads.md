# Заявки

Заявка принадлежит организации и канонической учётной записи платформы. Отдельной сущности
«контакт заявки» нет: повторные заявки одного человека группируются по `platformUserId`.

Создать заявку можно только после подтверждения введённой почты через существующий публичный
email-OTP либо из уже аутентифицированного кабинета. Если введённый телефон уже подтверждён у другой
учётной записи, общий механизм platform-user merge переносит подтверждённую почту на владельца
телефона; сам введённый телефон доверенным не становится.

До принятия заявки строки `org_enrollments` нет. Принятие атомарно переводит заявку в
`accepted_in_progress` и создаёт активное отношение пациента с клиникой. Отклонение отношения не
создаёт и атомарно ставит письмо в существующую долговечную очередь доставки. Клиничная блокировка
будет отдельным состоянием `org_enrollments` и в этот слой не входит.

Статусы: `new`, `rejected`, `accepted_in_progress`, `accepted_closed`. Архивирование — отдельный
`archivedAt` и статус не меняет. Список принимает взаимоисключающий `archiveScope`: основной экран
читает только активные заявки, экран архива — только архивные.
