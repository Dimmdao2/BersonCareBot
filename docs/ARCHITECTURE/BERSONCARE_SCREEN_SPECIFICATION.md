# BERSONCARE — SCREEN SPECIFICATION

> **Назначение.** Полный проект интерфейса продукта — вход для ИИ-генерации визуальных макетов.
> Документ детерминирует экран настолько, что генератор **не принимает собственных UX/UI-решений**:
> он берёт готовую структуру, зоны, компоненты, данные, действия и состояния — и рисует.
>
> **Место в стеке документов (читать в этом порядке):**
>
> 1. **Design DNA v1.0+v1.1** (`docs/design/dna/`) — «из чего»: цвет, шрифт, форма, тень, движение.
> 2. **Screen Architecture Guide** (`docs/ARCHITECTURE/SCREEN_ARCHITECTURE_GUIDE.md`) — «как собрать»: зоны Z0–Z6, шаблоны страниц T1–T12, инварианты композиции.
> 3. **Screen Specification** (этот документ) — «что именно на каждом экране»: данные, действия, состояния, переходы.
>
> **Дата:** 2026-07-11. **Приоритет глубины:** кабинет врача (по DNA — приоритетная зона); карта покрывает обе зоны.
> **Формат:** каждый экран = человекочитаемое описание **+** машиночитаемый YAML-блок по единой схеме (§1).
> **Статус:** каркас + спеки шаблонов + эталоны + полная карта. Из этого генерируются остальные экраны по §1-схеме.

---

## 0. Как этим пользоваться (инструкция для ИИ-генератора макетов)

**Модель наследования.** Экран не описывается «с нуля». Каждый экран объявляет свой **шаблон** (T1–T12). Всё общее для типа — зоны, порядок блоков, визуальная иерархия, стандартные состояния, стандартные модалки — задано **один раз** в спеке шаблона (§2). Конкретный экран (§3 эталоны, §4 карта) описывает только **дельту**: свои данные, свои действия, свои специфические состояния и переходы.

```
Макет экрана = Design DNA (стиль)
             + Screen Architecture Guide (зоны/инварианты)
             + Template spec T-X (§2)         ← общий скелет типа
             + Screen entry (§1-схема)        ← данные/действия/состояния/переходы конкретного экрана
```

**Что генератор обязан взять как данность (НЕ решать самому):**

- Токены и визуальный язык — только из Design DNA (`bersoncare-theme.css`): Nunito, моно-синий `#386FBA`, общий холст `#f2f2f0`, радиусы 5·8·11·14, общий радиус кнопок `8px`, микротень, «тихие» статусы, плоские строки списков, движение 150–200мс, light-first.
- Расположение зон (заголовок/действия/фильтры/поиск/навигация) — только из §5 Screen Architecture Guide и спеки шаблона.
- Компоненты — только из реестра примитивов (SAG §6). Новых типов элементов не изобретать.

**Что генератор рисует по каждому экрану:** все перечисленные в его записи блоки сверху вниз, во всех состояниях (loading/empty/error/success/no-data + специфические), включая модалки и боковые панели.

**Порядок обхода при генерации:** сначала прочитать §1 (схема) и §2 (спеки шаблонов) целиком; затем для каждого экрана из карты (§4) взять его запись (эталон в §3 или строку карты) и сгенерировать макет во всех состояниях.

## 1. Схема экрана (обязательные поля)

Каждый экран описывается **прозой** (2–5 предложений: назначение + место в сценарии) **и** YAML-блоком ниже. YAML — канонический вход для генератора; проза — контекст для человека.

### 1.1 Машиночитаемая схема (YAML)

```yaml
screen:
  id: <route>                      # напр. /app/doctor/exercises
  name: <RU-название>
  zone: doctor | patient | public
  template: T1..T12
  purpose: <1–2 строки>
  journey:
    entry:                         # откуда пользователь приходит
      - from: <route|событие>  via: <действие>
    exit:                          # куда уходит
      - to: <route>  via: <действие>
  layout:                          # СТРУКТУРА СВЕРХУ ВНИЗ — порядок блоков = порядок отрисовки
    - zone: Z0|Z1|Z2|Z3|Z4|Z5|Z6   # см. модель зон SAG §3
      block: <имя блока/компонента>
      role: <что показывает>
      contains: [ <под-элементы> ]
  hierarchy:                       # визуальная иерархия
    primary: <главный фокус экрана>
    secondary: [ ... ]
    tertiary: [ ... ]
  components:                      # используемые примитивы
    - name: <ИмяКомпонента>
      path: <файл>
  data:                            # ОТОБРАЖАЕМЫЕ ДАННЫЕ — конкретные поля/значения
    - field: <имя>
      type: <text|number|date|badge|media|list|chart|...>
      source: <API/загрузчик, если известно>
  actions:                         # ВСЕ ДОСТУПНЫЕ ДЕЙСТВИЯ
    - label: <подпись>
      kind: primary | secondary | ghost | destructive | inline-link | icon
      placement: <зона/слот>       # где кнопка на экране
      effect: <что происходит>
      target: <route|modal|none>
  states:                          # СОСТОЯНИЯ ЭКРАНА (все применимые)
    loading: <как показано (компонент/скелет)>
    empty: <текст/компонент пустого состояния>
    error: <как показана ошибка (DataLoadFailureNotice/…)>
    success: <подтверждение действия — тост/инлайн>
    no_data: <нет данных vs пустой фильтр — если отличается от empty>
    extra: [ <спец-состояния: archived, unpublished, offline, guest, …> ]
  modals:                          # МОДАЛЬНЫЕ ОКНА
    - name: <имя>
      trigger: <действие-триггер>
      content: <что внутри>
      size: <sm|md|lg|content — DoctorModal / PatientModalDialogContent>
  side_panels:                     # БОКОВЫЕ ПАНЕЛИ
    - name: <имя>
      trigger: <когда появляется>
      content: <что внутри>
  related:                         # СВЯЗАННЫЕ ЭКРАНЫ
    - <route> — <связь>
  transitions:                     # ПЕРЕХОДЫ ПОЛЬЗОВАТЕЛЯ
    - on: <действие>
      to: <route|pane|modal>
```

### 1.2 Обязательный минимум

Запись экрана **невалидна**, если не заполнены: `id, name, zone, template, purpose, layout, data, actions, states(loading/empty/error как минимум), transitions`. Пустые секции указываются явно (`modals: []`), а не опускаются — чтобы генератор знал, что их нет, а не что забыли.

## 2. Спеки шаблонов (T1–T12)

Общий скелет каждого типа. Конкретный экран наследует всё отсюда и переопределяет только дельту.
Каждый шаблон описан в терминах зон **Z0–Z6** (Screen Architecture Guide §3): Z0 shell-навигация · Z1 шапка страницы · Z2 действия · Z3 тулбар/фильтры · Z4 контент · Z5 деталь/панель · Z6 футер.

> Общий для ВСЕХ шаблонов слой (не повторяется в каждом): **Z0** = оболочка зоны (`DoctorWorkspaceShell` сайдбар+контент / `PatientAppShell` верх+низ-нав). Заголовок и навигацию рисует оболочка — экран их не дублирует (инвариант SAG §7.1–7.2).

### T1 — Dashboard / «Сегодня»

- **Зоны:** Z1 (заголовок) → Z4 (KPI-сетка → стек секций-сигналов).
- **Порядок сверху вниз:** заголовок → строка(и) KPI-карточек → секции «требует внимания / сегодня / задачи» → (опц.) мини-календарь.
- **Иерархия:** primary — KPI-числа и срочные сигналы; secondary — списки задач/событий; tertiary — навигация вглубь.
- **Компоненты:** `DoctorPageHeader`, `doctorStatCardGridClass`+`DoctorStatCard`, `DoctorSection`, `KpiPreviewModal` (врач) / `FeatureCard`, semantic surfaces, hero (пациент).
- **Стандартные состояния:** loading — скелет KPI+секций; empty — «на сегодня событий нет» в секции; error — `DataLoadFailureNotice`; no-data по каждой секции отдельно.
- **Стандартные модалки:** KPI drill-down (`KpiPreviewModal`), карточка события (`TodayAppointmentFullModal`), диалог «требует внимания».
- **Переходы:** клик по KPI → модалка-список → элемент; клик по сигналу → соответствующий раздел/карточка.

### T2 — Простой список / таблица (без деталь-колонки)

- **Зоны:** Z1 → Z3 (sticky: поиск + Z2 «Добавить») → Z4 (список строк-ссылок или таблица).
- **Порядок:** заголовок → тулбар (поиск/фильтр/добавить) → строки (плоские, hairline, DNA §7.1) → пагинация/счётчик.
- **Иерархия:** primary — имена/названия строк; secondary — мета справа; tertiary — статус-метка.
- **Компоненты:** `DoctorCatalogStickyToolbar`, строки на `doctorSectionItemClass` / `FeatureCard` (пациент), `DoctorEmptyState`.
- **Состояния:** loading — скелет строк; empty — `DoctorEmptyState`; no-data (пустой фильтр) — «ничего не найдено» + сброс фильтра; error — `DataLoadFailureNotice`.
- **Переходы:** клик по строке → отдельный роут детали (не колонка).

### T3 — Каталог master-detail ⭐

- **Зоны:** Z1 → Z3 (sticky filters + Z2 «Создать») → Z4 (**master** слева) + Z5 (**detail** справа).
- **Порядок:** заголовок → sticky-тулбар (поиск/фильтры/сорт/«Создать») → двухколоночный `CatalogSplitLayout`: слева шапка списка (сорт+scope+переключатель список/плитки) и список/сетка, справа — деталь/форма. Мобайл: одна колонка, слайд list↔detail.
- **Иерархия:** primary — выбранный элемент в detail; secondary — master-список; tertiary — фильтры.
- **Компоненты:** `DoctorCatalogPageLayout`, `DoctorCatalogFiltersToolbar`+`DoctorCatalogFiltersForm`, `CatalogSplitLayout`, `CatalogLeftPane`, `CatalogRightPane`, `DoctorCatalogMasterListHeader`, `VirtualizedItemGrid`+tile-card.
- **Состояния:** loading — `CatalogSplitLayoutSkeleton`; empty — `doctorCatalogListEmpty*`; no-data (фильтр) — пусто в списке + подсказка; detail-empty — «выберите элемент слева»; error — `DataLoadFailureNotice`; элемент: archived/unpublished — метки.
- **Модалки:** медиа-пикер, подтверждения архивации.
- **Переходы:** клик по строке → detail в правой колонке (URL `?selected=`); «Создать» → пустая форма в detail или `.../new`.

### T4 — Просмотр объекта (entity card)

- **Зоны:** Z1 (entity-header) → Z2 (action-strip) → Z3 (вкладки) → Z4 (контент вкладки).
- **Порядок:** шапка сущности (имя, ключевые атрибуты, статус) → полоса быстрых действий (только если есть) → вкладки раздела → контент активной вкладки (2-колоночная сетка панелей уровня-2).
- **Иерархия:** primary — имя+статус сущности; secondary — активная вкладка; tertiary — вторичные панели.
- **Компоненты:** `DoctorPageHeader` (якорь), entity-header (`PatientCareBar`/`MembershipCardHeader`), `PatientActionStrip`, `TabsList variant="line"`, панели уровня-2 (`doctorClientCardChrome`).
- **Состояния:** loading — скелет шапки+вкладок; empty (у вкладки) — своё пустое; error; not-found (объект удалён) — заглушка.
- **Модалки:** редактирование поля, действия над сущностью.
- **Переходы:** вкладки — client-переключение (без ре-фетча); действия → модалки/связанные роуты.

### T5 — Создание / редактирование (форма)

- **Зоны:** Z1 → Z4 (секции полей) → Z2 (sticky publish-bar).
- **Порядок:** (в split-detail — внутри правой колонки) заголовок формы → группы полей (`DoctorSection`) → медиа/связи → sticky-футер Save/Publish.
- **Иерархия:** primary — редактируемые поля; secondary — where-used/связи; tertiary — служебные.
- **Компоненты:** поля `Input/Textarea/Label`, `ReferenceSelect`/`ReferenceMultiSelect`/`CreatableComboboxInput`, `DoctorDateTimePicker`, `DoctorCatalogPersistPublishBar`, `MediaLibraryPickerDialog`.
- **Состояния:** pristine / dirty (несохранённое — publish-bar активен) / saving / saved (успех — тост/инлайн) / validation-error (по полям) / archived (только чтение + «восстановить»); load-error.
- **Модалки:** медиа-пикер, подтверждение архивации/удаления.
- **Переходы:** Save → остаётся; Publish → метка published; Archive → в архив-scope.

### T6 — Календарь / расписание

- **Зоны:** Z1 (заголовок + вкладки раздела) → Z3 (sticky: дата/период/переключатель вида) → Z4 (сетка календаря) + Z5 (панель события).
- **Порядок:** заголовок с вкладками → тулбар (нав по датам, вид day/3days/week/month/list, KPI-строка кроме day) → сетка (тайм-колонка слева + события) → при клике на событие — боковая панель/модалка.
- **Иерархия:** primary — события в сетке; secondary — навигация периода; tertiary — KPI.
- **Компоненты:** FullCalendar (day/timeGrid/dayGrid/luxon), `DoctorTimeColumn`, `DoctorCalendarEventPanel`, `DoctorCalendarRescheduleDialog`, KPI-строка (`AppointmentKpiItem`).
- **Состояния:** loading — скелет сетки; empty — «нет записей в этом периоде»; error; событие: статусы (запланировано/отменено/перенесено) — цветом полоски.
- **Модалки/панели:** панель события (детали+действия), диалог переноса, создание записи.
- **Переходы:** клик события → панель; из панели → карточка клиента; переключение вида/периода — client.

### T7 — Аналитика

- **Зоны:** Z1 (заголовок + таб-кнопки) → Z3 (период) → Z4 (KPI-сетки + графики).
- **Порядок:** заголовок с вкладками аналитики → выбор периода → строки KPI-карточек → графики (в карточках) → (опц.) таблицы-разрезы.
- **Иерархия:** primary — KPI-числа; secondary — графики; tertiary — фильтры периода.
- **Компоненты:** `DoctorMetricList`+`DoctorStatCard`, recharts в `Card`+`AppRechartsTooltip`, `ExerciseExecutionGraph`/`ExerciseMicroChart` (SVG), `KpiPreviewModal`.
- **Состояния:** loading — скелет карточек/графиков; empty — «недостаточно данных за период»; error; no-data по метрике — «—».
- **Модалки:** drill-down по KPI (`KpiPreviewModal`).
- **Переходы:** клик KPI → модалка-список → элемент; смена периода — client.
- **Инвариант:** KPI-сетку отделять от секций разделителем (SAG §7.9).

### T8 — Видео / медиа

- **Зоны:** Z1 → Z3 (фильтр типа/поиск) → Z4 (сетка медиа-карточек) + модалка-лайтбокс/плеер.
- **Порядок:** заголовок → тулбар → адаптивная сетка карточек (превью `MediaThumb` + мета) → по клику лайтбокс/плеер.
- **Иерархия:** primary — превью-сетка; secondary — мета файла; tertiary — действия над файлом.
- **Компоненты:** `doctorMediaCardGridClass`, `MediaCard`, `MediaThumb`+`MediaPreviewUiModel`, `MediaLightbox`, плеер `DoctorMediaPlaybackVideo`/`PatientMediaPlaybackVideo` (HLS+fallback, `/playback`).
- **Состояния плеера:** loading (постер+спиннер) / playing / paused / ended / error (fallback MP4) / no-source. Превью: skeleton → image; pending-transcode — статичный плейсхолдер (пациент — только картинка, без `<video>`).
- **Модалки:** лайтбокс (превью), плеер, пикер медиа (`MediaPickerShell`).
- **Инвариант:** превью только `MediaThumb`; воспроизведение только единый плеер; формат решает сервер.

### T9 — Чат / сообщения

- **Зоны:** Z1 (+ вкладки) → Z4 (лента тредов) + Z5 (переписка) — либо master-detail, либо full-bleed.
- **Порядок:** заголовок с вкладками → слева список тредов (`CatalogSplitLayout`) → справа переписка (пузыри + composer снизу).
- **Иерархия:** primary — активная переписка; secondary — список тредов; tertiary — composer.
- **Компоненты:** `ChatView` (modules/messaging), пузыри (`ChatBubbleOutgoingMeta`, `ChatMessageDeliveryTicks`), composer.
- **Состояния:** loading — скелет ленты; empty (нет тредов) — пусто; empty (тред без сообщений) — приглашение; sending / sent / delivered / read (тики); error отправки — ретрай; offline.
- **Переходы:** выбор треда → переписка; из треда → карточка клиента.

### T10 — Мастер / визард

- **Зоны:** Z1 (+ «Шаг N из M») → Z4 (контент шага) → Z2 (Назад/Далее/Завершить).
- **Порядок:** заголовок+прогресс шага → контент текущего шага (выбор/форма) → навигация шагов внизу.
- **Иерархия:** primary — выбор/поле текущего шага; secondary — прогресс; tertiary — назад.
- **Компоненты:** степпер/прогресс, hero-секции выбора (пациент `patientHeroBookingSectionClass`), CTA.
- **Состояния:** шаг: pristine/valid/invalid; загрузка вариантов; нет доступных вариантов (напр. слотов) — пустое + альтернатива; ошибка; завершение — экран успеха.
- **Переходы:** Далее → следующий шаг (URL-шаг); Назад → предыдущий; Завершить → экран done/оплата.

### T11 — Настройки / администрирование

- **Зоны:** Z1 (+ вложенный sub-nav у booking) → Z4 (стек секций / сетка карточек настроек).
- **Порядок:** заголовок → (опц. под-навигация) → группы настроек (`DoctorSection` / сетки карточек) → на изменение — inline save или sticky-bar.
- **Иерархия:** primary — редактируемые настройки; secondary — описания; tertiary — опасные зоны (внизу).
- **Компоненты:** `DoctorSection`, поля, `LabeledSwitch`, сетки `BOOKING_CARD_GRID_CLASS`.
- **Состояния:** loading; saved (успех); validation; unsaved (dirty); restricted (нет прав) — заглушка.
- **Переходы:** табы настроек; вложенные разделы.

### T12 — Инфо / легал / пустые / гостевые / редиректы

- **Инфо/легал:** Z1 → Z4 (секции текста + inline-ссылки + `LegalFooterLinks`).
- **Пустое состояние (как экран):** `DoctorEmptyState`/`patientEmptyStateClass` — иконка/текст + первичное действие.
- **Гость/гейт:** `GuestPlaceholder`/`DiarySectionGuestAccess` — объяснение + вход.
- **Ошибка загрузки (как экран):** `DataLoadFailureNotice` — сообщение + digest-код.
- **Редирект-стаб:** без UI, `redirect()` на целевой роут (в карте помечается `→ redirect`).
