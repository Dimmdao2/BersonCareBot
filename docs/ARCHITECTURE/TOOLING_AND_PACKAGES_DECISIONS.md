## Аналитика — своя, self-hosted; наружу ничего не уходит

**Линия (для медданных — осознанная): аналитика ТОЛЬКО self-hosted, стороннего сервиса нет.**

- **Текущее состояние: своя встроенная product-аналитика уже работает** — инициатива `PRODUCT_ANALYTICS_INITIATIVE`
  (закрыта 2026-05-27). События (`app_open`, `page_view`, `heartbeat`, `auth_login`, воронка регистрации, push)
  идут в **наши же API-роуты → нашу БД**, агрегируются в докторский дашборд «Использование»
  (`/app/doctor/usage`). Модуль `apps/webapp/src/modules/product-analytics/`.
- **Наружу не уходит ничего.** Никакого стороннего сервиса. В метаданных — **без сырого PII** (оговорено в каноне
  инициативы); тестовые аккаунты исключены из агрегатов.
- **Plausible (из списка) — опционально и только как self-hosted дополнение.** Даже при внедрении: свой сервер на
  нашей инфре, данные третьей стороне не уходят (Plausible cookieless, без PII). Смысл — веб/PWA-трафик (источники,
  воронка установок), которого внутренняя система не покрывает. Не ядро; заводить только если реально понадобится
  маркетинговая трафик-аналитика.

- **dnd-kit — `@dnd-kit/core@^6`, `/sortable@^10`, `/utilities` уже установлены** (reorder упражнений/шаблонов).

## Редактор контента — Tiptap Simple Editor (решение владельца 21.07)

**Задача:** WYSIWYG-редактор для текстов на платформе там, где сейчас markdown (статьи/CMS, рассылки, рекомендации).
Markdown и поле-ввода/превью — отклонены владельцем; нужен единый WYSIWYG. Красивые HTML-письма — **отдельная**
тема (HTML-конверт транзакционных писем, см. ниже), не этот редактор.

**Выбор: Tiptap, шаблон «Simple Editor» (free, MIT, self-hosted). НЕ «AI-editor».**

- **Почему Tiptap:** headless — надевается на нашу Design DNA (Nunito, свои primitives), без чужой панельки;
  модульный (не громоздкий — ставим только нужные расширения); WYSIWYG на одной поверхности; отдаёт HTML/JSON
  (в БД лучше JSON — надёжнее санитайзить и рендерить под стенами тенанта); self-hosted, наружу ничего не ходит.
- **Simple Editor vs AI-editor:** отличие ровно в AI-функциях. «AI-editor» = Tiptap **Content AI** — **платный
  Tiptap Cloud**, отправляет содержимое редактора во **внешний** AI-сервис. Против нашей линии (медданные,
  self-hosted, ничего наружу) → берём **Simple Editor**. Захотим AI-помощь позже — на **своей** модели, не Tiptap Cloud.
- **Не берём:** CKEditor 5 / TinyMCE (громоздкие + платные тиры), Quill/Editor.js (тяжелее управлять дизайном /
  блочная модель). Lexical — запасной, если Tiptap где-то упрётся.

**Куда идёт Tiptap:** во **ВСЕ места, где сейчас стоит markdown-редактор** — рассылки (`/broadcasts`),
CMS/статьи (`/content`), рекомендации (`/recommendations`) и любые другие markdown-поверхности (см. #931 —
обязательный discovery-sweep, не только 3 известных экрана). Формат хранения остаётся markdown (вариант 1).

**Куда Tiptap НЕ идёт (решение владельца 21.07) — транзакционные письма-шаблоны:** тексты уведомлений,
напоминания о записи на приём, проверочные (OTP) коды в email. Здесь **редактора контента не меняем**: текст
остаётся простым шаблоном с переменными (как сейчас, в настройках специалиста/клиники). Визуально настраивается
**только HTML-конверт письма** — см. следующий блок.

### HTML-конверт транзакционных писем (решение владельца 21.07) — часть N1B (#930), НЕ Tiptap

Разделение **layout + content** (владелец: «не усложнять»):
- **Контент** (заголовок + тело уведомления, код, детали записи) — **данные**, правятся текущим простым
  редактором «Тексты уведомлений» (`/app/doctor/schedule`). Не Tiptap, не меняем.
- **Конверт (обёртка)** — **один HTML-шаблон** на организацию: брендинг (логотип, аватар специалиста, подпись,
  контакты) + плейсхолдеры `{{title}}` / `{{body}}`, куда сервер подставляет заголовок+тело из уведомления.
  Правится **как HTML-код с живым превью на синтетике** — не WYSIWYG-письмо и **не** визуальный email-билдер
  (GrapesJS/Unlayer — не берём). На отправке: контент → санитизация → подстановка в конверт → финальный email-HTML
  + обязательный **plain-text fallback**.
- **Безопасность (уже требования N1B, не новый скоуп):** HTML-конверт правит клиент → инъекционная поверхность.
  Серверная санитизация конверта; **разрешён только whitelisted набор плейсхолдеров/тегов** (server-enforced
  allowlist N1B; script/onclick/внешние ресурсы — режутся); подставляемый контент тоже санитизируется.
- **«Один» конверт = на организацию, под entitlement брендинга** (в N1B брендинг гейтится; без оплаты —
  нейтральный платформенный конверт по умолчанию). Мессенджеры/push — свои безопасные поля, HTML-конверт к ним не применяется.

**Синхронизация с планами (не плодить сущность):** и текстовые шаблоны, и HTML-конверт — это **эволюция
существующей системы шаблонов**, а не новый экран. Стадия **N1B «managed notification templates»** (taskdb `#930`,
[`docs/_TODO/RU_PRIVACY_AND_PRODUCTION_READINESS/stages/NTF-01_APP_PUSH_AND_MESSENGER_AUTH_ONLY.md`](../_TODO/RU_PRIVACY_AND_PRODUCTION_READINESS/stages/NTF-01_APP_PUSH_AND_MESSENGER_AUTH_ONLY.md)).
Обязательный reuse (канон N1B, не форкать второй стор): `modules/notif-templates/notifTemplatesService.ts`,
admin/doctor-роуты, настройки `notif_template:*`, редактор «Тексты уведомлений» (`NotificationTemplatesPageClient.tsx`).
**Tiptap в N1B не участвует** — HTML-конверт правится редактором HTML-кода.

**Массовые рассылки врача** (`/app/doctor/broadcasts`, `DOCTOR_BROADCASTS.md`) — отдельный **уже готовый**
механизм (текст + HTML для мессенджеров, markdown-форматирование = task #20). Тот же Tiptap можно переиспользовать
для тела рассылки позже, но это НЕ скоуп N1B — отдельным решением.

### Замена существующих markdown-редакторов на Tiptap (решение владельца 21.07 — **вариант 1**)

Владелец: «поменять редактор ВЕЗДЕ, где стоит markdown». **Способ — вариант 1: WYSIWYG-начинка меняется, формат
хранения остаётся markdown.** План: [`docs/_TODO/EDITOR_TIPTAP_MIGRATION_PLAN.md`](../_TODO/EDITOR_TIPTAP_MIGRATION_PLAN.md), taskdb `bcb`.

- **Где сейчас markdown-редактор (3 экрана доктора, на 2 общих компонентах):** `/app/doctor/content` (Toast UI —
  `MarkdownEditorToastUi`), `/app/doctor/broadcasts` и `/app/doctor/recommendations` (кастомный `MarkdownEditor`).
  Контракт компонентов — **markdown-строка in / out** + скрытое поле формы.
- **Чокпоинт:** менять только внутренности этих 2 компонентов (Tiptap читает markdown → WYSIWYG → сериализует
  обратно в markdown, тот же `value`/`onChange`/`name`). 3 формы не трогаются.
- **Формат хранения = markdown, миграции БД НЕТ. Пациентский рендер (`react-markdown`, `shared/ui/patient/markdown/*`)
  НЕ трогается.** Диагноз феасибилити: markdown стандартный **GFM** (`remark-gfm`), кастомных директив нет —
  «диплинки видео» это обычные `[текст](url)` на media/YouTube/Rutube, вся логика в рендер-`components`. Roundtrip
  безопасен.
- **Что переносится на Tiptap-команды:** вставка из медиатеки (`MediaLibraryInsertDialog` → сейчас вставляет
  markdown-сниппет ссылки/картинки) — переезжает на Tiptap-ноды link/image с тем же URL.
- **Убрать после миграции:** `@toast-ui/editor`, `@toast-ui/react-editor`.
- **Аудит:** presentation-tier → воркер + ОДИН независимый аудит; критерий готово = зелёный CI + **живой скрин**
  трёх экранов (owner acceptance), не «тесты зелёные».

## Про «фронтовый стек» из того же списка

Блок «Next.js 16 + React 19 + Tailwind v4 + shadcn new-york … Tiptap как ядро контента, idea-inbox → storyline, kanban,
30 экранов, статистика постинга» — это **язык проекта storylama, не BersonCare**. У BersonCare своя дизайн-система
(Design DNA v1, Nunito, свои primitives; эталон каталога — страница упражнений). Оттуда в BersonCare переносится только
точечно и по месту — не как стек. **Исключение — сам rich-text-редактор: конкретный экран его потребовал**
(тексты платформы / шаблоны уведомлений), поэтому Tiptap **принят** отдельным решением 21.07 — см. раздел
«Редактор контента» выше. Остальной блок storylama-стека это не втягивает.
