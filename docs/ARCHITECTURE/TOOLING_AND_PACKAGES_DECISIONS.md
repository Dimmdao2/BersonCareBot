## Внедрять сейчас — Security CI

Дёшево + прямая польза с учётом медданных и прошлого инцидента (реальные прод-креды утекали в dev `.env` —
см. память `dev-env-hardening-real-creds`). Полный план подключения к `.github/workflows/ci.yml` —
**[`docs/_TODO/SECURITY_CI_STACK_PLAN.md`](../_TODO/SECURITY_CI_STACK_PLAN.md)**. Кадэнс:

- На каждый PR: **Gitleaks**, **Semgrep**, **Trivy** (быстрый режим).
- Раз в неделю + перед релизом: **OWASP ZAP** (DAST), **Trivy** (полный режим).
- Позже (после появления AI-агентов в продукте): **Garak**.
- `Zeropath` — экосистема молодая, пропускаем.

## Дорожная карта — реальные фичи продукта (НЕ сейчас)

- **Видеозвонки.** Целевой — **LiveKit** (запись → дальнейшая расшифровка). Быстрый MVP для проверки сценария —
  **Jitsi-embed**. Не начинать до рабочего теста.
- **faster-whisper — расшифровка ГОЛОСОВЫХ В ЧАТАХ** (уточнение владельца 19.07: не приёмы, а голосовые сообщения
  в переписке). Отдельный `transcription-worker`, НЕ через Open WebUI как ядро. Голосовые в чате = медицинский PII —
  хранение/доступ под стенами тенанта.
- **Анкеты/опросники — НАТИВНЫЕ** (решение владельца 19.07): собственная модель в нашей БД, под tenant-стенами, а не
  внешний движок Formbricks. Formbricks максимум как референс UX-модели анкет.
- **Stirling PDF** — документы/анализы пациента, OCR, merge/сжатие. Подключать, когда появится продуктовый workflow
  «документы пациента»; фичи пока нет.

## По месту — узкие библиотеки, без «внедрения платформы»

- **pgvector, НЕ Qdrant.** Векторный поиск по базе знаний/транскриптам — на существующем Postgres. Второй datastore
  (Qdrant) не заводить.
- **Recharts — `^3.8.1` уже установлен и используется** (`MiniStatsChart`, `SymptomChart`, `DiaryLineChartRecharts`,
  дневник пациента). Ставить нечего. Новые графики — по зафиксированному lazy-паттерну
  `next/dynamic(() => import("…Recharts"), { ssr: false })`; recharts не импортировать в серверных компонентах.
- **dnd-kit — `@dnd-kit/core@^6`, `/sortable@^10`, `/utilities` уже установлены** (reorder упражнений/шаблонов).
  Переиспользовать, не добавлять аналогов.

## Не внедрять сейчас

- **@tanstack/react-table — в проекте НЕ установлен, в коде не используется.** Справочники у доктора
  (`apps/webapp/src/modules/references`, `ReferenceSelect`/`ReferenceMultiSelect`, `/app/doctor/references`) и прочие
  списки/таблицы сделаны на своих primitives и **работают — не трогать**. react-table вводить только если появится
  реально тяжёлая сортируемая/фильтруемая/пагинируемая таблица, которую больно держать вручную; тогда — отдельным
  решением, а не «заодно».
- **Twenty CRM** — только как референс модели (клиники-как-клиенты ≈ CRM). Не внедрять.
- **Open WebUI / Ollama как ядро медпроцесса** — нет; максимум внутренний dev-инструмент.
- **Crawl4AI, Memos, Upscayl, HandBrake** — внутренние/контентные, не пациентский продукт (видео упражнений кодируется
  через ffmpeg-пайплайн, отдельный HandBrake не нужен).
- **Penpot как «AI-редактирование макетов через Cursor»** — не решает задачу, не делаем. Сам Penpot — см. ниже.
- **Uptime Kuma** — nice-to-have (внешний аптайм-монитор), низкий приоритет; health-dashboard уже есть.
- **cmdk / motion (framer-motion)** — полировка, по вкусу и не сейчас.

## Penpot — уже развёрнут (пробел в доках закрыт)

**Факт (владелец 19.07): Penpot уже развёрнут как сервер `penpot.bersonservicex.ru`.** В доках репозитория он ранее
не был зафиксирован — это и был пробел, отмеченный владельцем. В taskdb есть связанная задача **#6** (экспорт страниц
кабинета доктора в Penpot-библиотеку, на Нео). Penpot — инструмент для макетов/дизайн-библиотеки; в продукт
BersonCare (пациентский/докторский рантайм) он не входит. «AI-редактирование макетов через Cursor» — отдельно, не
делаем (см. выше).

> Инфра-провенанс URL/доступов Penpot: держать вместе с остальной топологией сервисов (`SERVER CONVENTIONS`/деплой-доки),
> когда владелец даст детали хостинга; здесь фиксируется сам факт существования сервиса.

## Про «фронтовый стек» из того же списка

Блок «Next.js 16 + React 19 + Tailwind v4 + shadcn new-york … Tiptap как ядро контента, idea-inbox → storyline, kanban,
30 экранов, статистика постинга» — это **язык проекта storylama, не BersonCare**. У BersonCare своя дизайн-система
(Design DNA v1, Nunito, свои primitives; эталон каталога — страница упражнений). Оттуда в BersonCare переносится только
точечно и по месту — не как стек. Rich-text-редактор (Tiptap/Lexical) — только если конкретный экран (CMS/библиотека)
реально этого потребует, отдельным решением.
