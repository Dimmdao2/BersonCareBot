## Полный CI гоняется В ЭТОМ дереве — и только когда никто не пишет

Владелец, 27.07: «гонять CI в отдельном рабочем дереве — нет. гонять в этом дереве». Отдельное дерево тянет
свой `node_modules`, расходится с реальной средой и проверяет не то, что поедет. Изолируются ИСПОЛНИТЕЛИ, а не
проверка: воркеры работают в своих клонах, главное дерево остаётся лиду.

**Два условия перед `pnpm run ci`, оба обязательны.**

1. **Никто не пишет.** Проверяется командой, а не взглядом на дерево:

   ```bash
   pgrep -af agent-run.mjs
   ```

   Аудитор с `--sandbox read-only` не мешает; воркер с `workspace-write` — блокирует. ⛔ Чистое `git status`
   этой проверки НЕ заменяет: воркеры пишут в своих клонах, дерево при этом чистое, и условие выглядит
   выполненным, когда оно нарушено.

2. **Сведение закончено.** Пока впереди есть ещё хоть одна ветка к слиянию — прогона нет, даже если прямо
   сейчас ни один воркер не активен. Полный CI измеряет ОДНО состояние репозитория; если это состояние ещё
   дописывается, его результат не доказательство ни в зелёном виде (он про дерево, которого не будет), ни в
   красном (падение может принадлежать половине слияния). Гейт — после последней влитой ветки.

Результат называется КОММИТОМ, а не временем: «CI зелёный» без sha — впечатление, а не факт.

Норматив — `AGENTS.md` §9 «Full CI gate», там же требование назвать непокрытую область ДО запуска
(«Если назвать нельзя — полный CI не запускается»).

**Почему это здесь.** Правило владельца от 27.07 три недели существовало только в памяти лида и ни в одном
файле репозитория — поэтому его не видел ни один другой агент и не проверял ни один гейт. 20.08 лид повторил
тот же провал: пять воркеров с `workspace-write`, идущее сведение одиннадцати веток, прогон запущен по признаку
«дерево чистое». Правило, живущее только в памяти, не работает.
