# Сверка платежей с провайдером, баланс клиники, срок жизни счёта

Владелец, 18.08: «Сверка платежей с провайдером — делаем». Плюс его решения:
расписание адекватное (не каждые две минуты); уведомление глобал-админу как критический алерт **без спама**
(повторно — не чаще раза в сутки, пока не починили); непарный платёж **зачисляется автоматически**;
у клиники появляется **баланс**, с которого можно оплатить тариф; **оплатить можно только актуальный счёт**,
срок жизни счёта — константа 30 дней в коде.

Источник практики: исследование 18.08 (ЮKassa шлёт вебхук 7 раз за 24 часа и прекращает; Stripe — баланс
выводится из неизменяемого списка операций; Alertmanager/PagerDuty — одно происшествие на отпечаток).

## Этап 3 — баланс

- [ ] 3.1 Таблица движений, только дозапись; баланс = сумма. Не колонка с числом
- [ ] 3.2 Ограничения в БД, а не в коде: один платёж нельзя зачислить дважды; нельзя зачислить чужой клинике
- [ ] 3.3 Автозачисление только если видно организацию; иначе — тревога и деньги не разобраны
- [ ] 3.4 Баланс виден клинике, с него можно оплатить тариф (одна транзакция, баланс не уходит в минус)

## Ждут решения владельца

- [ ] G1 Двойное списание: у провайдера защита от повтора живёт сутки, наши ключи вечные. Повторная отправка
      черновика старше суток спишет деньги второй раз. Предложено: обновлять ключ, если черновику >24 ч
- [ ] G2 Чек при оплате с баланса (54-ФЗ). Предложено: второго чека нет — чек пробит при приходе денег
- [ ] G3 Возврат неразобранных денег: кнопка у глобал-админа (предложено) или автоматически
