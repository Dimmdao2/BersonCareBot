## MUST FIX-1 — заявленная локальная граница не включает часть локальных объявлений и литералов

Строка оракула: клинические данные до завершения общего прохода не показываются.

Шапка на `:14-15` обещает следовать по локальным объявлениям и литералам route-файла.
Фактически `directBindingInScope()` на `:152-157` признаёт только декларацию с простым
`Identifier`, `propertyNameOf()` на `:192-197` не признаёт статически вычислимое имя
`['pull']`, а `memberValuesOf()` на `:239-264` останавливается на spread. Для раннего
helper это превращается в молчание: `firstDataReadPortIn()` на `:584-594` использует
только найденные тела и игнорирует `unresolvedPotential`.

Собственные инъекции через `checkSource()` дали четыре небезопасных зелёных формы:

- `{ ['pull']: pull }.pull()`;
- `{ ...base }.pull()`;
- `const { pull } = box; await pull()`;
- `const [pull] = box; await pull()`.

Во всех четырёх `pull` читает `treatmentProgram`/`materialRating` до двери. Обратная
сторона того же дефекта шумит: полностью защищённый handler в computed-свойстве и
полностью защищённый destructured handler оба краснеют как неразрешимые.

Impact: обычная локальная форма скрывает клиническое чтение от обязательного lint-гейта,
а эквивалентная безопасная форма блокирует законный код. Это не заявленный предел
межмодульных фабрик и не общий data-flow: все значения и bindings находятся в одном
route-файле. Нужно либо разрешать эти локальные формы симметрично, либо честно сузить
шапку; небезопасная половина при этом всё равно обязана fail-closed по оракулу.

## MUST FIX-2 — прямое чтение молчит при bracket-access и под агрегирующим `await`

Строка оракула: клинические данные до завершения общего прохода не показываются.

`dataReadPortOf()` на `:534-557` разбирает только цепочку `PropertyAccessExpression`,
а `firstDataReadPortIn()` на `:578-595` проверяет только непосредственное выражение
каждого `await` и затем пытается разрешить его callee как локальную функцию.

Две собственные прямые формы ожидались красными, но получили пустой `findings`:

```ts
const exposed = await buildAppDeps()['treatmentProgram'].getForPatient({});
const [plan] = await Promise.all([
  buildAppDeps().treatmentProgram.getForPatient({}),
]);
```

Обе стоят до общей двери и выполняют клиническое чтение; ни alias, ни импортированной
фабрики, ни межмодульного анализа здесь нет. Шапка эти синтаксические ограничения не
называет, поэтому её граница не совпадает с поведением.

Impact: разработчик меняет только эквивалентную форму локального прямого чтения и
получает зелёный обязательный гейт при доступе к клиническим данным до двери.
