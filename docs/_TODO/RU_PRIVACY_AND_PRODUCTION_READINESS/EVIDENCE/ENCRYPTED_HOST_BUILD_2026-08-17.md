# Зашифрованный хост собран и загружается (2026-08-17)

Доказательство по `IS-I0-03` (разметка), `IS-I7-01` (репетиция install → encrypt → unlock → reboot) и
частично `IS-I3-08` (путь восстановления без панели провайдера).

**Хост:** `135.106.187.95`, имя `bcb-prod`, Ubuntu 24.04.4, ядро 6.8.0-138-generic.

## Итоговое состояние диска

```
sda                80G
├─sda1              8M               BIOS boot
├─sda2              2G  ext4         bcb-boot    /boot   (не шифруется: grub читает отсюда ядро)
├─sda3             70G  crypto_LUKS  bcb-crypt
│ └─bcbcrypt            LVM2
│   ├─bcbvg-swap    8G  swap         bcb-swap    [SWAP]  (подкачка внутри шифрования)
│   └─bcbvg-root   62G  ext4         bcb-root    /
└─sda4              8G  ext4         bcb-tmpsys          (временная система, снимается на ступени C)
```

`cryptsetup status`: LUKS2, `aes-xts-plain64`, ключ 512 бит, ключ в keyring, устройство `/dev/sda3`.
Открытого корня на машине больше нет. Снаружи слушает только порт 22; отказавших служб нет.

## Как это собрано и почему так

Прямой путь «загрузиться в rescue и поставить систему с шифрованием» на этой площадке невозможен: rescue —
BusyBox с ядром 2018 года, **без модуля dm-crypt** (в образе 43 модуля, в разделе криптографии только
`xor.ko`) и без perl, из-за чего не работает и `debootstrap`. Поэтому сборка идёт двумя ступенями:

1. [`stage-a-temp-installer.sh`](../../../../deploy/host/encrypted-install/stage-a-temp-installer.sh) — из
   rescue: разметка и распаковка проверенного по контрольной сумме `ubuntu-base` во временный раздел
   **в конце диска**. Единственная задача этой системы — дать современное ядро с dm-crypt.
2. [`stage-b-encrypted-system.sh`](../../../../deploy/host/encrypted-install/stage-b-encrypted-system.sh) —
   из временной системы: LUKS2 + LVM, установка боевой системы, разблокировка по SSH из initramfs.
3. Ступень C (реклейм 8 ГБ временного раздела в контейнер) — **ещё не выполнена**: временная система
   намеренно сохраняется как путь восстановления, пока хост не закончен.

Временный раздел стоит последним именно для того, чтобы контейнер потом можно было расширить вперёд.
`/boot` общий, и установка ядра затирает ядро временной системы (имена файлов совпадают), поэтому ступень B
откладывает её ядро и initrd под именами `tmpsys-*` и добавляет пункт меню
«Stage A temporary system (recovery)». Он реально использовался и сработал.

## Разблокировка при загрузке

В initramfs работает `dropbear`; адрес интерфейсу задаёт ядро параметром `ip=`. Проверено вживую: машина
останавливается на `Please unlock disk bcbcrypt`, доступна по SSH, `cryptroot-unlock` принимает фразу,
загрузка продолжается. Ключ разблокировки сверяется **по содержимому**, а не по пути: `dropbear-initramfs`
кладёт домашний каталог root внутрь initramfs под случайным именем.

## Дефекты, найденные до того, как они стоили времени владельцу

Каждый из них скрипт завершал кодом 0, то есть «успешно»:

| Что случилось | Как проявилось бы | Почему поймали |
| --- | --- | --- |
| `fstab` собран из вывода BusyBox `blkid`, который игнорирует `-s/-o` | аварийная консоль при первой загрузке | ручной осмотр установленной системы до перезагрузки |
| не поставлена система инициализации (`--no-install-recommends` её не тянет) | `Target filesystem doesn't have requested /sbin/init` | владелец увидел на консоли; теперь ловится проверкой |
| `ip=` с именем `eth0` | `ipconfig: eth0: SIOCGIFINDEX: No such device`, недостижимый запрос пароля | консоль; теперь ловится проверкой |
| подавление stderr на строке вызова обработчика отказа | скрипт умирает молча | расхождение «код 0» и пустого результата |
| проверка ключа в initramfs по фиксированному пути | ложный отказ на исправной системе | проверка против реальности, а не против ожидания |

**Имя интерфейса — отдельный вывод.** В работающей системе он `eth0`, но это имя присваивает netplan
*после* монтирования корня; в initramfs он `ens3`. Поэтому в `ip=` имя устройства не указывается вовсе.

**ICMP до хоста не проходит.** `ping` показывает 100% потерь на полностью живой машине — проверять
доступность нужно портом, не пингом.

## Открыто

- Парольная фраза временная и была напечатана в выводе команды разблокировки. Подлежит замене до появления
  на диске любых настоящих данных; постоянную задаёт владелец, второй слот — ключ восстановления (`IS-I0-05`).
- Ступень C (возврат 8 ГБ) — после того как хост доведён.
- Настройка хоста как таковая (firewall, SSH, service users, systemd, PostgreSQL) — `§I1` плана, не начата.
