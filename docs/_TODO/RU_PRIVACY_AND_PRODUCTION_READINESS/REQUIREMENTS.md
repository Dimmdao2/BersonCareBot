# Требования и границы

## 1. Исходные допущения

- Продукт позиционируется как немедицинская записная книжка специалиста, но фактически может хранить сведения о
  состоянии здоровья. Название продукта не отменяет режим защиты фактически обрабатываемых данных.
- Selectel/VPS и размещение в России приняты как входное условие владельца. Проверка договора, фактической
  локализации всех копий и субподрядчиков входит в `PR-01`, но выбор провайдера не пересматривается.
- Tenant isolation, billing, тарифы, оплаты и S5 settings split уже имеют собственные планы. Здесь они только
  зависимости, а не повторный scope.
- Никакие секреты, реальные ПДн, дампы, cookies, IP allowlist или credential-bearing URL не коммитятся.

## 2. Нормативные опорные точки

Окончательный перечень и актуальные редакции подтверждает привлечённый специалист. Baseline для decision packet:

- Федеральный закон № 152-ФЗ: специальные категории данных, согласие/основания обработки, обязанности оператора,
  права субъекта, локализация и уведомление об инцидентах;
- Постановление Правительства РФ № 1119: требования к защите ПДн в ИСПДн;
- приказ ФСТЭК России № 21 и актуальные изменения: состав организационных и технических мер;
- уведомление/актуализация сведений оператора в Роскомнадзоре;
- договоры поручения обработки, реестр получателей/подрядчиков и проверка трансграничных потоков.

Официальная отправная точка по уведомлению: [Портал персональных данных Роскомнадзора](https://pd.rkn.gov.ru/operators-registry/notification/).

## 3. Обязательные результаты

### PRIV — персональные данные

- реестр целей, категорий данных, субъектов, систем, получателей и правовых оснований;
- утверждённая матрица «платформа / клиника / специалист: оператор или лицо по поручению»;
- доказуемый lifecycle согласия на обработку сведений о здоровье;
- запросы субъекта: доступ/экспорт, исправление, прекращение обработки/удаление в допустимых пределах;
- retention matrix для БД, файлов, сообщений, журналов, резервных копий и платёжных данных;
- offboarding организации без утечки или бесконечного хранения данных;
- комплект модели угроз, уровня защищённости и применимых мер, подтверждённый внешним специалистом.

### SECOPS — production security и устойчивость

- default-deny периметр, управляемый SSH, защита от перебора и минимальные привилегии процессов;
- реестр и проверяемая ротация секретов;
- шифрованные резервные копии, отдельная российская копия, контроль целостности и restore drill;
- определённые RPO/RTO и проверенный сценарий потери VPS/БД/S3;
- журнал успешного и неуспешного доступа к чувствительным данным без самих клинических значений в логах;
- контролируемые security logs, alerts, access review, incident runbook и tabletop drill;
- Security CI и процесс устранения находок с владельцем и сроком.

## 4. Вне scope

- медицинская лицензия, клиническая диагностика и медицинские рекомендации;
- смена Selectel или вывод данных за пределы РФ;
- повторная разработка tenant walls/RLS, тарифов, billing, платежей и S5 settings split;
- установка software на production без отдельного owner-approved change window;
- автоматическое исправление находок security-сканеров;
- сертификация средств защиты или аттестация ИСПДн до отдельного решения профильного специалиста.

## 5. Общие требования к исполнению

- Для каждого этапа: worker → risk-based audit → не более двух содержательных correction rounds.
- На границах `PR-01`, `PR-02` и финального gate обязательна приёмка владельца; audit PASS её не заменяет.
- Production-факты сначала подтверждаются read-only командами по `SERVER CONVENTIONS`, затем в документацию
  попадают только non-secret значения.
- Все миграции backward-compatible, tenant-aware и с rollback/rehearsal; новые unscoped clinical tables запрещены.
- Большая инициатива получает один полный `pnpm run ci` перед merge/release checkpoint, а не после каждого шага.
