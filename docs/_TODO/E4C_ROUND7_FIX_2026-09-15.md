## Что сделано

### F1 — восемь поимённых поломок

В `FAULTS`, allowlist внешнего теста и существующий инжектор добавлены ровно восемь имён из аудита.
Фикстура отказа теперь наблюдает неверный `id` чтения и запись approval в соседнюю строку/пару через
`FACTS.neighbourRows`. Фикстура двух клиник содержит пять независимых decoy-решений: чужую организацию,
закрытый статус, немедицинскую причину, отсутствие `doctorApproved` и чужую неупорядоченную пару. Их принятие
видно в `FACTS.neighbourAdmission` как фактическое слияние вместо `awaiting_other_organization`.

| Новая поломка                     | Наблюдаемое утверждение, которое краснеет                                                                                       |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `approval-write-any-row`          | `deepEqual(facts.neighbourRows, ...)`: у `pending` появляется комментарий «подтверждение не той строки»                         |
| `approval-write-any-pair`         | `deepEqual(facts.neighbourRows, ...)`: у `pending` появляется комментарий «подтверждение не той пары»                           |
| `refusal-read-any-row`            | `equal(facts.wrongRowTraceRead, null)`: по постороннему UUID возвращается snapshot собственного разобранного отказа             |
| `neighbour-approval-any-org`      | `deepEqual(facts.neighbourAdmission, ...)`, ключ `wrongOrg`: outcome становится `merged`, а duplicate получает `merged_into_id` |
| `neighbour-approval-any-status`   | то же, ключ `closed`: закрытая строка признаётся одобрением и outcome становится `merged`                                       |
| `neighbour-approval-any-reason`   | то же, ключ `nonMedical`: немедицинская строка признаётся одобрением и outcome становится `merged`                              |
| `neighbour-approval-not-required` | то же, ключ `notApproved`: строка без `doctorApproved` признаётся одобрением и outcome становится `merged`                      |
| `neighbour-approval-any-pair`     | то же, ключ `wrongPair`: решение другой пары признаётся одобрением и outcome становится `merged`                                |

### F2 — маркер и воспроизводимая матрица

`replaceOnce` печатает `FAULT INJECTED: <name>` сразу после каждой успешной замены из одного общего места.
Для двух нестроковых инъекций (`privilege`, `staff-insert`) тот же центральный formatter вызывается после
успешного изменения живой транзакции. Удалены ручные `say`-ветки отдельных fault-имён.

Матрица сохранена рядом с набором:
`deploy/postgres/privileges/doctor-medical-merge-door.fault-matrix.sh`. Она считает fault пойманным только при
`rc=1` **и** точном маркере; отсутствие маркера увеличивает отдельный `marker_missing`. Rollback считается только
по исходным TAP-comment строкам, а не по диагностическим копиям output внутри упавшего assertion.

### F3 — `refusal-write-any-row`

Инъекция меняет `id = p_conflict_id` на `id <> p_conflict_id`. При фикстуре с ровно одной подходящей соседней
pending-medical строкой дверь обновляет её. Proof печатает `FACTS` до выхода: целевая `ownResolved` остаётся
`pending`, соседняя `pending` становится `dismissed`, получает комментарий врача и
`resolvedBy=clinicA_doctor`. Краснеет `deepEqual(facts.neighbourRows, ...)`; `P0003` нет.
