# Сотрудничьи двери входа задаются кодом, а не переключателями админки

Решение владельца 16.09.2026, дословно: «пусть сценарии входа сотрудников будут жестко заданы
(основа), выбирается только требование 2FA и подкобчение сотрудником входа по ТОТП или коду на
почту»; «ну и пасскей как вариант»; «и переключатели сами убрать можно»; про поверхности — «для
терапиго оно доступно а для тераписто и админ.тераписто - нет». Про прежнюю схему: «это защита
настройкой, а не устройством - вот это убрать. зря сделали», «то есть это как раз стоит
захардкодить».

Канон, с которым сверяется работа: `docs/ARCHITECTURE/AUTH_AND_IDENTITY_CANON.md` — таблица «Дверь |
Способы входа | Сессия» и записанный перед разделом «### 2. Текущие маршруты» блок этого решения.

## Откуда взялась работа

15.09 по прямому вопросу владельца («17 групп маршрутов — разбери их аудитором и сам») прошёл аудит
дверей входа (`docs/_TODO/AUTH_DOORS_AUDIT_2026-09-15.md`). Одна из находок: телефонная дверь не
спрашивает, на какой поверхности её позвали, — только глобально включён ли канал. Замер ведущего на
живом TEST показал, что прямо сейчас сценарий не проходит: у `test.therapysto.ru` в публичном
конфиге входа все кодовые каналы `false`. То есть сотрудника защищала НАСТРОЙКА: один переключатель в
админке — и телефонный код становится полной заменой пароля, молча и без единого красного теста.
Владелец решил убрать саму возможность.

## Этапы

- [x] **С1. Телефонный метод убран из набора сотрудничьих поверхностей.** Ведущий, `3e0a5c616`:
      `staff` и `platform_admin` больше не содержат `phone_bot` в `availableMethods`, а проверка
      канала отвечает отказом ДО чтения настройки (`surfaceAuthControlAvailable`). Тесты написаны;
      прогон — первый шаг С2, в клоне не было зависимостей.
- [ ] **С2. Переключатели каналов у `staff` и `platform_admin` сняты совсем** — ключи настроек,
      записи реестра, строки экрана админки и все чтения. У пациентской поверхности остаются.
- [ ] **С3. Состав сотрудничьей двери — константа кода:** почта с паролем как основа, passkey как
      вариант; ни один пункт не зависит от записанной настройки поверхности.
- [ ] **С4. Второй фактор — выбор самого сотрудника** (TOTP или код на почту); механика
      `staffSecurity` не переделывается, только перестаёт читать снятые переключатели.
- [ ] **С5. Требование 2FA остаётся административной настройкой** («выключена / добровольная /
      обязательная») — не переносится в код.
- [ ] **С6. Приёмка:** независимый адверсарный аудит другой моделью, чем автор, затем глаза
      владельца на живом стенде. Галочка этапа не ставится до последнего.
      **Владелец 16.09 передал глаза ведущему: «С6 — проверь сам глазами на дев».** Проверка
      сделана 16.09 на живом `127.0.0.1:5200`, снимки `/home/dev/shots-c6/{doctor,admin,patient}-login.png`.
      Экраны верны: у `/app/doctor/login` и `/app/admin/login` ровно две кнопки — «Войти по ключу
      доступа» и «Войти по email», ни телефона, ни мессенджеров, ни OAuth; пациентский
      `/app/patient/login` цел — Яндекс, почта, номер телефона. Живые двери на сотрудничьей
      поверхности: `email-otp/start` → `auth_channel_disabled`, `oauth/start` → `oauth_disabled`.
      **Галочка НЕ ставится: найдена дыра — см. С7.**
- [ ] **С7. `phone/start` на сотрудничьей поверхности отвечает `ok` — дверь не закрыта.** Замер
      ведущего 16.09 на DEV (поверхность `staff`, публичный конфиг отдаёт `{"email":false,"sms":false,"telegram":false,"max":false}`):
      `POST /api/auth/phone/start` с одним номером возвращает `{"ok":true,"challengeId":…,"deliveryChannel":"automatic"}`.
      Причина найдена в коде: `apps/webapp/src/app/api/auth/phone/start/route.ts:88-89,143` —
      проверка канала стоит под условием `!automaticPublicLogin`, а обычный публичный вход по
      номеру идёт именно автоматической веткой и не спрашивает ни канал, ни набор способов
      поверхности. Поверхность в маршруте читается только ради брендированной организации
      (`:83-85`). То есть С1–С5 закрыли ПЕРЕКЛЮЧАТЕЛИ, а эта дверь их не спрашивает.
      Основание — прямое слово владельца 16.09: «а, ну так надо просто вырезать в тераписто
      /api/auth/phone/start (или заблокировать» — и таблица дверей канона, где у сотрудника
      телефона нет. Требуемый результат: маршрут отказывает ДО всякой ветки, если набор способов
      поверхности не содержит `phone_bot`; пациентская поверхность не задета.
      ⚠️ Файл сейчас правит соседняя сессия (#1005, вход по номеру) — этап начинается после того,
      как её работа приземлится, иначе две правки одного файла столкнутся.

## Границы

Пациентский вход не меняется ни одной строкой поведения. Двери `api/auth/*` правятся только там, где
это прямо следует из этапов выше. Прод и TEST не трогаются. Миграции из клона на DEV не
накатываются. Полный CI — только когда в `feat` приедет исполняемый код.
