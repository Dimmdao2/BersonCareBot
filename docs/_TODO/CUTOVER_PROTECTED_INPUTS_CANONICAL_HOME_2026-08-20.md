# Защищённые входы раскатки — штатное место, а не поиск по диску

Решение владельца 20.08, дословно: «Манифест на месте — но ты его не нашел значит он не там где должен
быть. ЕГО НЕ ДОЛЖНО БЫТЬ НУЖНО ИСКАТЬ».

## Что сломано (замерено)

`deploy/host/deploy-test-saas.sh` принимает манифест ФИО ТОЛЬКО как аргумент: `--fio-manifest=<путь>` плюс
`--fio-manifest-file-sha256`, `--fio-manifest-sha256`, `--fio-review-source-sha256` (строки 2329-2358, все
четыре обязательны, 2354-2356). Дефолта нет. В шапке скрипта (строки 20-21) и в подсказке по использованию
(строка 2302) как пример стоит `/secure/fio-manifest.json`; каталога `/secure` на боксе не существует.
`apps/webapp/scripts/fio-backfill/README.md` (строки 152-158) повторяет тот же несуществующий путь.

Фактически файлы лежат в `/tmp/bcb-cutover-inputs/` (`0600`, владелец `deploy`), имена не совпадают ни с
одним документом: `fio-owner-reviewed-test-20260820-merge-preserve.manifest.json` и `.payload.json`, рядом
`fio-owner-reviewed-test.manifest.json` от 15.08 и `rubitime-records.csv`. Найти их можно было только
раскопками по логам чужого рана.

Отдельно: `/tmp` — неверный дом для входа раскатки с ПДн. Он чистится, и переживать перезагрузку не обязан.

## Чек-лист

- [x] Канонический каталог защищённых входов, вне `/tmp`, права `0700` на `deploy`. Один путь, зашитый в
      скрипт константой, а не переданный аргументом. — `/opt/env/bersoncarebot/protected-inputs`,
      `deploy/host/deploy-test-saas.sh` (`PROTECTED_INPUTS_DIR`); `sudo -n ls -la` подтвердил `deploy:deploy 0700`.
- [x] Стабильные имена: манифест ФИО и его payload лежат под фиксированными именами, версия — внутри файла
      (`runId`, `createdAt`), а не в имени. — `fio-owner-reviewed-test.manifest.json` и
      `fio-owner-reviewed-test.payload.json`; JSON key inspection подтвердил оба version-key без печати ПДн.
- [x] Рядом с манифестом — файл-спутник с тремя sha256 (хеши не секрет). Оператору не нужно их помнить. —
      `fio-owner-reviewed-test.sha256`, три именованные строки, hashes сверены с raw/canonical inputs.
- [x] `--fio-manifest` и три хеша становятся НЕОБЯЗАТЕЛЬНЫМИ: при отсутствии берётся канонический путь и
      хеши из спутника. Явный аргумент по-прежнему побеждает. — no-argument protected-input preflight дошёл до
      `FIO manifest: protected input + SHA-256 OK`; явный нулевой file hash дал mismatch, exit 2.
- [x] Проверка хешей НЕ ослабляется: несовпадение — по-прежнему отказ. Отсутствие файла — отказ с печатью
      ТОЧНОГО ожидаемого пути. — переименование дало exact-path abort, exit 2; однобуквенная порча sidecar дала
      `FIO manifest SHA-256 mismatch`, exit 2; оба файла восстановлены.
- [x] Существующие файлы перенесены в канонический каталог с сохранением прав и владельца. — текущая пара,
      предыдущий manifest и `rubitime-records.csv` имеют `deploy:deploy 0600`; ничего не удалено.
- [x] Шапка скрипта, строка usage и `fio-backfill/README.md` называют реальный путь. — также добавлен операторский
      раздел в `deploy/HOST_DEPLOY_README.md` рядом с backup contract.

## Приёмка

Готово = галочки выше + прогон `deploy-test-saas.sh` без аргументов манифеста доходит до стадии ФИО и
подтверждает хеши + отказ с точным путём при переименованном файле. Живой полный сброс TEST — отдельно.
