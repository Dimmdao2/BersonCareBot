## Задача 1 (главная) — сторож сырого SQL обходится комментарием

`scripts/check-no-new-raw-sql.mjs` смотрит только на первый SQL-токен аргумента и не отбрасывает комментарии.
Доказанный аудитом обход: `pool.query('/* comment */ SELECT 1')` в новом файле → `exit 0`, то есть новый сырой SQL
проходит. Пока это так, D18a не выполняет своего обещания, и галочка в плане снята.

Сделать проверку **fail-closed**: любой строковый литерал или шаблон, переданный в `.query(...)` из файла вне
замороженного манифеста, — нарушение, независимо от того, чем начинается текст. Не строить список «плохих начал»;
разрешение должно быть по файлу из манифеста, а не по виду строки.

**Доказательство обязательно:** самопроверка (self-test) внутри скрипта или отдельный тест, где случай
`/* c */ SELECT 1` падает. Приложить дословный вывод падения. Плюс проверить, что честный путь
``db.execute(sql`...`)`` по-прежнему проходит, и что удаление живой строки манифеста роняет проверку.
