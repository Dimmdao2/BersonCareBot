## Что проверить

1. **Обойти сторож.** Придумать СВОИ способы протащить сырой SQL мимо него, не трогая манифест. Уже
   проверены и падают: комментарии обоих видов, перенос строки, шаблон с интерполяцией, чужой объект,
   псевдоним через `bind` и через присваивание, склейка строк, доступ по индексу `pool['query']`,
   необязательный вызов `pool.query?.()`, запрос в переменной. Ищи то, чего в этом списке нет:
   реэкспорт, обёртка-функция в другом файле, динамический `import`, `eval`, переименование при импорте,
   вызов через `Reflect`/`apply`, генерация имени метода, файл с расширением, который сканер не читает,
   путь, который не попадает в обход каталогов. Для каждого — дословный вывод и вердикт.
2. **Не сломан ли честный путь:** ``db.execute(sql`…`)`` и обычные вызовы Drizzle обязаны проходить.
3. **Манифест честен:** девять добавленных путей — это существовавшие ранее вызовы инфраструктуры пулов,
   а не новый долг. Сверить с историей файлов; назвать, если что-то внесено задним числом.
4. **Проверка не декоративна:** сломай её саму — падает ли самопроверка; удали живую строку манифеста —
   падает ли основной прогон.
5. **Лишнего не внесено:** коммит трогает только сторож.
