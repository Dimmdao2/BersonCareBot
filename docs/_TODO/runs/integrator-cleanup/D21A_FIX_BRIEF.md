## Что сделать

1. **F1 — главное. Тест сквозного пути кнопки.** Аудитор уже показал, как: временный зонд гонял **реальные**
   `scripts.json` через реальный `buildPlan` и реальный `executeAction`, без мока сценария. Сделать это
   постоянным тестом для обоих каналов: нажатие «Пропустить» доходит до обработчика с нужным составом
   полей, **без** кода причины и **без** перевода диалога в ожидание. Тест обязан краснеть на каждой из
   семи поломок аудитора — перечислить их в отчёте поимённо и показать красное по каждой.
2. **F2 — связать кнопку с разбором.** Сборка клавиатуры пишет литерал `rem_skip:`, разбор читает свой
   литерал; между ними нет ничего. Заменить на общую константу или тест, ловящий расхождение.
3. **F3 — вечно зелёное утверждение.** Тест проверяет отсутствие строки, которой в исходниках нет вообще:
   он не может покраснеть никогда. Переписать на проверку поведения либо удалить.
4. **F5 — проверка владения занятием.** Коммит переписал строку с этой проверкой (убрал `!reasonCode` из
   условия). Снос проверки сегодня не ловится ничем: **чужое занятие можно пропустить**. Покрыть тестом.
5. **F4 — живые доки описывают удалённое как текущее** («выбор причины остаётся для старых клавиатур»,
   `reasonCode: none`). Привести к факту.
6. **F6 и F7 — честность отчёта.** В `D21A_SKIP_REASONS_REPORT.md` дописать: фактический размер коммита и
   то, что внесённая исполнителем поломка возвращала только файлы обработчиков, а не тот слой, который
   правился. Это не переписывание истории, а исправление неверного утверждения.
