## Пять модулей и что обязан поймать тест

14. `repos/idempotencyKeys.ts` — занятие ключа под гонкой: два одновременных `tryAcquire` — успех ровно у одного.
15. `repos/outgoingDeliveryQueue.ts` — захват одной строки двумя воркерами; постановка «если ещё нет»
    (`enqueueIfAbsent`); предел возврата зависших.
16. `bersoncare/bookingLifecycleRoute.ts` — дедупликация событий живёт **в памяти процесса**: после рестарта
    повтор пройдёт заново и человек получит два напоминания о приёме. Тест обязан зафиксировать это
    поведение как есть; менять его нельзя — это развилка №2 карты, ответа владельца нет.
17. `adapters/dispatchPort.ts` — провал записи аудита не должен приводить к повторной отправке.
18. `delivery/deliveryContract.ts` + `runtime/worker/retryPolicy.ts` — **две лестницы отступов и два места,
    где считается «сколько попыток осталось»**. Тест обязан зафиксировать, какая из них целевая; если по
    коду это неоднозначно — строка в «развилки», а не догадка.
