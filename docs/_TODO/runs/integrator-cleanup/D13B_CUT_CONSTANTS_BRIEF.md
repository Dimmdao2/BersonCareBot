## Что резать

Решение владельца — «вырезать нещадно»: смещения 24ч/2ч и тексты в `bookingLifecycleRoute.ts` (ориентир по
плану — строки ~365-376, номера могли сместиться после D14; ищи по смыслу, не по номерам).

**Порядок работы, обязательный:**
1. **Сначала перепись.** Для КАЖДОЙ константы и каждой запасной ветки («поля нет → прежнее поведение»),
   заведённой в D14, доказать, что вебапп теперь всегда присылает значение. Доказательство — код отправителей
   (`modules/patient-booking/*`, `app-layer/booking/*`), а не рассуждение. Список: константа → кто её теперь
   присылает → где это видно.
2. **Резать только доказанное.** Ветка, для которой отправителя не нашлось, НЕ режется: она остаётся, а факт
   выносится в отчёт отдельной строкой. Это не недоработка, а правильный исход.
3. Убирать целиком, а не помечать «устаревшим»: владелец 28.07 — «не надо держать ради истории устаревшее».

## Приёмка

- построчная перепись: константа → отправитель в вебаппе → вырезано / оставлено с причиной;
- тест: напоминания ставятся по плану от вебаппа, и при этом в интеграторе больше НЕТ пути, где смещение
  берётся из константы — доказать, что старый путь отсутствует, а не просто не вызывается;
- тест краснеет, если вернуть константу как запасной вариант — дословный вывод до и после;

- `pnpm --filter @bersoncare/integrator lint`, `pnpm --filter webapp lint`, оба `typecheck` зелёные;
