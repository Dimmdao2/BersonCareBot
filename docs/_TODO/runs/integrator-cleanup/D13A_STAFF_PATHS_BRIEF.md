## Почему эта работа появилась

Прогон `worker-d13b-cut` отказался резать константы интегратора и был прав — я перепроверил лично. Предусловие
D13b («вебапп всегда присылает план напоминаний») выполняется НЕ везде:

| путь | шлёт `reminderPlan` |
| --- | --- |
| пациент создаёт запись (`modules/patient-booking/canonicalCreate.ts`) | да |
| пациент переносит (`modules/patient-booking/service.ts`) | да |
| подтверждение оплаты (`app-layer/booking/appointmentPaymentConfirmedHandler.ts`) | да |
| **персонал создаёт/переносит** (`app-layer/booking/staffBookingIntegratorEvent.ts`) | **НЕТ** |
| **ручные маршруты**: `api/admin/booking-engine/appointments/manual`, `api/doctor/booking-engine/appointments/manual`, `api/doctor/booking-engine/appointments/manual-patient-visit` | **НЕТ** |

Проверено: `staffBookingIntegratorEvent.ts` шлёт `booking.created` и `booking.rescheduled`, но поля плана в
событии нет (`grep reminderPlan` по файлу — пусто). Значит сегодня для записей, созданных врачом или админом
вручную и перенесённых персоналом, напоминания ставит интегратор своими константами 24ч/2ч. Вырежи их
сейчас — эти пациенты молча перестанут получать напоминания: **ошибок в логах не будет, деплой останется
зелёным, обнаружится по неявкам** (формулировка самого плана).

## Что сделать

Подключить план напоминаний во ВСЕХ путях персонала — так же, как это сделано для пациентских путей в D13a:
вебапп читает настройки клиники, строит план и кладёт его в событие. Один способ на все пути, не копипаст.

Обрати внимание: у ручных маршрутов может не быть части данных, которые есть у пациентского пути. Если для
какого-то пути план построить нечем — **назови это отдельной строкой с причиной**, не подставляй умолчание молча.

## Приёмка

- построчная таблица: путь → шлёт план (да/нет) → чем доказано;
- тест на каждый путь персонала: событие содержит план, и план соответствует настройкам клиники;
- тест краснеет, если путь перестал класть план — дословный вывод до и после;
- существующие тесты D13a/D14 остаются зелёными;
- ⛔ **константы интегратора в этой работе НЕ резать** — это следующий шаг (D13b), он пойдёт только после
  доказательства, что план шлют все пути;
- `pnpm --filter webapp lint`, `pnpm --filter @bersoncare/integrator lint`, оба `typecheck` зелёные;
- галочки плана не ставить, push и merge не делать.
