## Что измерено и с чем ты имеешь дело

Бэкенд VK **уже сделан**: `app/api/auth/oauth/start/route.ts` знает `'vk'` (строки 47, 62, 69, 204-206), есть
callback, есть проверка включённости, есть ключи в админке (`vk_id_application_id`, `vk_id_client_secret`,
`vk_id_redirect_uri`) и их приём в `api/admin/settings/route.ts`.

Не сделан **экран**. Тройка `yandex/google/apple` зашита литералом: `modules/auth/publicAuthSnapshot.ts:12-22`
отдаёт ровно три флага, `shared/ui/patient/auth/AuthFlowV2.tsx` объявляет тип на три поля (216), инициализирует
его дважды (257-260, 349-352) и перечисляет три флага в четырёх условиях (355, 396-398, 421-423, 442-444).
`app/app/admin/auth/PlatformAuthChannelPolicySection.tsx:22` — ещё одна такая же тройка.

## Работа

1. **Один реестр провайдеров** — данные, а не повторяющийся литерал: ключ, подпись, признаки «включён» и
   «настроен». Снимок для экрана и условия «есть ли вообще OAuth» строятся из него перебором. После правки
   добавление провайдера — это строка в реестре, и ни одного нового `||`.
2. **VK показывается только когда включён И настроен** (заполнены его ключи). Ненастроенный провайдер не
   должен появляться кнопкой, которая ведёт в ошибку.
3. **Клиентский код VK грузить лениво** — ровно то, о чём спросил владелец: отдельный модуль, который
   подключается только если VK включён и настроен, и не попадает в бандл остальным. Если VK ID технически
   работает обычным redirect-потоком без их SDK — скажи это прямо и не тащи SDK ради галочки; выбор обоснуй.
4. **Не расширять скоуп до переделки экранов входа.** Инвентаризация показывает несколько входных дверей;
   здесь — только источник списка провайдеров и появление VK, без перекладки вёрстки и без изменения порядка
   экранов (это отдельная работа, владелец её ещё не назначил).
5. **Покрыть поведением:** провайдер выключен → кнопки нет; включён, но не настроен → кнопки нет; включён и
   настроен → кнопка есть и ведёт в свой `start`; ни одного провайдера → блок OAuth отсутствует целиком.
