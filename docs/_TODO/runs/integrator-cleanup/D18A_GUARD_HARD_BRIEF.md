## История: что уже ловится и что нет

Первый круг ловил только первое слово запроса. Обход комментарием (`pool.query('/* c */ SELECT 1')`) проходил.
Второй круг это починил и заодно закрыл: `--` комментарий, перенос строки, шаблон с интерполяцией, вызов на другом
объекте. **Аудит `audit-d12-d18a-fix` нашёл ещё два прохода:**

- вызов через псевдоним: `const query = pool.query.bind(pool); query('SELECT 1')` — проверка требует прямой `obj.query(...)`;
- склейка строк: `pool.query('SELECT ' + column + ' FROM users')` — `BinaryExpression` не распознаётся как текст запроса.

## Задача

Перестать угадывать форму аргумента. Требование D18a простое: **в файле вне замороженного манифеста не должно быть
сырых запросов вообще.** Значит и проверка должна быть по этому признаку, а не по разбору того, что именно передали.

Предложенный подход (можешь заменить своим, если он строже и проще): в файле не из манифеста запрещён ЛЮБОЙ вызов
`.query(`, независимо от объекта, псевдонима и вида аргумента; разрешение выдаётся файлом из манифеста, а не видом
строки. Если такой запрет ловит честные библиотечные вызовы `.query(` не про SQL — назови их поимённо в отчёте и
предложи узкое исключение по модулю-источнику, а не по форме аргумента.

Требование к результату: **ни один из шести обходов не проходит** — комментарий (`--` и `/* */`), перенос строки,
шаблон с интерполяцией, чужой объект, псевдоним через `bind`/присваивание, склейка строк. При этом честный путь
``db.execute(sql`…`)`` проходит, а удаление живой строки манифеста — падает.
