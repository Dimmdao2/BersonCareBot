## Как писать

- **Каждый тест — «дано … когда … тогда …»** из карты, в терминах «чей это аккаунт / чьё сообщение», а не
  «функция вернула X».
- **У каждого теста — свой арбитр** в комментарии: что сломать в продуктовом коде, чтобы он покраснел.
- **Арбитра проверить делом**, не поверить на слово: внести поломку, снять дословный вывод до/после, откатить,
  сверить с `git show HEAD:<файл>`, что откат точный.
- Прогнать самопроверку «переформатирование не красит тесты» (как на уровне 0: `prettier --print-width 60` по
  затронутым продуктовым файлам, тесты обязаны остаться зелёными) и написать результат в отчёт.
- Не переписывать продуктовый код без необходимости. Если поведение непроверяемо без правки — сказать в отчёте,
  предложить минимальную правку, не делать её молча.
- Если для проверки токена (пункт 1) нужен настоящий секрет/время — держать это управляемым в тесте (fake
  timers / инжектируемый секрет), не обращаться к живым сервисам.
