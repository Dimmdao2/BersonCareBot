## Проверки по пунктам брифа

**1. Дефолт побайтно прежний.** Все удалённые литералы вытащены из диффа механически

приёме» и «Следующий прием» → «Следующий приём». Уточнение к записи в плане: **два написания, но три

## Находки: вопросы ведущему, не работа (§24.6)

**N1. Три из четырёх примеров, названных владельцем в строке T-B, физически лежат в кабинете
клиента.** Строка плана перечисляет «Очный приём», «Формат приёма», «Новое время приёма», «Журнал
прошедших приёмов». Замер: «Формат приёма» — `app/app/patient/cabinet/BookingFormatGrid.tsx:25`;
«Новое время приёма» — `app/app/patient/booking/slot/page.tsx:59,96`; «Журнал прошедших приёмов» —
`app/app/patient/cabinet/CabinetPastBookings.tsx:52`. Все три не тронуты и по границе прохода
относятся к T-D. Аналоги на стороне специалиста закрыты («Формат», «Подтвердите новое время приёма»,
«История приёмов»). То есть по заголовку строки блок закрыт, по её примерам — нет. Решение, куда
отнести эти три строки, за ведущим/владельцем; сам по себе это не дефект кода.

**N2. Число колл-сайтов в записи плана занижено.** Запись говорит «13 колл-сайтов зовут резолвер без
значения `appointment_label`». Измерено разбором по дереву скобок: 18 (17 продуктовых + 1 в тесте),
поимённый список приложен выше. На вывод «нужен T-G» это не влияет, но цифру в плане стоит поправить.

**N3. Два из 21 изменённого файла не импортируются нигде.** `DoctorCurrentAppointmentCard.tsx` и
`tabs/karta/EncounterSummary.tsx` не имеют ни одного потребителя во всём репозитории (проверено
полнотекстовым поиском по имени, не только по `import`). Их переведённые надписи — включая «Предыдущая
тренировка», «Тренировки: N», «Не удалось загрузить тренировки» из замерной таблицы отчёта — на экран
не попадают, и живая приёмка их проверить не сможет. Мёртвыми они были и до этого коммита; это факт
для приёмки, а не дефект прохода.

**N4. Синоним «визит» остаётся на экране рядом с выбранным словом.** В `EncounterViewModal` заголовок
станет «Тренировка», а строкой ниже сохранится «— файлы, прикреплённые к визиту». «Визит» в набор
владельца не входит и по плану не переключается — вопрос владельцу, работой автоматически не
становится.

**N5. «Сейчас на приёме» в живом кабинете приходит из двух разных компонентов** —
`DoctorCurrentAppointmentCard` (мёртвый, см. N3) и `DoctorTodayNextAppointment` (живой). При живой
приёмке проверять надо второй.
