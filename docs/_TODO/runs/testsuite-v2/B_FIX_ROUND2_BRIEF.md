## Что чинить — по убыванию цены ошибки

1. **Откатить удаление** `apps/webapp/src/infra/repos/pgProgramItemDiscussion.doctorComments.devDb.integration.test.ts`
   (`git show 9a0b514c3^:<путь>`). Аудит доказал арбитром, что файл ловит настоящую поломку
   (`42702 column reference "id" is ambiguous`). Вернуть как есть, пометить кандидатом на перенос.
   Остальные 11 удалений подтверждены — их не трогать.
2. **`DATABASE_URL` больше не читается на этапе сбора.** Сейчас пул строится до `beforeAll`, и на машине
   разработчика тесты уходят в живую `bcb_webapp_dev`. Брать из `globalSetup`/провайдера. Плюс утверждение
   в общем setup: имя текущей базы обязано соответствовать одноразовой (`current_database()` по шаблону
   имени), иначе прогон падает — чтобы ни один будущий тест не мог молча уехать в DEV.
3. **Схема — эталон + дельта.** Требование «только миграции с нуля» снято решением Б1а: цепочка не
   самодостаточна (`platform_users` не создаётся ни одной из 287 миграций). Стартовать с эталона
   `a0-greenfield`, миграции накатывать поверх. **Дамп живой базы запрещён по-прежнему.**
4. **Транспорт — на существующий `resolveTrustedPostgresBinaries` + `initdb`/`pg_ctl`.** Это снимает
   требование `sudo`, делает харнесс пригодным для CI и **убирает второй механизм поднятия базы**,
   построенный рядом с тремя имеющимися `verify-*.mjs`. Второй механизм не оставлять.
5. **Права роли клона** — после клонирования шаблона роль не владеет таблицами (`permission denied for
   table`). Миграции и тесты под одной ролью либо `GRANT`/`ALTER … OWNER` после клона.
6. **Уборка полная** — `buildTemplateDatabase` в `try/finally`; клоны дропать раньше роли шаблона; сейчас
   течёт при падении миграций.
