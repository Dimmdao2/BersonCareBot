## Скоуп — ровно три пункта, в этом порядке

### М4 — гейт «раннер видит каждый тест-файл» (первым: даёт доказательство в момент включения)

Сегодня в `apps/webapp` 22 файла `*.devDb.integration.test.ts` не выбираются НИ ОДНИМ vitest-проектом:

```bash
cd apps/webapp && pnpm exec vitest list --filesOnly | sed 's/^\[[a-z]*\] //' | sort -u   # 99
find src \( -name '*.test.ts' -o -name '*.test.tsx' \) | sort                            # 121
pnpm exec vitest run src/infra/repos/pgDoctorClients.devDb.integration.test.ts
#   → "No test files found, exiting with code 1"
```

Канон это уже запрещает (`test-execution-policy.md`, чек-лист аудитора п.4: «zero-file или висячий include не
считается зелёным»), проверки нет ни одной.

Сделать: скрипт, который по каждому приложению сравнивает список тест-файлов на диске со списком, который
реально отдаёт раннер, и **падает на расхождении**. Подключить к CI (там же, где живут остальные механические
гейты — корневой `pnpm lint` → `ci.yml`).

⚠️ **Эти 22 файла НЕ трогать и НЕ удалять** — их разбирает параллельный воркер (блок Б3), это чужой скоуп.
Чтобы гейт вошёл зелёным и при этом не легализовал дыру: список известных исключений держать **только на сокращение** —
файл с ровно этими 22 путями и датой; гейт падает, если появился НОВЫЙ невидимый раннеру файл ИЛИ если запись
в списке протухла (файл уже удалён/перенесён). Список имеет право только сокращаться.

**Самотест обязателен** (`test-execution-policy.md`: «у любого механического гейта обязан быть самотест
„сломай специально — убедись, что заметил“»): временно создать тест-файл, не попадающий ни в один проект,
показать красный вывод гейта, удалить файл. Дословный вывод — в отчёт.

### М2 — три отказа в `tools/orch-launch.sh`

Дописывать САМ порт, а не обходить его. Стиль уже задан существующими проверками (`die "ОТКАЗ: …"` с объяснением
причины и способа обойти осознанно). Три новых условия:

1. **Аудит тестов — только ролью `auditor-live`.** Если бриф упоминает поломки/fault injection/арбитров/аудит
   тестов, а роль запуска — обычный `auditor`, порт отказывает с объяснением: `auditor` уходит в песочницу
   read-only и физически не может внести поломку (так первый аудит уровня 2 выдал предсказания вместо прогонов).
2. **Бриф воркера обязан называть строку плана, дающую оракул.** Сегодня порт требует лишь ссылку на правила
   тестов; этого мало — воркер должен знать, ОТКУДА взято ожидаемое поведение. Проверять наличие явной пометки
   вида «Строка плана, дающая оракул:». Обход — существующий `ORCH_NO_TESTS="<причина>"`.
3. **Вердикт в очереди аудита не принимается без артефакта.** Проверка при запуске СЛЕДУЮЩЕГО воркера того же
   клона (там, где сейчас проверяется регистрация коммитов в очереди): если предыдущая работа была тестовой,
   строка вердикта обязана содержать путь к отчёту слепых поломок и число непойманного. Формат согласовать с
   тем, что уже пишется в `NIGHT_WAVE_AUDIT_QUEUE_2026-07-28.md`, новый формат не изобретать.

**Доказательство по каждому из трёх — прогон `ORCH_DRY=1`**, показывающий отказ, и прогон, показывающий проход
при выполненном условии. Дословный вывод в отчёт. Живых агентов при этом не запускать.

### М3 — Stryker как diff-scoped гейт (третьим; если распухает — остановись и скажи)

**Если diff-scoped режим требует существенной машинерии** (сборка списка изменённых строк, кэш, время прогона
за пределами разумного) — **остановиться и написать в отчёт с числами**, а не строить наполовину. Половина
