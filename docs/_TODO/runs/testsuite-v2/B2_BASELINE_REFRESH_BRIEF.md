## Проблема, которую снимаем

Штатный гейт репозитория падает **сам по себе**, без участия чьего-либо нового кода:

```bash
pnpm run check:saas-a0-greenfield-baseline
# check-a0-greenfield-baseline: drizzle_historical_hash_drift:0175_p0_8_b4_roles_1_is_staff_wall_rls
# exit 1
```

Причина: миграцию `0175_p0_8_b4_roles_1_is_staff_wall_rls.sql` правили на месте **после** того, как эталон был
снят (шесть коммитов, последние — бутстрап аксессоров принципала и `GRANT app_owner CREATE`, то есть правки,
без которых цепочка не проходит на свежем дампе). Откатывать их нельзя — сломается цепочка.

**Следствие, ради которого это делается:** на нынешней голове ветки шаблон одноразовой базы не собирается
вообще, значит блок В (матрица стен арендатора) стартовать не на чем.

## Что делать — по документированной процедуре, ничего не изобретая

Канон: [`docs/ARCHITECTURE/DB_DUMPS/a0-greenfield/README.md`](../../../ARCHITECTURE/DB_DUMPS/a0-greenfield/README.md),
раздел **«Осознанный refresh»** — прочитать целиком до первой команды. Он fail-closed: перед чтением базы
проверяет чистоту migration-каталогов, журнала Drizzle и генератора относительно `HEAD`; манифест строится из
зафиксированного `sourceCommit`; привилегированное чтение метаданных идёт только root-owned бинарями PostgreSQL.

1. **Привести DEV к ветке.** Миграции применяются недеструктивно:
   `bash deploy/host/migrate-dev.sh --preflight`, затем `bash deploy/host/migrate-dev.sh --execute`.
   ⛔ Пересоздавать DEV, лить в неё дампы TEST или прода — запрещено.
2. **Обновить эталон** ровно командой из README (`scripts/refresh-a0-greenfield-baseline.mjs` с флагом
   подтверждения и `--env-file` для `apps/webapp/.env.dev`).
3. **Прогнать оба гейта:** `pnpm run check:saas-a0-greenfield-baseline` и
   `pnpm run verify:saas-a0-greenfield-baseline` (второй поднимает приватный кластер и проверяет ноль строк во
   всех таблицах, затем накатывает штатные миграции и сверяет ledger'ы).
4. **Доказать то, ради чего всё делалось:** после обновления эталона шаблон одноразовой базы обязан собираться.
   Взять харнесс из ветки `wt/testsuite-b` (коммит `5aec73dd8`, файлы
   `apps/webapp/scripts/postgres-integration/*`) и показать сборку шаблона живым прогоном. Харнесс НЕ править —
   он чужой скоуп; если не собирается по причине, не связанной с эталоном, — это находка в отчёт, не работа.
