### M3-2 — ложный `Survived` на полностью покрытой строке решения

**Было:** `if (!value) return { ok: false, error: 'required' };` → `if (value === '') return {...}` —
покрытая тем же тестом строка, гейт **краснел** (5 из 6 мутантов `Survived`, хотя мутант убивается —
подтверждено вручную аудитором).

**Корень (найден трассировкой, не в нашем коде — сам движок Stryker/vitest-runner):**
`apps/webapp/vitest.config.ts` держит `experimental.fsModuleCache: true` — персистентный на диск кэш
трансформации модулей (`node_modules/.experimental-vitest-cache`), рассчитанный на обычный дев-цикл, где
исходник между прогонами не меняется. Stryker переписывает файл в песочнице на каждый следующий мутант
одной строки; кэш это не инвалидирует — vitest подсовывает тестам уже неактуальную (не текущего мутанта)
транспилированную версию, мутация физически не наблюдается тестами → ложный `Survived`. Изолированная
проверка (см. журнал команд ниже) с `coverageAnalysis: 'off'` бага НЕ убрала (значит дело не в фильтрации
тестов по покрытию, версия воркера круга 1 «баг perTest» была неверна) — убрал именно `fsModuleCache: false`,
причём с `coverageAnalysis` в исходном `'perTest'`.

**Фикс:** гейт больше не использует `apps/webapp/vitest.config.ts` напрямую — `check-stryker-diff-scoped.mjs`
генерирует свой временный конфиг (`generateStrykerVitestConfig`), наследующий базовый через `mergeConfig`
с переопределением `experimental.fsModuleCache: false`. Основной конфиг не тронут — кэш даёт реальную
пользу обычной локальной разработке, ломает только повторные прогоны Stryker внутри одного файла.

**До/после (дословно, `check-stryker-diff-scoped.mjs --base <тот же коммит>`, поломка та же самая правка
