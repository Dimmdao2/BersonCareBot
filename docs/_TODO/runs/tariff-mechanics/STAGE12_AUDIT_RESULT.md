## MUST FIX

1. **Класс `никогда` остаётся реальным коммерческим рубильником.**  
   Достижимый сценарий: администратор создаёт тариф; `emptyMechanics()` выставляет все скрытые ключи в `false`, полный map отправляется API, а резолвер принимает tariff boolean. После назначения тарифа POST/PATCH медицинской карточки получает `entitlement_required`. Impact: врач не может вести визиты, диагнозы и анамнез. Нарушены 2.5, канон §§3–5 и запрет делать карточку пациента/приложение управляемыми механиками.

2. **Новый тариф фактически отключает оба оставшихся числовых класса.**  
   `clinic_team` и `files` исключены из capability-checkboxes, но создаются с boolean `false`. `resolveClinicSeatLimit` при этом возвращает `0`: [service.ts:246](/home/dev/dev-projects/bcb-wt-tariff/apps/webapp/src/modules/org-entitlements/service.ts:246), а file mutation guard запрещает загрузки. Impact: введённые места и объём файлов не работают без ручного override. Нарушены 1.3, модель классов и 2.10.

3. **Класс `запас` объявлен, но типом не реализован.**  
   При добавлении обязательных этапом 4 механик «число пациентов» или «число филиалов» запись `{ class: 'запас', ... }` не проходит `MechanicDefinition`. Impact: следующий зависимый этап не может использовать принятую пяти-классовую модель без переделки stage 1. Нарушен 1.2.

4. **Platform-wide off не закрывает все записи оценочного контура.**  
   При `material_ratings_enabled=false` пациент всё ещё может POST-ить 1–3 rating feedback, который записывается через `submitPatientFeedback`. Impact: данные оценок продолжают создаваться при выключенной функции. Нарушен 2.9.

5. **Обязательные mutation gates не доказаны поведением.**  
   Удаление guard из course POST, notification-template PUT или проверки `material_ratings_enabled` оставляет оба новых service-теста зелёными. Impact: регрессия платного доступа/write refusal пройдёт текущий набор. Нарушены правила «рубильник доказывается поведением» и пункты 2.2/2.7/2.9.

6. **Формальные границы §1 плана нарушены.**  
   Вне перечисленного file scope изменены:

   - `[redacted-token].ts`
   - `[redacted-token].ts`
   - `[redacted-token]-templates/route.ts`
   - `[redacted-token]-ratings/route.ts`
   - `apps/webapp/src/modules/system-settings/registry.ts`

   Часть изменений необходима самим 2.7/2.9, то есть план внутренне противоречив: чекбоксы требуют работы в путях, которых нет в разрешённой границе. Но по заданному правилу `git diff --stat` это всё равно finding до явного уточнения scope.
