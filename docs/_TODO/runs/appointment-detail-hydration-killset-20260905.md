# Blind kill-set — appointment detail initial hydration (APPT-DETAIL-11)

Составлен `auditor-live` по authority (owner requirement APPT-DETAIL-11 + §24.4/§24.5/§10a/§10b)
**до чтения существующих тестов**. Каждый пункт — «подали X → система ошибочно делает Y».

| # | Имя | Поломка | Наблюдаемое последствие |
|---|---|---|---|
| K1 | `missing-initial-comment` | Запись с существующим первичным комментарием персонала открывается, а в первичном payload деталей комментария нет (`undefined`/пусто) | Врач видит `—` вместо реального текста; думает, что комментария нет |
| K2 | `missing-initial-payment` | Запись с оплатой/суммой открывается, а в первичном payload нет блока оплаты | Блок оплаты не отрисован первым кадром; статус денег невидим |
| K3 | `immediate-edit-loses-comment` | Сразу после открытия нажали «Изменить» — черновик инициализирован пустым, хотя комментарий есть | Сохранение затирает существующий комментарий пустотой (потеря данных) |
| K4 | `redundant-mount-fetch` | При открытии карточки уходит GET `.../comments` и/или GET `.../payment` на mount | Мигание/гонка первого кадра, лишняя нагрузка; требование «не подгружаться доп. фетчем» нарушено |
| K5 | `today-schedule-divergence` | Today-модалка и календарь «Расписание» собирают событие по разным путям → на одном хосте гидратация есть, на другом нет | На одном экране комментарий/оплата есть, на другом `—` |
| K6 | `n-plus-one` | Гидратация делает запрос(ы) на КАЖДУЮ запись диапазона | Месяц записей = сотни запросов; календарь тормозит/падает |
| K7 | `cross-tenant-leak` | Комментарий/оплата подтягиваются без фильтра по клинике/организации | Врач чужой клиники видит чужие комментарии и деньги |
| K8 | `cash-principal-regression` | Гидратация/рефактор `/payment` сломал фикс `c37f08cb8` (наличные пишутся под принципалом своей двери) | Возврат 42501 либо запись под чужим принципалом; платёж не проходит |
| K9 | `post-mutation-refresh-regression` | После платёжной мутации повторное чтение оплаты не обновляет блок (или падает из-за смены формы ответа `/payment`) | Врач принял оплату, а карточка показывает старое состояние |
| K10 | `payment-route-consumer-break` | Изменение формы ответа `/payment` ломает достижимого потребителя в репозитории | Клиент падает/рисует пусто после мутации |
| K11 | `unsafe-any-or-raw-sql` | В гидратации появился `any` без гварда или сырой SQL мимо Drizzle-репозиториев | Обход слоя доступа, необнаруживаемая рассинхронизация типов |
| K12 | `arch-boundary-violation` | Модуль импортирует infra/repo напрямую, минуя порт (§5) | Нарушение слоистой изоляции; порт перестаёт быть chokepoint |

Приёмка: каждый named fault либо пойман зелёным тестом при инъекции, либо предъявлен падающим
acceptance-тестом/инспекцией на исходной реализации.
