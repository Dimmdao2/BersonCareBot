## Почему добор

Существующий тест (`apps/webapp/src/app/api/patient/courses/route.route.test.ts`) подменяет сборщик зависимостей и
доказывает только одно: при состоянии «выключено» маршрут отвечает отказом и не зовёт данные. Не покрыто:

1. **Состояние «только чтение».** По канону чтение при нём РАЗРЕШЕНО (запрещена запись). Сейчас это никем не
   доказано — то есть регресс «read-only начал отказывать в чтении» пройдёт незамеченным.
2. **Шесть остальных точек чтения** из семи: карточка курса, расход курсов, список курсов специалиста, встроенное
   чтение статей, список приглашений и состав команды клиники.
3. **Обратная сторона видимости:** при состоянии «только чтение» раздел обязан остаться видимым (прячет только
   «выключено»). Сейчас тест видимости покрывает лишь «выключено».

## Задача

Добавить тесты на всё перечисленное. Форма — как в существующих: подменяется сборщик зависимостей, состояние
задаётся явно, проверяется наблюдаемое поведение (код ответа, вызывался ли порт данных, есть ли пункт в навигации).

Каждый новый тест обязан краснеть при снятии соответствующей проверки — приложить дословный вывод по каждому.

## Приёмка

- по каждой из семи точек: тест на «выключено» и тест на «только чтение»;
- видимость: раздел скрыт при «выключено», виден при «только чтение»;
- `pnpm --filter webapp lint` и `typecheck` зелёные;
- галочки плана не ставить, push и merge не делать.
