## Что делаем

Три числовые механики: число пациентов, число филиалов, объём файлов в байтах. Для каждой:

1. Предел ограничивает РОСТ и больше ничего: достигли — новое не создаётся, существующее работает как работало.
   Ни режима чтения, ни скрытия раздела на пределе быть не должно (решение владельца 31.07: «не давать превышать
   квоты… никто не скрывает раздел с пациентами потому что достигли лимита — бред»).
2. Проверка предела — атомарная, внутри пишущей транзакции под блокировкой, под установленным принципалом
   организации. Образец уже есть в репозитории для мест специалистов — следовать ему, не изобретать свой.
3. Пациенты: предел проверяется только при создании и реактивации; ведение существующей карточки не блокируется
   никогда; архивирование освобождает место.
4. Объём файлов: сумма байтов проверяется при загрузке; при нехватке блокируется только новая загрузка, старые
   файлы видны и скачиваются всегда.

## Доказательство гонки (обязательно, пункт 5.7)

На настоящем PostgreSQL: две одновременные попытки занять последний слот — проходит ровно одна. По каждой из трёх
механик. Не мок, не имитация: реальная база, реальные параллельные транзакции.
