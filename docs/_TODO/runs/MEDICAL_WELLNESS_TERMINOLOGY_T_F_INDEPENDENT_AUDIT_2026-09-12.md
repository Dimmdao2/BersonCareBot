2. **Полный `pnpm run ci` не гонялся.** По §9 само событие приёмки его не требует; прогнаны `tsc`,
   полный `lint` вебаппа и целевые тесты семи затронутых областей. Непокрытым остаётся
   интеграционный риск за пределами этих областей (сборка `next build`, интегратор, media-worker).
3. **Двери замерены на DEV, не на TEST и не на PROD.** Состав объявленных корней там может
   отличаться; прод не трогался вовсе.
4. **Не проверял дверь ЗАПИСИ слова** (`/api/admin/settings`) — это T-A, закрытый блок.
5. **Не проверял поведение при значении ключа вне набора владельца, записанном мимо админ-двери**
   (прямым SQL): резолвер падает в дефолт, что и требуется, но живой пробы такого ряда не делал.
6. **Не проверял web-push, напоминания и подтверждение оплаты живьём** — они в этом проходе
   намеренно не переводились.
7. **Не строил граф импортов на мёртвые файлы** (как это делал аудит T-D): в T-F дифф целиком лежит
   на путях, достижимость которых я проверил трассировкой вызывающих поимённо.

## 11. Как воспроизвести замеры

```bash
# двери по принципалам и значение слова через настоящую дверь
#   временные *.probe.test.ts в apps/webapp/src/modules/system-settings, сняты после прогона;
#   ORG=a0000000-0000-4000-8000-000000000001, staff=b0021a38-… (be_organization_members), patient=3f355fa7-… (org_enrollments)
RUN_TF_DOOR_PROBE=1 USE_REAL_DATABASE=1 pnpm exec vitest run --project fast <probe>

# базовая линия тестов
cd apps/webapp && pnpm exec vitest run --project fast --project unit --project route \
  src/modules/patient-booking src/app-layer/booking src/modules/system-settings \
  src/modules/booking-notifications src/modules/web-push src/modules/reminders \
  src/modules/patient-notifications           # 44 файла / 241 тест

cd apps/webapp && pnpm exec tsc --noEmit      # зелёный
cd apps/webapp && pnpm run lint               # exit 0
```
