# Public identity no-residue fix — 2026-08-28

## Итог

Публичный числовой `integrator user id` выведен из действующей модели личности. Человек во всех
runtime-путях называется каноническим UUID `platform_users.id`; связь с мессенджером хранится в
`user_channel_bindings`. Число осталось только у внутреннего DB-principal процесса интегратора и не
является идентификатором человека в продуктовой базе.

Исполнительский процесс Claude Opus 5 оборвался после 65 минут с ошибкой порта `invalid JSON`, не
успев сделать коммит и финальный отчёт. Рабочая копия сохранилась. Оркестратор принял изменения с
диска, проверил diff и миграцию и закоммитил сохранённый результат вручную.

## Что изменено

- Удалены публичные колонки `integrator_user_id` из канонических пользователей, правил и истории
  напоминаний, разговоров поддержки, доступов к контенту и диагностического журнала доставки.
- Callback-операции напоминаний, mute/topic-настройки, получение телефона доставки и support-door
  принимают канонический UUID и проверяют принадлежность клинике.
- Webapp-entry token принимает только закрытый набор канонических полей; любой старый или неизвестный
  ключ отклоняется общей проверкой формы.
- Telegram/MAX/VK больше не разрешают мессенджерного пользователя в публичное число и не устанавливают
  такой principal вокруг входящего события. Вебхук либо знает организацию, либо работает в bootstrap-
  контексте; сам по себе он не создаёт аккаунт.
- Удалены оставшиеся исполняемые projection/reconcile/backfill/merge-пути, которые существовали только
  ради старой публичной связи. Исторические миграции, архивы и evidence не переписывались.
- Доставка ошибок больше не дублирует вытесненный идентификатор: попытка относится к каноническому
  пользователю, событию и получателю.

## Независимая приёмка оркестратора

### Активный runtime-census

Команда:

```bash
rg -n "integrator_user_id|integratorUserId" \
  apps/integrator/src apps/webapp/src apps/webapp/db/schema contracts packages/platform-merge/src \
  --glob '!**/*.test.ts' --glob '!**/*.spec.ts'
```

Вернула только шесть строк внутреннего DB-principal plumbing:

- перенос `principal.integratorUserId` в port-context интегратора;
- тип контекста webapp;
- четыре адаптера `set_config('app.integrator_user_id', ...)` в Drizzle.

Это допустимый технический идентификатор исполняющего процесса. Публичных колонок, token-полей,
product-port полей, webhook resolver-ов или читателей старой связи в активном runtime нет.

### Миграция и права

Полный анализ изменяемых функций, владельцев, runtime-ролей, relation surfaces и причины пересоздания
