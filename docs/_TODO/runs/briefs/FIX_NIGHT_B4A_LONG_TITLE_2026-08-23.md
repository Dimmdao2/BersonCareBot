## Блокер: четвёртый случай `404`, которого не должно быть

Аудит прошёл швом целиком (настоящий `B1` → настоящий `B4` → настоящий `proxy`) и нашёл дыру:

1. форма регистрации принимает название организации **до 200 знаков** (`specialist-signup/start/route.ts:46`);
2. в базе `be_organizations.title` — `text`, ограничения нет;
3. новый путь отдаёт `core.displayName` в анонимную проекцию **без нормализации** (платный путь режет по 120);
4. санитайзер отбрасывает бренд длиннее 120 (`requestSurface.ts:90-99`) → резолвер отдаёт `null` → `404`
   **на весь хост**.

Итог: активная клиника с названием в 121–200 знаков получает мёртвый адрес — ровно то, что §1.2b-1 запрещает.

**Почини так, чтобы `404` остался ровно для трёх случаев плана: метка неизвестна, организация неактивна,
организация удалена.** Способ выбираешь сам, но держи два правила: адрес обязан жить при любом валидном
названии, и нормализация должна быть в ОДНОМ месте, общем для платного и бесплатного пути, а не двумя копиями.

Если по дороге увидишь, что правильное место — граница записи (ограничение длины названия при регистрации),
это **вопрос владельцу в отчёт, а не работа**: сейчас чинится чтение, чтобы живые клиники не падали.
