## Работа

1. Для каждой уязвимости найти **точную исправленную версию** по её advisory, а не «взять последнюю».
2. **Поднять пины до исправленных версий, оставаясь внутри своего мажора**, если это возможно: именно так
   чинилась предыдущая волна (`brace-expansion`, коммит `82ddaf06e`) — переход через мажор ломал eslint.
3. Если для какой-то уязвимости патча не существует: расширить существующий allowlist
   (`scripts/registry-prod-audit-allowlist.json`) в той же форме, что уже используется, с честным обоснованием
   — почему в проде недостижимо — и датой пересмотра. Новый механизм подавления не изобретать, уровень аудита не
   понижать, сам `registry-prod-audit` не ослаблять.
4. После правки прогнать **полный** `pnpm run ci`, а не только аудит: пины трогают дерево зависимостей, и
   поднятая версия может сломать сборку или lint — именно это случилось при прошлой попытке поднять
   `brace-expansion` через мажор.
5. В отчёте по каждому пакету одной строкой: подняли до версии X / подавили с обоснованием Y.
