## Что сделать

Сегодня резолвер отдаёт `null` (то есть `404`), если у известной активной организации нет купленного бренда.
Это неверно: адрес клиники обязан жить. Требуется:

- известная активная метка **всегда** даёт брендированную поверхность: имя берётся из `core.displayName`
  организации, оформление — платформенное по умолчанию;
- `404` остаётся ровно для трёх случаев: метка неизвестна, организация неактивна, организация удалена;
- **никаких плашек «работает на Therapygo»** — владелец это прямо запретил;
- **правка живёт в резолве поверхности**, а не отдельной веткой на странице: второго пути собирать
  поверхность в репозитории быть не должно (`TPB-16`).

## Чего НЕ трогать

- сверку происхождения бренда (`requestSurface.ts`, `afbbb348e`) — она только что прошла независимый аудит;
  твоя правка обязана её сохранить: чужая организация по-прежнему `404`;
- купленный бренд побеждает платформенный, как сейчас, — фолбэк `B4` не ломать;
- граница «свой домен клиники» из §1.2b: там `404` остаётся правильным ответом и в объём не входит.

## Доказательства в отчёте

- тесты на все четыре исхода: активная без бренда → живая страница с именем организации; активная с брендом →
  купленное имя; неизвестная метка → `404`; неактивная → `404`. Плюс чужая организация → `404` не сломана;
- покажи, что правка одна и в резолвере: `grep` по местам сборки поверхности;
- scoped lint, `typecheck`, прогон затронутых тестов с числами;
