# Клиника не может подключить свой SMTP, хотя интеграция включена везде

**Источник оракула:** `docs/_TODO/OWNER_WALKTHROUGHS/2026-08-23_TEST_FULL_WALK.md` — «Сохранить SMTP»

Канон — `AGENTS.md` (`grep -n "^## \|^### " AGENTS.md`), §1, §5, §10a.

## Что измерено на живом TEST 23.08

Врач (`dimmdao@yandex.ru`) на `/app/doctor/clinic/settings` жмёт «Сохранить SMTP»:

```
403 PATCH /api/admin/settings {"ok":false,"error":"integration_disabled","integration":"email"}
```

Три источника при этом говорят «email включён»:

- переключатель «Email (SMTP)» в кабинете глобального админа (`/app/admin/integrations`) — включён;
- строка на TEST: `platform_integration_availability` (scope `admin`, audience `server`, org `NULL`)
  → `{"integrations": {"email": true, …}}`;
- значение по умолчанию в реестре `apps/webapp/src/modules/system-settings/registry.ts:215` → `email: true`.

Подозреваемый (это гипотеза ведущего, НЕ вывод — проверь и назови настоящую причину):
`isClinicDeliveryIntegrationEnabled` (`apps/webapp/src/app/api/admin/settings/route.ts:293`) читает
настройку и имеет **пустой `catch`, возвращающий `false`**. Чтение идёт через
`getSettingWithRuntimeFirst` → `runtimeRepository.getEffective({… operationFamily: 'auth_role_config'})`,
то есть под принципалом ВРАЧА. Если этот путь под врачом отказывает, отказ молча превращается в
продуктовый ответ «интеграция выключена».

## Что сделать

1. **Сначала назови причину, потом чини.** Воспроизведи под принципалом врача на именованной DEV и
   покажи, что именно возвращает или бросает чтение. Если это отказ прав — приведи SQLSTATE и роль.
   «Похоже, из-за catch» не принимается: нужен снятый след.
2. Почини так, чтобы **отказ чтения перестал притворяться продуктовым ответом**. Пустой `catch`,
   превращающий ошибку доступа в «не подключено», — это тот же класс, что 19.08 сломал календарь.
   Ошибка должна быть видна в журнале и отличаться от честного «выключено».
3. Врачу, который настраивает СВОЮ клинику, читать глобальный рубильник нужно — сделай это
   именованной дверью с гейтом, а не расширением его прав на настройки платформы.
4. **Второй, независимый дефект в том же экране:** человеку показывается машинный токен —
   «Не подключён `integration_disabled`». Замени на человеческий текст. Различай три состояния:
   интеграция выключена платформой, тариф не разрешает свой SMTP, сервер отказал.
   Страница админа формулирует правило сама: «Выключенная интеграция не должна показываться и
   настраиваться в клинике» — при выключенной интеграции форма не должна предлагаться вовсе.

## Доказательство

- Живая проверка: врач сохраняет SMTP клиники и получает успех; при выключенном платформой
  рубильнике форма не показывается, а не падает на сохранении.
- Поведенческий тест на каждое из трёх состояний выше + fault injection.
- `typecheck`, `lint`, затронутые route-тесты — зелёные.
