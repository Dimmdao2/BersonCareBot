## Разбор прав обязателен (AGENTS.md §1)

По каждой миграции назови в отчёте: какие объекты создаёт; под какой ролью исполняется тело; хватает ли
ОБЪЯВЛЕННЫХ прав, чтобы тело ВЫПОЛНИЛОСЬ, а не только чтобы объект родился. Смотри именно то, что видно
лишь при исполнении: `SELECT … FOR UPDATE`/`FOR SHARE` требует UPDATE-класса; запись в ранее read-only
таблицу; **право, которое требует ТРИГГЕР на таблице, а не оператор тела** — для него в репозитории уже
заведён явный маркер `FunctionRelationSurface.requiredByTrigger`, пользуйся им, а не обходи гейт.
Таймштамп каждой миграции строго больше последней применённой (мигратор идёт по watermark `created_at`,
НЕ по хешу). Миграции прав не выдают: ни GRANT/REVOKE, ни CREATE/ALTER ROLE, ни ALTER DEFAULT PRIVILEGES,
ни CREATE POLICY — только `declaration.ts` + генератор.
