## Что покрыть (`Gate B`: host matrix + tenant-isolation fault injection)

1. **Cookies host-only при нескольких Host.** Сессионная кука, выданная на staff-origin, не должна
   приниматься и не должна отправляться на patient-origin и на арендаторском Host, и наоборот. Ни одного
   `Domain=`-атрибута, который расширял бы куку на поддомены — проверь это утверждением о самом заголовке
   `Set-Cookie`, а не только поведением.
2. **CSRF request-origin seam.** Запрос с `Origin`/`Referer` чужой поверхности обязан отбиваться на
   каждой из поверхностей: `staff`, `patient_default`, `platform_admin`. Проверь и «нет заголовка вовсе».
3. **Unknown Host — fail closed.** Незнакомый Host не должен давать ни сессии, ни платформенного фолбэка.
4. **Cross-org попытка — fail closed.** Принципал одной организации против ресурса другой.
5. **Матрица задаётся в тесте, а не наследуется из окружения процесса.** Ровно тот дефект, который сожрал
   два круга в `B3`: сегодня staff- и patient-origin в vitest совпадают, поэтому тест, полагающийся на
   ambient-окружение, проверяет одну ячейку и молчит про остальные. Смотри, как это сделано в
   `apps/webapp/src/proxy.route.test.ts` после круга 4 (`594f20d3f`) — там есть готовый образец матрицы,
   переиспользуй подход, а не изобретай второй.

## Приёмка — инъекциями, а не зелёным набором

Минимум четыре, каждая обязана краснить:
- снять host-only у куки (добавить `Domain`);
- принять куку чужой поверхности;
- пропустить запрос с чужим `Origin`;
- отдать что-нибудь содержательное на неизвестном Host вместо отказа.
Приведи числа красных до и после по каждой. **Зелёный набор без инъекций доказательством не считается.**
