## Что сломано (замер ведущего, живой отказ полного CI)

`pnpm run ci` на `a304a4e04` падает EXIT=1 на сборке webapp:

```
Error: topic_unsubscribe_secret_unavailable
Error: Failed to collect page data for /api/account/security/recovery/confirm
```

`createTopicUnsubscribeService` (`topicUnsubscribe.ts:70-71`) **бросает прямо при создании**, если секрета
нет. Next при сборке собирает данные страниц и исполняет модульный уровень маршрутов — секрета там нет, и
падает вся сборка. То есть отсутствие переменной окружения ломает не отправку письма, а БИЛД.

## Задание

1. **Секрет должен читаться в момент запроса, а не на сборке.** Отказ обязан случаться там, где секрет
   реально нужен (создание ссылки или проверка маркера), и НЕ должен исполняться при сборке страницы.
2. **Не ослаблять проверку:** короткий или отсутствующий секрет обязан по-прежнему приводить к отказу —
   меняется КОГДА он проверяется, а не проверяется ли. Молчаливая работа с пустым секретом запрещена: ссылка
   без подписи открыла бы отписку кому угодно.
3. **Проверь, нет ли той же беды рядом:** другие места, читающие секреты или обязательные переменные на
   модульном уровне маршрутов. Перечисли найденное; чинить в этом заходе только названный случай (§24.6).
4. **Доказательство:** `pnpm --dir apps/webapp run build` проходит БЕЗ переменной секрета в окружении;
   при этом поведенческий тест показывает, что без секрета создание ссылки и проверка маркера отказывают, а
   с секретом работают. **Инъекция:** убери отказ — тест краснеет.
5. Затронутые тесты, typecheck, lint.
