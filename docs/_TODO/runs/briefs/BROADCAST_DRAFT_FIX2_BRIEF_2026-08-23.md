## Что не так

Строка `broadcast_drafts` арендная (`organization_id` + арендная политика `FOR ALL`), а уникальный ключ —
`broadcast_drafts_doctor_user_id_key UNIQUE (doctor_user_id)`, то есть ОДИН черновик на врача на всю платформу.
Отсюда два живых отказа, оба измерены на DEV:

- строка с `NULL` `organization_id` (её писал прежний код всегда) — `42501` навсегда, и она же невидима
  для `loadDraft`: врач видит пустую форму, набирает заново и снова получает 500;
- врач в двух клиниках: черновик сохранён в клинике A, в клинике B он и не виден, и не сохраняем — навсегда.

`ON CONFLICT DO UPDATE` починить `organization_id` не может: `UPDATE`-гранта на дискриминатор нет и не должно
быть — дискриминатор арендной строки не переписывают.

## Решение (принято ведущим, не изобретай своё)

**Владелец строки — пара «врач + клиника», значит и ключ должен быть парой.**

1. Уникальный ключ → `(doctor_user_id, organization_id)`, `ON CONFLICT` целится в него.
2. `organization_id` → `NOT NULL`. Перед этим — бэкфилл в той же миграции: строке проставляется клиника
   врача, если активное членство ровно одно; если членств ноль или больше одного — строка **удаляется**.
   Черновик рассылки — расходный набросок, а не документ: удалить неразрешимый черновик честнее, чем
   оставить вечно несохраняемую форму. Удаление и его причину напиши комментарием в миграции.
3. Миграция НЕ содержит `GRANT`, `REVOKE`, `CREATE POLICY`, `CREATE ROLE`, `ALTER DEFAULT PRIVILEGES`.
   Права по-прежнему только через `declaration.ts` + генерация (`--all`, `--all --port-context-only`,
   `--all --check` побайтово).

Если после чтения кода увидишь, что это решение ломает что-то, чего я не учёл, — **не делай молча по-своему**:
напиши, что именно ломается, и остановись.

## Доказательство (закрыть слепую зону прошлого круга)

Тест ОБЯЗАН исполнять ветку `ON CONFLICT DO UPDATE`, а не удалять строку перед каждой пробой. Четыре состояния
из таблицы аудита плюс два новых, все на живой DEV-фикстуре, rollback-only:

| состояние до сохранения | ожидание |
|---|---|
| строки нет | записана |
| своя клиника | обновлена (**повторное** сохранение, реальный upsert) |
| `NULL` | после миграции такого состояния не существует; докажи, что бэкфилл его убрал |
| чужая клиника | своя строка создаётся рядом, чужая не тронута и не прочитана |
| врач в двух клиниках: сохранить в A, затем в B | обе строки живут, каждая читается в своей клинике |
| чтение чужого черновика | ноль строк |

Fault injection на каждый независимый класс: снятый бэкфилл, снятый `NOT NULL`, ослабленная арендная политика.
`typecheck`, `lint` и `node --test` по затронутым файлам — зелёные.
