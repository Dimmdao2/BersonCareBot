## Что сломано (замер ведущего, живой отказ)

Приземлена миграция `20260822T190000_the_incoming_recipient_door_opens_for_the_integrator_principal.sql`
(вторая дверь у `app.integrator_read_channel_binding_identity(text,text,text)`). Смысл правки верен и
доказан инъекциями — **менять смысл не надо.** Но `bash deploy/host/migrate-dev.sh --execute` на DEV падает
на reconcile:

```
ERROR:  runtime definer body is not context gated: app.integrator_read_channel_binding_identity(text,text,text)
```

Причина структурная. Проверяющий блок в `generate.mjs` (около строки 1530) требует, чтобы у plpgsql-корня
**первым оператором сразу после `BEGIN`** стоял `PERFORM app.require_accepted_context(` (или
`require_attested_context_for_roles`). Автор вынес пробу класса в отдельный блок с обработчиком
`insufficient_privilege` ПЕРЕД приёмкой контекста — гейт такое тело не принимает.

**Сосед, на которого автор ссылался, устроен иначе, и это ключевая деталь:**
`app.record_reminder_occurrence_finalized_projection` в
`20260822T140000_the_shared_roots_name_the_role_of_their_door.sql` держит `PERFORM
app.require_accepted_context(` ПЕРВЫМ оператором, а ветвление прячет **внутрь списка аргументов**
через `CASE`. Форма соседа — целевая.

   `pnpm test:db-privileges`, тесты интегратора, typecheck, оба `--check` побайтно.
