## Что измерено (ведущий, живой прогон TEST 22.08.2026, голова `c62e066aa`)

Регистрация клиники повторно с той же почтой и тем же паролем:

    POST /api/auth/specialist-signup/start  →  409 {"ok":false,"error":"duplicate_email"}

Так быть не должно. `apps/webapp/src/app/api/auth/specialist-signup/start/route.ts:98-104`: когда
`registerPendingSpecialistVerification` отказывает дублем, маршрут НЕ отбивает, а зовёт
`tryResendRegistrationChallenge` и переотправляет код — 409 отдаётся только если и переотправка отказала.
Замысел верный: неподтверждённая почта + совпавший пароль = вторая отправка того же кода.

**Замысел мёртв по построению.** `pgUserPasswordCredentials.ts:210` ищет кандидата через
`app.email_password_find_login_candidate(text)`, а её тело (живой `pg_proc` на TEST) джойнит
`app.find_platform_user_ids_by_any_confirmed_email(p_email_norm)`, в теле которой дословно:

    WHERE uc.contact_kind = 'email'
      AND uc.confirmed_at IS NOT NULL

У человека, которому нужна переотправка, почта по определению НЕ подтверждена — он же кода и не вводил.
Функция возвращает пусто → `row` пуст → `{ok:false}` → 409. **Ветка переотправки не может сработать
никогда, ровно в том случае, ради которого написана.** Отдельное условие `WHERE email_verified = false`
в вызывающем показывает, что неподтверждённого там ЖДУТ, — то есть противоречие внутри одной пары.

Живая база TEST подтверждает: `user_contacts` держит `klinika.proba.2208@yandex.ru`,
`confirmed = f`, пароль тот же — ответ всё равно 409.

**Цена для живого человека.** Не получил письмо, закрыл вкладку, ошибся в коде трижды — назад дороги нет:
регистрация говорит «аккаунт уже существует», код не приходит, вход по паролю запрещён (почта не
подтверждена), восстановление пароля тоже требует подтверждённой почты. Тупик, из которого достаёт только
администратор руками. Это хвост цутовера почты 21.08 (`20260821T040000`): чтение переехало на
ПОДТВЕРЖДЁННЫЕ контакты, а сценарий неподтверждённого не перенесли.
