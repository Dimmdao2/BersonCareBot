## Находка 1 — отказ по тарифу приезжает пятисоткой

`PUT /api/admin/notification-templates` под глобальным админом (полное тело по схеме маршрута) отвечает
`500`. В журнале TEST:

```
⨯ Error [MechanicWriteClearanceRequiredError]: mechanic write clearance required: branding
   at Object.saveManagedTemplate (…)   { mechanic: 'branding' }
```

Два отдельных вопроса, ответь на оба:

1. **Форма ответа.** Отказ по механике тарифа — это НЕ внутренняя ошибка. В этом же репозитории такой
   отказ уже умеют показывать по-человечески: `entitlementMutationRefusalResponse` в
   `apps/webapp/src/app-layer/guards/requireEntitlement.ts` (см. как им пользуется
   `apps/webapp/src/app/api/doctor/tasks/route.ts`). Приведи маршрут шаблонов к тому же виду — **вторую
   реализацию отказа не заводить** (`AGENTS.md` §5).
2. **Уместность самой проверки.** Здесь сохраняется ПЛАТФОРМЕННЫЙ шаблон (`{ organizationId: null }`),
   а механика `branding` — арендная, клиничная. Проверь по коду и по декларации тарифов, должна ли она
   вообще спрашиваться у глобального админа на платформенной записи. **Если считаешь, что не должна —
   не меняй молча, а напиши это в отчёт отдельной строкой с доказательством**, решение принимает ведущий.

## Находка 2 — личные настройки уведомлений недоступны глобальному админу

`/app/admin/notifications`, кнопки «Включить» и «Восстановить» → `GET /api/doctor/web-push/status` →
`500`. Причина в журнале: `Patient port context requires an organization-scoped patient principal`.

Маршрут задуман общим для персонала и глобального админа (см. его же комментарий: «personal staff/
global-admin PWA boundary runs under app_patient identity-self context»). У глобального админа
организации нет, поэтому org-scoped patient principal не собирается. Почини так, чтобы **личное**
(свои подписки, свой тумблер) открывалось дверью «идентичность-себя», а не арендным принципалом —
в репозитории это уже сделано для другого экрана админа, ищи `runWithStaffSecuritySelfPrincipal` и
повтори форму. Стена не ослабляется: админ видит ТОЛЬКО своё.
