### `FC-1` (блокер). Чтение стенованной таблицы без привязки к принципалу

`deploy/postgres/privileges/definer-tenant-predicate.test.mjs:142`:

```
app.read_integrator_clinic_delivery_credential(text,uuid) -> public.system_settings:
чтение стенованной таблицы не привязано к принципалу
```

`C4` расширил тело корня чтением шаблона `clinic_transactional_mail_template` из `public.system_settings`
(видно прямо в `BCB-MIGRATION-VERIFY` миграции `20260823T010000_mail_profile_reaches_auth_delivery.sql`).
`SECURITY DEFINER` обходит RLS, поэтому такое чтение обязано быть либо сужено предикатом принципала в теле,
либо помечено `crossesTenantWall: { why: … }` с настоящей причиной.

**Это решение по безопасности, а не форматирование.** Реши по факту: может ли этот корень при чужом
`organization_id` вернуть шаблон другой клиники. Ответ доказывай запросом к живой DEV (rollback-only), а не
рассуждением: принят чужой принципал → что возвращает корень. Если течёт — сужай предикатом в теле
(миграцией, `GRANT`/`REVOKE`/`CREATE POLICY` в ней быть не должно). Если по построению не течёт — пометка
`crossesTenantWall` с причиной, которую можно перепроверить.

в тесте устарел и правится он, но правка обязана сопровождаться доказательством вызова. Если где-то остался
