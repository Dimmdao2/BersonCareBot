# Рантайм-роль пишет в таблицу, на которую у неё нет права: перепись прямых записей

**Источник оракула:** `docs/_TODO/UI_FINISH_AND_REAUDIT_2026-07-22/WORK_ORDER.md` — «узкая роль интегратора не мешает доставке»

Канон — `AGENTS.md` (`grep -n "^## \|^### " AGENTS.md`), §1, §5, §10a, §24.

## Живой замер

23.08.2026, TEST, голова `a3c5a4f40`. Врач отправляет рассылку из своего кабинета
(`/app/doctor/communications?tab=broadcasts`, аудитория «С будущей записью», канал Email,
6 получателей, шаг подтверждения показан правильно). На кнопке «Отправить 6 получателям» экран
отвечает **«Ошибка при отправке рассылки. Попробуйте ещё раз.»**, `500` на RSC-запросе.

Журнал вебаппа и Postgres в ту же секунду:

```
42501 ERROR: permission denied for table broadcast_audit
STATEMENT: insert into "broadcast_audit" (…) values (…) returning …
роль: bcb_test_webapp_staff
```

Права на TEST: у `app_staff` на `public.broadcast_audit` есть только `SELECT`, `INSERT` нет.
Запись идёт **прямым drizzle-insert**, не через `SECURITY DEFINER`-корень, поэтому владелец шва тут
ни при чём. **Ни одна рассылка врача сегодня не отправляется вообще.**

## Что сделать

1. **Главное — перепись, а не одна заплатка.** Найди ВСЕ прямые (не через definer-корень) записи
   рантайм-ролей вебаппа в таблицы и сопоставь с реально выданными правами. Ответ по каждой:
   роль, таблица, операция, право есть или нет. Метод назови так, чтобы я его повторил.
   Смотри на реальные права живой базы, а не только на декларацию — расхождение между ними и есть
   предмет работы.
2. **Почини найденное.** Начни с `broadcast_audit` (и `broadcast_audit_recipients`, если у неё то же
   самое). Право — минимальное: `INSERT` там, где вставляют; не выдавай `UPDATE`/`DELETE` «заодно».
3. **Только через `deploy/postgres/privileges/declaration.ts` и генерацию**
   (`--all`, `--all --port-context-only`, `--all --check` побайтово). В миграциях
   `GRANT`/`REVOKE`/`CREATE ROLE`/`ALTER DEFAULT PRIVILEGES`/`CREATE POLICY` **запрещены**.
4. **Арендную стену не ослаблять.** Если у таблицы есть RLS-политика, право на запись не должно
   открывать чужую организацию — проверь это, а не предположи.

## Доказательство

- Тест, краснеющий при отзыве нового права.
- Отдельно назови, **почему это не поймали раньше**: есть ли гейт, который обязан был показать

- `--all --check` и `--all --port-context-only --check` — побайтово чисто; `typecheck`, `lint`,
  затронутые тесты — зелёные.
