Repo canon: `AGENTS.md` (`grep -n "^## \|^### " AGENTS.md`, затем свои разделы).

Источник оракула: `docs/_TODO/THERAPYSTO_PATIENT_BRANDING_INITIATIVE/IMPLEMENTATION_PLAN.md`, пункт `C5`,
дословно: «не включается, пока не прошла успешная ЖИВАЯ отправка — не по галочке «настроил», а по факту доставки».

Соседняя формулировка того же решения, §1.2h: «Опции для тех, кто дорос (обязанностью не являются): своя почта
(свой SMTP плюс DNS-подписи на её стороне) и свой бот. Включаются только после успешной живой отправки — гейт
(б) пункта `C5`.» И там же: «На пути по умолчанию не блокируется ничего».

## Объём — ровно две вещи, и только вторая делается сейчас

Гейт `C5` стоит в двух местах: (а) свой ДОМЕН клиники — отложен вместе с `B8`, в этот проход НЕ берём;
(б) свой КАНАЛ клиники (своя почта или свой бот) — это и есть твоя работа.

1. Свой канал клиники переходит в состояние «включён» только после успешной ЖИВОЙ отправки через него.
   Сохранение настроек, галочка «настроил» и валидность формы состояния «включён» не дают.
2. Проверочная отправка идёт по существующему шву доставки; второго отправителя и второй очереди не заводить.
   Адресат проверки — сотрудник клиники, а не пациент.
3. До успешной проверки продолжает работать путь по умолчанию (наш бот / наша почта от имени клиники) —
   ничего не блокируется и никто не остаётся без сообщений. Это прямая буква §1.2h, проверь тестом.
4. Поломка канала ПОСЛЕ включения адрес клиники не гасит (§1.2h): сигналим, но не выключаем адрес.
   Если сегодня в коде иначе — скажи в отчёте, но менять поведение адреса не надо.
5. Состояние гейта видно тому, кто настраивает: «ждём проверочной отправки» / «канал включён» / «проверка не
   прошла, причина». Отдельного экрана не строить — использовать существующий раздел настроек каналов.

## Границы (решения владельца, не инженерные развилки)

- Ничего не слать реальным адресатам: на DEV действует шов перенаправления, оставь его в силе.
- `telegram_mode=long_polling` не ставить НИКОГДА — в настройках лежит настоящий прод-токен бота.
- Не трогать `app.read_integrator_clinic_delivery_credential` и миграции `20260823T030000…` / `20260823T043206…`;
  обе роли в одном списке не разрешать.
- Не трогать `app.enqueue_outbound_message` и `senderScope` — по ним прямо сейчас идёт соседний круг.
- Миграции никогда не содержат `GRANT`/`REVOKE`/`CREATE ROLE`/`ALTER DEFAULT PRIVILEGES`/`CREATE POLICY`.
- Прод не трогать, `--execute` на DEV не запускать, в `feat/doctor-ui-rebuild` не вливать.
- Своя находка вне плана — вопрос владельцу, а не новая работа.
