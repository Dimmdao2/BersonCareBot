## Blind kill-set (written before inspecting test files)

1. Replace the canonical result selected by an existing patient session with a contact-derived user; a booking/payment must not be created for that other identity.
2. Treat an unverified or mismatching submitted email as proof; no booking/payment may be created and no alternate identity may be authorized.
3. Remove/ignore the SMS proof-to-canonical-user resolution; confirmed SMS must still produce the canonical `platformUserId` passed to the unchanged payment door.
4. Fail to retain the normal patient session after SMS or email confirmation; the canonical owner path must still have its usual patient session.
5. Remove the ownership comparison in `/api/booking/payment-status`; a session for user A must not receive user B's booking.
6. Restore a phone-based public payment-status endpoint/method, phone query or return URL, or a second authorization path; each must remain absent.
7. Add a provider, migration/table, duplicate OTP mechanism, or new payment identity; each must remain absent.
