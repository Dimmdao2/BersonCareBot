## A. 17.F — «галка ничего не закрывает»

- **K1.** `card_is_published = false` → дверь визитки перестаёт отдавать идентификатор ФОТОГРАФИИ
  клиники → публичный `/{clinic}/media/{uuid}` на эту фотографию отказывает, хотя клиника её сама
  опубликовала. Молчаливо: клиника не узнаёт, что её картинки закрылись.
- **K2.** То же для ФАЙЛА МАТЕРИАЛА (медиа, на которое ссылается описание): при выключенной галке
  выпадает из набора двери → 404 анониму.
- **K3.** То же для АВАТАРА СПЕЦИАЛИСТА: галка клиники выключена → аватар не отдаётся.
- **K4.** СТРАНИЦА СПЕЦИАЛИСТА закрывается галкой клиники: специалист активен и опубликован, но
  `/{clinic}/...specialist...` даёт отказ, потому что клиника выключила свою визитку.
- **K5.** Обратная поломка: галка перестала влиять на ЕДИНСТВЕННОЕ, за что отвечает, — вид
  корневого экрана. При `card_is_published = false` корень снова рисует расширенную визитку вместо
  вырожденного входа в кабинет.
- **K6.** Дверь перестала отдавать сам признак (`cardIsPublished`) либо отдаёт его инвертированным
  → корневой экран выбирает вид наугад.

## B. 17.Q — галка «визитки специалистов в модуле записи»

- **K7.** Свежий специалист (`is_active = true`, `card_is_published = false`) по `?specialist=<id>`
  НЕ резолвится → посетитель читает «больше не принимает записи», неправду о человеке, который
  записи принимает; клиника об этом не узнаёт. (Находка 1 аудита 2c.)
- **K8.** Специалист ЧУЖОЙ организации по `?specialist=<id>` резолвится → межарендаторская утечка
  имени/описания.
- **K9.** Четыре отказа (`несуществующий` / `чужой` / `неактивный` / `не в этом филиале`) различимы
  по форме ответа → аноним перечисляет клиники и людей (§3.3).
- **K10.** Галка организации ВЫКЛЮЧЕНА, а `cardIsReadable = true` → модуль записи предлагает
  открыть карточку, показ которой клиника выключила («нет галочки — не показываем»).
- **K11.** Галка ВКЛЮЧЕНА, человек сам не опубликован → `cardIsReadable = true` → кнопка ведёт в
  404: интерфейс молча врёт.
- **K12.** Настройка читается не для той организации (перепутан `organization_id`) либо не
  откатывается на глобальную строку `organization_id IS NULL` → клиника A управляет показом у B.
- **K13.** ДЕФОЛТ: у существующей организации строки настройки нет, и поведение молча изменилось
  (описание перестало показываться). Отсутствие строки обязано означать ВКЛЮЧЕНО.
- **K14.** Галка выключает не описание, а самого специалиста: выключили — и он исчез из списка
  записи либо запись к нему перестала работать. Владелец: «человек видит только список
  специалистов. И всё.»
