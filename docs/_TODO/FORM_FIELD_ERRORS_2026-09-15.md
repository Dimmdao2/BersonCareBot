## Что уже сделано (ветка `wt/form-field-errors`, коммит `cb5c56317`)

Корень оказался не в формах, а в проводе. Маршрут писал точную причину в поле `message` ответа,
`apiJson` доносил её до клиента внутри `ApiRequestError` — а `safeUserMessage` её выбрасывал,
потому что проверял КЛАСС (`UserFacingError`), а не пометку. Поэтому общую заглушку вместо
названной причины показывала КАЖДАЯ форма на `apiJson`, а не только настройки бота.

- [x] `ApiRequestError` несёт `userMessage` — только продуктовую копию маршрута, никогда машинный код.
- [x] `userFacingMessage` смотрит на поле `userMessage`, а не на класс. Инвариант «наружу только
      сознательно написанный человеку текст» сохранён.
- [x] `DoctorField` получил слот `error`: красная подсказка под полем, `role="alert"`.
- [x] Настройки бота (`OrgBrandingSection`): подписи у полей, объяснение у галки пересылки, отказ
      печатается у того поля, которое его вызвало, поле краснеет по `aria-invalid`.
- [x] Тексты отказов маршрута называют, что сделать, и отбивают саму частую ошибку — токен бота,
      вставленный в поле «id чата».

## Замер: возможен ли универсальный гейт (15.09.2026)

| Что | Сколько |
|---|---|
| `<Input` в `apps/webapp/src` | 386 |
| из них внутри `DoctorField` | 107 |
| файлов с `aria-invalid` (вне `components/ui`) | 18 |
| вхождений `text-destructive` в `.tsx` | 309 в 171 файле |

**Гейт «у каждого поля, где возможна ошибка ввода, есть подсветка и подсказка» статически
недоказуем:** нельзя грепом узнать, у какого из 386 полей ошибка ввода «вообще возможна». Такой
гейт пришлось бы кормить списком полей руками — это ровно та машинерия, которую владелец запретил.

**Обратное утверждение доказуемо и дёшево:** механизм показа ошибки поля должен быть ОДИН.
То есть `aria-invalid` на контроле и красная подсказка об ошибке рядом с контролом законны только
изнутри общего компонента поля. Это не доказывает, что у каждого поля есть ошибка, — зато делает
невозможным РАЗНОЕ поведение у разных полей, а именно это владелец и назвал требованием
(«должно вести себя одинаково»). Побочно это и есть обещанная чистка: 279 полей мимо общего
компонента сводятся к нему.

## Этапы

- [ ] **Э1. Единый механизм.** Один компонент поля (`DoctorField` и его пациентский аналог, если он
      отдельный) — единственное место, где рождается `aria-invalid` контрола и красная подсказка под
      ним. API: `error` + подпись + hint. Ad-hoc разметку ошибок в формах убрать, переведя на него.
- [ ] **Э2. Единственный разрешённый гейт.** Скрипт в `pnpm run lint` (рядом с
      `check-safe-error-transport.mjs`): `aria-invalid` и разметка ошибки поля вне общего компонента —
      отказ. Обязателен `--self-test`, как у соседних гейтов: гейт, который не краснеет на
      собственной поломке, хуже отсутствующего. Никаких тестов «на каждое поле с ожидаемым текстом
      подсказки» — владелец запретил дословно.
- [ ] **Э3. Живая приёмка.** Настройки бота на TEST: вставить в «id чата» заведомо неверное значение
      → поле краснеет, под ним причина, тоста-заглушки нет.
