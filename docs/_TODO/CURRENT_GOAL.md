# ТЕКУЩАЯ ЦЕЛЬ — читать первым, обновлять по факту

Файл живёт постоянно. Это не план и не отчёт: здесь одна цель и очередь до неё. Каждый агент,
который берётся за работу в этом репозитории, читает его ДО того, как что-то делать, и обновляет
сразу после того, как что-то закрыл. Пусто здесь не бывает — если цель достигнута, её меняет владелец.

## Цель (владелец, 21–22.08.2026)

**Полностью работающая система на TEST и закрытый трек D.** Дословно: «утром уже я вижу, когда
просыпаюсь, работающий домен тест и законченный трек Д».

Живая проверка владельцем **не блокирует работу** — она блокирует только закрытие этапа в документах
(решение 22.08). Этап, у которого осталась только живая проверка, доводится по коду до конца и
приземляется, а его галочка остаётся `[ ]` с пометкой «код готов, ждёт живой проверки».

## Очередь до цели — в этом порядке

1. **Вход и регистрация на TEST работают руками владельца.** Вход по паролю — работает (Б1 закрыт).
   Вход по коду из почты — работает на DEV, на TEST поедет с ближайшей выкаткой. Регистрация клиники
   (Б2) — `start` отвечает 200, отказ переехал на подтверждение почты.
2. **Зелёный reconcile на DEV** — без него не выкатывается TEST. Проверяется `bash
   deploy/host/migrate-dev.sh --preflight`, и только назначенной веткой `--execute`.
3. **Полный CI → push → выкатка TEST → живая проверка** входа по коду и регистрации уже на TEST.
4. **Трек D:** D17 (шесть писателей канона на именованные корни, затем узкая роль) → D19 (его пункт 4
   зависит от D17) → D15b/7a (шаги 1–2 сделаны, дальше по схеме) → D30 (живой прогон Ш3) →
   D25 и D15b/2/6 — живые проверки.

## Правила ведения, которые уже стоили нам времени

- **Ход не заканчивается ожиданием.** Ни ожиданием CI, ни ожиданием воркера, ни будильником. Ход
  заканчивается либо запущенной работой, либо названным блокером. 22.08 сессия простояла семь часов
  ровно потому, что ход завершился ожиданием, а таймер не сработал.
- **Три ветки параллельно, четвёртый слот свободен** под коррекции и приёмку.
- **`--execute` на DEV — только у одной назначенной ветки за раз**, иначе они сводят базу под себя
  по очереди и затирают друг друга.
- **Приёмка — своей проверкой против реальности**, не по отчёту воркера. Отчёт «зелено» доказательством
  не является.
