# Резервный канал связи — чтобы предупреждение о взломе дошло не только туда, куда ушёл код

**Повод.** 14.09, разбирая письмо о входе с нового устройства, владелец назвал сценарий, который
ничем не закрывается: взломщик увёл почтовый ящик, вошёл, получил письмо о новом устройстве раньше
владельца, сам нажал «закрыть сеансы и сменить пароль» и задал новый пароль по коду, пришедшему в
тот же угнанный ящик. Владелец при этом не узнаёт вообще ничего. Дословно: «если мы отправляем это
только ему, то тот человек даже не узнает, что у него уже поменяли пароль, отовсюду вышли».

**Решение владельца 14.09:** «это отдельная инициатива по созданию второго подтверждённого канала,
именно как резервного… там надо будет сделать какое-то регулярное напоминание людям о том, что у них
нету второго резервного канала, и просьбы его создать… составить какой-то план работ».

## Что требует мир — не выдумано, найдено 14.09

| Норма | Что требует |
|---|---|
| NIST SP 800-63B-4 §4.6 | уведомления о событиях безопасности уходят **во ВСЕ** адреса уведомлений; поддерживать нужно **минимум два** адреса на человека; людей следует подталкивать заводить несколько |
| NIST SP 800-63B-4 §4.6, там же | если единственный второй адрес — тот, **куда ушёл код восстановления**, уведомление обязано уйти ещё одним путём (вплоть до бумажной почты). То есть канал, получивший код, НЕ считается предупреждённым |
| NIST SP 800-63B-4 §4.2.1.2 | код уходит на адрес, **выбранный человеком из заранее подтверждённых**; новый адрес становится таким только после подтверждения кодом; адресов должно быть минимум два |
| NIST SP 800-63B-4 §4.2.3 | любое восстановление доступа **обязано** порождать уведомление |
| OWASP (смена адреса почты) | письмо уходит и на **старый** адрес, с возможностью остановить смену |

Источник: `nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.800-63B-4.pdf` (июль 2025),
`cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html`,
`owasp.org/www-community/pages/controls/Changing_Registered_Email_Address_For_An_Account`.

## Что у нас уже есть — замерено, а не предположено

Замеры 14.09 на базе TEST (она несёт перенесённые боевые данные). Команды приведены, чтобы цифру
можно было перепроверить:

```sql
SELECT contact_kind, count(*), count(confirmed_at) FROM public.user_contacts GROUP BY 1;
SELECT c, count(*) FROM (SELECT platform_user_id,
  count(*) FILTER (WHERE confirmed_at IS NOT NULL) AS c FROM public.user_contacts GROUP BY 1) t
 GROUP BY 1 ORDER BY 1;
SELECT channel_code, count(*), count(*) FILTER (WHERE bot_blocked_at IS NULL)
  FROM public.user_channel_bindings GROUP BY 1;
SELECT count(DISTINCT b.user_id) FROM public.user_channel_bindings b
  JOIN public.user_contacts c ON c.platform_user_id = b.user_id
   AND c.contact_kind='email' AND c.confirmed_at IS NOT NULL
 WHERE b.bot_blocked_at IS NULL;
```

| Что | Сколько |
|---|---|
| телефонов / из них подтверждённых | 208 / 207 |
| адресов почты / из них подтверждённых | 132 / **39** |
| людей с ОДНИМ подтверждённым контактом | **190** |
| людей с двумя | 28 |
| людей без единого | 2 |
| связок с ботом: телеграм / из них живых | 118 / 103 |
| связок с ботом: MAX / из них живых | 27 / 24 |
| людей, у кого ОДНОВРЕМЕННО подтверждённая почта и живая связка с ботом | **15** |

**Вывод из цифр, и он меняет объём работы.** Второй канал не надо строить с нуля: у 127 человек уже
есть живая связка с ботом, и бот умеет доставлять. Не хватает трёх вещей: (1) связка с ботом нигде
не считается каналом уведомлений о безопасности, (2) подтверждённой почты нет у большинства — 39 из
208, (3) человеку никто никогда не предлагает завести второй канал. Телефон подтверждён почти у
всех, но **каналом не является**: доставки по SMS у нас нет, подтверждение телефона пришло из входа
через мессенджер.

## Развилки владельца — ответить одним присестом ДО начала работ

1. **Считать ли живую связку с ботом подтверждённым каналом безопасности?**
   Рекомендация: **да**, если человек завёл её сам при входе — это доказанное владение каналом, и
   это мгновенно даёт второй канал 127 людям вместо нуля.
2. **Кому второй канал обязателен?**
   Рекомендация: **обязателен персоналу** (врач, админ клиники, админ платформы) — у них доступ к
   чужим данным; **добровольный пациенту**. Безопасный вариант по умолчанию, если решения не будет:
   всем добровольный.
3. **Как напоминать? Ритм не выдуман — взят у тех, кто это уже делает** (таблица ниже).
   Рекомендация: предложение показывается **после успешного входа**, а не посреди работы; кнопка
   «потом» откладывает на **14 дней**; пациент может откладывать сколько угодно, **персоналу — три
   раза, после чего добавление обязательно**; плюс **раз в год** — напоминание пересмотреть список
   своих каналов. Каждая цифра здесь чужая, не моя:

   | Кто | Что делает | Источник |
   |---|---|---|
   | Microsoft Entra, «кампания регистрации» | предложение показывается **после успешного входа**; «отложить» по умолчанию на **1 день**, настраивается в диапазоне **0-14 дней**; при включённом ограничении отложить можно **три раза**, дальше регистрация обязательна | `learn.microsoft.com/entra/identity/authentication/how-to-mfa-registration-campaign` |
   | NIST SP 800-63B-4 §4.2.1.3 | «CSPs **SHOULD send a reminder annually** to subscribers to review their list of recovery contacts» — раз в год пересмотреть список | NIST SP 800-63B-4 |
   | Google | предлагает добавить резервные способы при входе и в разделе проверки безопасности; **конкретного периода в документации нет** — не выдаю за норму | `support.google.com/accounts/answer/183723` |
4. **Можно ли не пускать в кабинет, пока не добавлен?** Рекомендация: **нет**, никогда для пациента
   и врача. Допустимо обсуждать только для админа платформы, и то отдельным решением.
5. **Считать ли подтверждённый телефон каналом?** Рекомендация: **нет**, пока нет доставки SMS.
   Иначе в списке каналов будет мёртвая строка, на которую никто не получит предупреждение.

## Этапы

- [ ] **Э1. Понятие «канал уведомлений».** Свести почту, телеграм и MAX в одно понятие со
      статусом подтверждения, отдельно от «контактов для связи с врачом». Показать, какие каналы
      живые: у бота есть признак «человек заблокировал бота» — заблокированный канал предупреждением
      не является. Без этого этапа остальные висят в воздухе.
- [ ] **Э2. Экран «Безопасность»: список каналов.** Человек видит свои каналы, добавляет второй,
      подтверждает кодом, удаляет лишний. Запрет удалить последний. Машинных слов на экране быть не
      должно.
- [ ] **Э3. События безопасности уходят ВО ВСЕ подтверждённые каналы.** Сейчас письмо о входе с
      нового устройства уходит только на почту. Список событий: вход с нового устройства, нажатие
      кнопки защиты, смена пароля, смена или удаление канала. Требование NIST §4.6.
- [ ] **Э4. Код восстановления — в один канал, уведомление во все остальные.** Человек выбирает,
      куда прислать код, из СВОИХ подтверждённых каналов; факт отправки и итог уходят во все
      прочие. Это то самое разведение, которого сейчас нет.
- [ ] **Э5. Напоминание тем, у кого канал один.** Ритм и вид — по развилке 3 (после входа, «потом»
      на 14 дней, персоналу три откладывания, раз в год пересмотр списка). Напоминание само
      исчезает, как только второй канал подтверждён, и не показывается тому, у кого он уже есть.
- [ ] **Э6. Видеть покрытие.** На экране здоровья системы — доля людей с одним каналом, чтобы
      знать, работает ли напоминание, а не верить в него.
- [ ] **Э7 (только если владелец скажет по развилке 2).** Требование второго канала для персонала.

## Что в эту работу НЕ входит

- Кнопка блокировки учётной записи — отдельный разговор, ведётся в плане про журнал входов.
- Уведомление на старый адрес при смене почты — уже стоит отдельным пунктом там же.
- Доставка SMS: заводить канал, которого у нас нет, эта работа не будет.
- Второй фактор при входе (TOTP, passkey) — другая тема; резервный канал это про ДОСТУЧАТЬСЯ до
  человека, а не про то, как он входит.

## Оценка

Э1-Э3 — основная часть: одно понятие, один экран, одна рассылка. Э4 короткий, но трогает
восстановление пароля, поэтому идёт после того, как починка смены пароля приземлится и проживёт
день. Э5-Э6 небольшие. Без развилок 1 и 3 начинать нельзя: от них зависит и объём Э1, и весь Э5.
