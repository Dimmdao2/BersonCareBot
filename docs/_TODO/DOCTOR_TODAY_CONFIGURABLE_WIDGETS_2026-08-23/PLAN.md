# Настраиваемые виджеты дашборда врача «Сегодня»

**Статус:** запланировано
**Дата решения владельца:** 2026-08-23
**Taskdb:** `#1093`
**Экран:** `/app/doctor`

## Результат для врача

Врач сам выбирает, какие блоки видеть на странице «Сегодня», в каких колонках и в каком порядке. Настройка
сохраняется для конкретного врача в конкретной клинике и восстанавливается после повторного входа с другого
устройства.

## Зафиксированное продуктовое решение

- [ ] **W1.** Справа в шапке страницы «Сегодня» есть кнопка с шестерёнкой и всплывающей подсказкой
      «Настроить дашборд «Сегодня»».
- [ ] **W2.** Кнопка открывает модалку «Выбрать блоки».
- [ ] **W3.** В модалке доступные блоки показаны в две колонки: включённые находятся сверху, выключенные — снизу,
      между группами проходит разделительная черта.
- [ ] **W4.** Перетаскивание блока внутри группы меняет его порядок; перенос между колонками меняет колонку;
      перенос через разделительную черту включает или выключает блок.
- [ ] **W5.** На мобильном две колонки идут последовательно: сначала блоки левой колонки, затем блоки правой. Этот же
      порядок используется и в модалке настройки.
- [ ] **W6.** Настройка хранится отдельно для каждого врача и клиники; изменение одного врача не меняет экран других
      врачей и общую конфигурацию клиники.
- [ ] **W7.** Блок «Задачи» возвращается в каталог доступных виджетов, но для профиля без сохранённой раскладки
      остаётся выключенным. KPI «Задачи» является отдельным элементом текущей KPI-строки и этим решением не
      удаляется.
- [ ] **W8.** После сохранения и перезагрузки страницы сохраняются состав блоков, их колонка и порядок.

## Что уже есть в коде

- `/app/doctor` уже состоит из двух колонок: слева KPI и список клиентов, справа мини-календарь.
- Блок списка задач ранее был отделён от KPI и может быть возвращён как самостоятельный виджет.
- `DoctorPageHeader` уже имеет правый слот; для шестерёнки не нужен второй вариант шапки.
- В проекте уже используется `@dnd-kit` с pointer- и keyboard-sensors; новый drag-and-drop пакет не нужен.
- `doctor_today_preferences` хранится на уровне клиники (`per_org`) и управляет общим режимом списка клиентов.
  Личную раскладку врача в этот ключ помещать нельзя.
- Универсального хранилища личной раскладки врача в текущей схеме нет.

## Модель раскладки

Для каждого доступного блока реестр задаёт стабильный код и компонент. Сохранённая раскладка содержит только
пользовательский выбор:

```ts
type DoctorTodayWidgetPlacement = {
  widgetCode: DoctorTodayWidgetCode;
  column: 'left' | 'right';
  order: number;
  enabled: boolean;
};
```

Первая версия реестра:

1. KPI-строка;
2. список «На сопровождении» / «Недавние с визитами»;
3. мини-календарь и записи текущего дня;
4. список задач.

Сервер нормализует раскладку: удаляет неизвестные и повторяющиеся коды, добавляет новые виджеты по их дефолтному
положению и выдаёт плотный порядок отдельно для каждой колонки и группы. Благодаря этому новый виджет можно
добавить в реестр без поломки ранее сохранённых настроек.

## Хранение и границы доступа

Использовать отдельную typed per-user запись раскладки, привязанную одновременно к `organization_id`,
`platform_user_id` и коду дашборда `today`. Существующий клинический `doctor_today_preferences` остаётся источником
общей настройки содержимого виджета со списком клиентов, а не личной раскладки.

- читать и менять раскладку может только текущий staff-пользователь для самого себя и текущей организации;
- сервер проверяет актуальное членство и доступ к doctor workspace;
- клиент не передаёт произвольный `platform_user_id` или `organization_id`;
- отсутствие записи означает дефолтную текущую раскладку: KPI и список клиентов слева, календарь справа, список
  задач выключен;
- сохранение выполняется одной атомарной операцией после кнопки «Сохранить»; «Отмена» не меняет раскладку.

## Границы работы

- Содержимое существующих KPI, списка клиентов, календаря и задач не перерабатывается.
- Размер виджетов пользователем не настраивается: каждый блок занимает ширину своей колонки.
- Отдельный мобильный порядок не хранится; mobile детерминированно использует левую колонку, затем правую.
- Настройка не становится organization-wide feature toggle и не заменяет entitlement-проверки блоков.

## Критерий готовности

Врач открывает «Выбрать блоки», перетаскиванием формирует две группы и две колонки, сохраняет их и после reload
видит тот же персональный дашборд. Другой врач видит собственную раскладку. Пользователь без сохранённой настройки
получает текущий экран без отдельного списка задач, но может включить его из каталога виджетов.
