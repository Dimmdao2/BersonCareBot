# Уборка по сроку хранения не работала ни на одной из шести таблиц

Найдено 18.08, когда охрана строк стала считаться раз на запрос: удаление, которое раньше молча
не находило строк и рапортовало успех, начало громко отказывать. Ошибка — симптом; болезнь в том,
что уборка не работала **никогда**.

## Механика

Таблица стоит под запертым арендаторским дескриптором, поэтому генератор выдаёт ей стену
`rev10_saas_org_dormant_p0_8_3` вместо обычной деловой политики. Стена требует
`CURRENT_USER = 'app_staff'` И совпадения организации. Роли обслуживания при этом выдано право
на удаление — но пройти стену она не может: у фоновой уборки организации нет и быть не должно,
она чистит записи всех клиник разом.

Итог: право есть, проход закрыт, удаление затрагивает ноль строк, вызывающий видит успех.

## Закрыто

- [x] `operator_health_failure_archive` — уборка переведена на именованный корень
      `app.prune_operator_health_failure_archive(integer)` (миграция 0029, выкачено на TEST 18.08).
      Ни одна стена и ни одно право при этом не менялись: та же схема уже работает на соседней
      уборке ошибок вебхуков. Мёртвое право роли обслуживания снято.

## Осталось — по каждой таблице нужно решение владельца

Все с недельным расписанием, поэтому ещё не всплыли. Данные копятся без ограничения.

- [ ] `media_hls_proxy_error_events` — ошибки прокси видео
- [ ] `product_analytics_events_recent` — события продуктовой аналитики
- [ ] `product_analytics_user_hourly` — почасовая аналитика по пользователям
- [ ] `product_push_notifications` — история пуш-уведомлений
- [ ] `media_upload_sessions` — сессии загрузки файлов (там ещё и UPDATE, не только DELETE)

**Развилка, одна на все пять.** Либо каждой таблице делается именованный корень, как уже сделано
для архива сбоев — не трогает ни стен, ни прав, но это пять функций; либо роль обслуживания
добавляется в запертый дескриптор — одна правка, но это **правка арендаторской стены**, а её
трогать без прямого решения нельзя.

Рекомендация: именованные корни. Дороже на пять функций, зато стена остаётся неприкосновенной,
и каждая уборка получает свой узкий гейт вместо расширения общего доступа.

## Как это вообще стало видно

Раньше проверка контекста была построчной: запрос, не нашедший строк, её не вычислял вовсе.
Теперь она вычисляется один раз на запрос — и отказ виден. Это же свойство сегодня вскрыло
и поломку напоминаний пациентам. Побочный эффект оптимизации оказался ценнее самой оптимизации.
