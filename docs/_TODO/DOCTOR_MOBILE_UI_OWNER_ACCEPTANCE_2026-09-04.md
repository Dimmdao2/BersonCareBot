# Doctor mobile UI — owner acceptance checklist (2026-09-04)

**Ветка:** `feat/doctor-ui-rebuild`  
**Authority:** последовательные указания владельца в live-review 2026-09-04.  
**Статус:** active, требования продолжают дополняться владельцем.

Этот документ — единый чек-лист текущего прохода. В каждом пункте записано только последнее решение владельца:
несовместимые промежуточные варианты не сохраняются. Новая более поздняя коррекция владельца переписывает
соответствующий пункт здесь, а не добавляется рядом вторым вариантом.

`[ ]` — не принято; `[x]` — реализовано и доказано подходящей проверкой; визуальные требования закрываются только
живой проверкой mobile UI, а не тестами текста/классов. Общие компоненты расширяются вместо создания локальных
копий. Presentation-правки не покрываются новыми UI-тестами.

## K. Деньги, абонементы и оплата записи — отдельный рискованный workstream

Этот раздел не смешивается с presentation-проходом. Реализация запускается через orchestration port отдельным
сильным worker после трассировки существующих contracts; деньги, entitlement и отправка платёжных ссылок требуют
независимого аудита до landing.

### K1. Цена и условия оплаты в записи

- [ ] `PAY-APPT-01` В форме создания записи врачом после услуги и длительности показана стоимость; исходное
      значение берётся из выбранной услуги и сохраняется снимком в самой записи.
- [ ] `PAY-APPT-02` Врач может изменить длительность и стоимость независимо для конкретной записи. Смена услуги
      подставляет цену новой услуги; уже сохранённый ручной снимок цены не меняется самопроизвольно.
- [ ] `PAY-APPT-03` В форме создания и редактирования врач видит условие оплаты: без предоплаты, процент
      предоплаты либо полная предоплата. Исходное значение берётся из политики услуги/клиники, но врач может
      переопределить его для конкретной записи.
- [ ] `PAY-APPT-04` Пациент при самостоятельной записи не может менять стоимость, длительность по финансовому
      расчёту или условие предоплаты; он видит зафиксированные клиникой значения.
- [ ] `PAY-APPT-05` Ссылка или QR-код для оплаты не создаются внутри формы врача: форма сначала сохраняет запись,
      а выставление счёта выполняется из деталей уже созданной записи.
- [ ] `PAY-APPT-06` Детали записи показывают общую стоимость, требуемую предоплату в рублях и процентах,
      фактически оплаченную сумму, текущий платёжный статус и срок оплаты. Из деталей врач может создать/повторно
      получить ссылку и QR-код на оплату.

### K2. Ожидание и завершение предоплаты

- [ ] `PAY-APPT-07` Если для записи требуется предоплата, и пациентская, и созданная врачом запись появляются в
      календаре со статусом `Ожидает оплаты`; слот на это время временно занят.
- [ ] `PAY-APPT-08` В настройках записи врача/клиники задаётся срок ожидания предоплаты. Для новой клиники значение

- [ ] `PAY-APPT-09` После самостоятельной записи пациент сразу получает явное действие перехода к оплате; ссылка

- [ ] `PAY-APPT-11` Если предоплата не поступила до дедлайна, бронь автоматически освобождается, а запись получает

      занимать слот.
- [ ] `PAY-APPT-12` Изменение услуги, стоимости или условия предоплаты до оплаты корректно обновляет снимок и
