# Слой прав БД — привести в «как надо»

**От:** владелец, 2026-08-07 — «НАДО запустить глобальную переделку этой помойки в ТАК КАК НАДО»
**Статус:** ждёт решений владельца по 4 развилкам (раздел «Развилки»), работа не начата
**Смежное:** `../DB_ACCESS_CHOKEPOINT_INITIATIVE/` — про ОДИН перехватываемый ствол *соединений*
(пулы, `SET LOCAL`, принципал). Здесь — про то, **кто владеет правами** на объекты. Не дублировать.

## Что произошло и почему это не заплатка

2026-08-07 в логах TEST нашлись 3 дефекта, при разборе стало 10 (7 читателей `system_settings`
+ 3 из журнала). Все — один класс: **код обращается к объекту, на который у его роли нет прав.**
Ни компиляция, ни типы, ни тесты (на моках), ни деплой этого не ловят. В рантайме каждый такой
вызов ловится своим `catch` и превращается в дефолт. Итог: врач в мессенджере не распознавался как
сотрудник, у клиник с подключённым Google Calendar интеграция была выключена, клиники с оплаченным
брендированием слали от имени платформы, критические алерты оператору не уходили — **и всё это при
чистом журнале.**

Заплатки уже поставлены (коммиты `3dbda6644`, `75d4ae1bd`, `93ca870d8`): 11 capability-функций,
lint-запрет, живой readiness-гейт. Это закрыло **две таблицы из ~30** и **один процесс из трёх**.
Причина осталась.

**Диагноз в одну строку:** у объекта прав нет одного владельца-файла. Поведение определяет тот,
кто применился последним, а порядок применения неявный и держится в голове. Из 61 оверлея
**ровно один** (`c4-operational-runtime.sql`) сверяет желаемое с фактическим (`expected_base` +
`EXCEPT` в обе стороны). Остальные 60 просто выполняются — молча и без проверки результата.

## Целевая архитектура

Готового инструмента под нашу картину нет: Atlas умеет роли/гранты/RLS декларативно, но это
**платный Pro** и он **не покрывает SECURITY DEFINER** — а у нас их 233, это ядро модели доступа.
Покупать инструмент, который не решает главную часть, смысла нет.

Зато нужный паттерн у нас **уже есть и доказал работоспособность** — C4:

1. **Желаемое состояние объявлено списком.** Не «выполни GRANT», а «вот полный перечень прав роли».
2. **Сверка в обе стороны.** `expected EXCEPT actual` ловит недостачу, `actual EXCEPT expected` —
   лишнее. Деплой падает на расхождении.
3. **Живая проверка ролью.** Readiness-гейт реально логинится каждой ролью и пробует и то, что
   должно работать, и то, что должно быть запрещено.

Работа = **распространить этот паттерн на весь слой** и дать каждому объекту одного владельца.

## Этапы

Каждая галочка = ссылка-доказательство. «Готово» = галочка + зелёный full CI + живая проверка.

### Э0 — гейт дрейфа (безопасно, ценность сразу, НЕ зависит от развилок)
- [ ] Скрипт: снять из живой БД полный слепок слоя прав (политики, ACL, definer-функции, роли,
      RLS-флаги) в стабильном текстовом виде
- [ ] Собрать из репо, что мы *думаем*, что описали
- [ ] Отчёт: объекты в БД, не описанные нигде; описанные дважды и более; описанные, но отсутствующие
- [ ] Прогнать на TEST, зафиксировать baseline дрейфа числом

### Э1 — один объект = один владелец-файл
- [ ] Реестр: объект → файл-владелец (по слепку Э0)
- [ ] Устранить 36 переопределений политик и рекордсменов среди функций (12/10/9/7…)
- [ ] Гейт: повторное определение объекта вне файла-владельца роняет CI

### Э2 — явный порядок применения
- [ ] Порядок оверлеев объявлен данными, а не позицией строки в `deploy-test-saas.sh`
- [ ] Зависимость «функция создаётся до гранта на неё» проверяется, а не подразумевается
      (сегодня это я поймал руками: C4 применяется позже `integrator-server-runtime-config`)

### Э3 — сверка на весь слой (обобщение C4)
- [ ] `expected` + `EXCEPT` в обе стороны для политик
- [ ] То же для definer-функций (владелец, `search_path`, ACL)
- [ ] То же для ролей и членств
- [ ] Живые role-пробы (позитив + запрет) для каждого контура, не только для четырёх операционных

### Э4 — вынести права из миграций
- [ ] Историю 160 миграций не трогаем — заморозить
- [ ] Запретить права в НОВЫХ миграциях (гейт), место для них — слой оверлеев

### Э5 — гейт «код vs права»
- [ ] Из кода вывести список объектов БД, к которым он обращается, и под какой ролью
- [ ] Сверить с фактическим ACL, расхождение = красный CI
- [ ] Это то, что поймало бы все 10 дефектов 07.08 на сборке. Lint-правило `93ca870d8` — его
      узкий частный случай на две таблицы

## Развилки владельца (нужны ДО старта; safe-default — мой выбор, если промолчите)

1. **Инструмент.** Свой паттерн (обобщить C4) / Atlas Pro (платно, без SECURITY DEFINER).
   → **safe-default: свой.** Atlas не покрывает 233 definer-функции, то есть главную часть.
2. **Глубина.** Только гранты+политики / плюс definer-функции / плюс роли и членства.
   → **safe-default: всё, но по этапам Э1→Э3**, начиная с того, что уже горело.
3. **Что со 160 миграциями с правами.** Заморозить историю + запрет на новые / переписать историю.
   → **safe-default: заморозить.** Переписывать 160 применённых миграций — риск без выгоды.
4. **Порядок.** Э0 сразу (замер дрейфа, ничего не меняет) / ждать решения по 1–3.
   → **safe-default: Э0 сразу**, он полезен при любом выборе и ничего не пре-эмптит.

## Не входит

- Миграция сырого SQL на Drizzle — отдельно и уже отклонено двумя ревьюерами
  (`../DB_ACCESS_CHOKEPOINT_INITIATIVE/RAW_SQL_RULING.md`).
- Chokepoint соединений/пулов — смежная инициатива, не здесь.
- Прод. Всё делается и проверяется на TEST; прод — только после живой приёмки владельцем.
- Изменение модели доступа по существу (кто что должен видеть). Здесь — только то, **как этим
  управляют**. Ни одна роль не должна получить или потерять доступ по итогам этой работы, кроме
  случаев, вынесенных владельцу отдельной строкой.

```bash
ls deploy/postgres/*.sql | wc -l && cat deploy/postgres/*.sql | wc -l
grep -lE '^\s*(GRANT|REVOKE|CREATE POLICY|ALTER TABLE .* (ENABLE|FORCE) ROW LEVEL|CREATE ROLE|SECURITY DEFINER)' apps/webapp/db/drizzle-migrations/*.sql | wc -l
grep -rhoE 'CREATE POLICY "?[a-z0-9_]+"? ON [a-z_.]+' deploy/postgres/*.sql apps/webapp/db/drizzle-migrations/*.sql | sort | uniq -c | sort -rn
grep -rhoE 'CREATE OR REPLACE FUNCTION app\.[a-z0-9_]+' deploy/postgres/*.sql apps/webapp/db/drizzle-migrations/*.sql | sort | uniq -c | sort -rn
```

```sql
select 'policies', count(*) from pg_policies where schemaname in ('public','integrator','app')
union all select 'app.* functions', count(*) from pg_proc p join pg_namespace n on n.oid=p.pronamespace where n.nspname='app'
union all select '  SECURITY DEFINER', count(*) from pg_proc p join pg_namespace n on n.oid=p.pronamespace where n.nspname='app' and p.prosecdef
union all select 'roles', count(*) from pg_roles where rolname ~ '^(app_|bcb_|saas_)'
union all select 'RLS tables', count(*) from pg_class c join pg_namespace n on n.oid=c.relnamespace where c.relrowsecurity and n.nspname in ('public','integrator');
```
