## Целевая архитектура — четыре принципа (evidence/07, проверяются в Ф0)

1. **Одна декларация — один генератор.** Истина о правах живёт в одном декларативном файле; гранты
   существуют только как вывод генератора; миграции несут только схему. Одна власть над ACL.
2. **Deny by default + стена в точке создания.** Рантайм-роли не получают ничего по умолчанию;
   новая таблица рождается закрытой; event trigger ставит RLS+FORCE при рождении org-таблицы.
   Забыл объявить = громкий 42501 на dev, никогда не тихая утечка.
3. **Двусторонняя сверка.** `объявлено EXCEPT есть` И `есть EXCEPT объявлено` — оба непусты =
   красный. Ядро уже есть (`c5a`, паттерн pg_permissions/CIS) — расширить на все роли.
4. **Стену держит движок + свип как страховка.** GRANT + RLS + FORCE применяет Postgres, не код.
   Свип = каталожные инварианты «ноль нарушений» одной командой. Стенд a1 = поведенческое
   доказательство сквозь реальный код. В нормальной жизни оба вечно зелёные; красный = ЧП, не будни.

Порядок важен: **сначала конструкция, при которой дефект не рождается (1, 2), потом детект как
страховка конструкции (3, 4).** Гейты как основной механизм = увековеченный режим «каждый ход
что-то ловим» — отвергнут владельцем.

## Правило приёмки — каждый инкремент, без исключений

Три транскрипта в сообщении коммита: **КРАСНЫЙ** (на непочиненной реальности) → **ЗЕЛЁНЫЙ** (после
починки) → **СНОВА КРАСНЫЙ** (дефект внесён обратно в откатываемой транзакции). Роли: доказыватель
(правит только код инкремента) · ломатель (Opus, не видит рассуждений доказывателя) · я (сверяю с
этим файлом). «Аудит доволен» ≠ готово. Стоп-правило: два круга без закрытой галочки → эскалация
моделей/контекста; ещё два — стоп и вопрос владельцу.
Растяжка еженедельно: строк `.md` не больше строк исполняемого кода (`FACTS.md` §7).
