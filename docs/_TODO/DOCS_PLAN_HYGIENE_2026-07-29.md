## Канон разметки — уже принят владельцем 27.07, не изобретать заново

Источник: `BACKLOG_CONSOLIDATION_2026-07-26.md` §6.3. Применять дословно:

| Состояние | Разметка |
|---|---|
| **Сделано** | `- [x] **<исходный текст>** — <доказательство: commit / file:line>` |
| **Отменено владельцем** | `- [-] ~~<исходный текст>~~ — ⛔ ОТМЕНЕНО ВЛАДЕЛЬЦЕМ <дата>: «<его слова>»` |
| **Вытеснено** | `- [-] ~~<исходный текст>~~ — ↪️ ВЫТЕСНЕНО <дата>: работа живёт в `<файл>` §<раздел>` |
| **Замороженная запись аудита** | `- [-] ~~<исходный текст>~~ — 🧊 ЗАМОРОЖЕНО <дата>: перезакрывать запрещено` |
| **Отложено владельцем** | `- [-] ~~<исходный текст>~~ — ⏸ ОТЛОЖЕНО ВЛАДЕЛЬЦЕМ <дата>: «<его слова>»` |
| **Открыто** | `- [ ] <исходный текст>` |

**Почему `- [-]`:** он не совпадает ни с `- [ ]`, ни с `- [x]`, поэтому сплошные подсчёты перестают видеть
такой пункт И как работу, И как достижение. Мёртвое выпадает из обеих цифр, оставаясь в файле.

**Отмена документа ОБЯЗАНА закрывать его боксы.** Пометка только в шапке при живых `- [ ]` внутри — это ровно
тот механизм, которым набралась «тысяча задач».

за одну ночь получил ТРИ разных вердикта от трёх агентов — воркер «закрыт по [x]», лид «0 сделанных»,
аудитор «ВЫТЕСНЕН». Файл всем троим говорил одно и то же, в первых 25 строках, со ссылками на восемь
преемников. Отметку, которую надо захотеть прочитать, не читает никто.

**Следствие для этого плана — Э1 переворачивается:** сначала МЕХАНИЧЕСКИ собрать уже существующие
указатели, и только потом классифицировать руками то, у чего указателя НЕТ. Иначе мы вручную

### ⚠️ ПОПРАВКА ВЛАДЕЛЬЦА 29.07: «вытеснено» — мусорная корзина, её надо разобрать

Владелец: «с одной стороны да, с другой - это все еще двоение планов. вытеснено - что значит? отменено и

| фактический смысл | сколько | пример дословно из репозитория |
|---|---:|---|

| **Та же ЖИВАЯ задача ведётся в другом файле** | ~13 | «работа ЕЩЁ НЕ ЗАКРЫТА. Живой трекер: `P0_7_WRITER_CENSUS_CHECKLIST.md:72`» |

**Вывод, меняющий подход:** 37 из 82 — это не переезд, а СДЕЛАНО. Ещё 10 — ОТМЕНЕНО. Им не нужна
навигация, им нужна правильная отметка. Настоящее двоение — только ~13 боксов, где одна живая задача
записана чекбоксом в ДВУХ файлах сразу и потому считается дважды.

**Указатель на переезд двоение НЕ лечит — он делает его удобным.** Сколько ссылок между двумя боксами ни
проложи, счётчик посчитает их дважды. Поэтому граф переездов НЕ строим.

**Три состояния вместо одного ярлыка «вытеснено» — обязательны для Э1 и Э3:**

| состояние | разметка | правило |
|---|---|---|
| **Сделано** | `- [x] <текст> — <доказательство: файл:строка / commit>` | Это НЕ переезд. Просто закрыто, доказательство рядом |
| **Отменено** | `- [-] ~~<текст>~~ — ⛔ ОТМЕНЕНО <дата>: <чьё решение / какая предпосылка умерла>` | Следовать некуда |
| **Переехало** | **бокс перестаёт быть боксом**: строка прозой «этот кусок ведётся в `<файл>:<строка>`» | Одно требование — один живой чекбокс, ровно в одном файле |

**Ключевое правило против двоения (владелец 29.07):** живой чекбокс существует РОВНО В ОДНОМ файле.
Если задача ведётся в другом плане — здесь она перестаёт быть `- [ ]` и становится прозой. Пока бокс
остаётся боксом в обоих местах, любой счётчик считает его дважды, и перелинковка этого не исправит.
