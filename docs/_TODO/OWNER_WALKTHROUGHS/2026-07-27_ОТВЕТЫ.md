# Что значат «месяц/год/день» на экране тарифов — период тарификации? период квоты? что именно?

а текущее значение (`snapshot`); у остальных механик это только сохранённая конфигурация.

# Что значит «без квоты / числовая / без лимита»?

«Без квоты» удаляет объект квоты (`null`), «числовая» сохраняет целое неотрицательное ограничение, «без
лимита» сохраняет явную квоту вида `unlimited` с `limit: null`. Для `courses` отсутствие квоты и `unlimited`
разрешают создание, а числовая квота блокирует новый курс сверх лимита; для остальных механик выбор только
сохраняется и показывается, но нигде не ограничивает работу.

Реальное ограничение есть ровно у одной механики:

- `courses` — «Курсы», `atomic_snapshot`.

- `booking` — «Онлайн-запись»;
- `exercise_catalog` — «Каталог упражнений»;
- `exercise_packages` — «Пакеты упражнений»;
- `cms_pages` — «Страницы CMS»;
- `files` — «Файлы пациентов»;
- `patient_card` — «Карточка пациента»;

# Что такое Error tracking DSN и зачем он нам.

DSN — адрес подключения к совместимому с Sentry серверу сбора ошибок; по нему серверные процессы понимают,
куда отправлять неожиданные исключения. В проекте это нужно для централизованного сбора ошибок webapp и
integrator вместо поиска только по локальным логам; перед отправкой код редактирует чувствительные поля.
Механизм включается только парой «enabled + валидный DSN» и требует перезапуска процесса, поэтому без
настроенного сервера и включения он ничего не отправляет.

# «Integrator: источник linkedPhone» — что это за настройка и что она делает.

Это переключатель источника, по которому integrator считает телефон пользователя привязанным:
`public_then_contacts` сначала читает канонический телефон webapp и затем старые контакты integrator,
`public_only` читает только webapp, `contacts_only` — только старые контакты. Он нужен для миграции между двумя
источниками и сам телефон не записывает. Результат влияет на выдачу главного меню и доступ к действиям
записи/кабинета: без `linkedPhone` integrator просит поделиться контактом.

# «Задержка SMS fallback для важных сообщений (минут)» — что это, работает ли, и делает ли так кто-нибудь в мировой практике (если найдёшь источник — назови; если нет — так и скажи).

По подписи интерфейса это задержка, после которой важное непрочитанное сообщение предполагалось повторно
отправлять по SMS. Сегодня это не работает: ключ можно сохранить и показать, но в коде нет ни читателя этого
значения, ни задачи, которая проверяет прочтение и отправляет fallback. Аналогичная практика задержанной
эскалации между каналами существует у PagerDuty: правила могут сначала отправить push, а через заданные
интервалы — звонок, email или SMS; это аналог для инцидентов, а не найденное подтверждение именно медицинского
сценария «пациент не прочитал сообщение».

# «Ручной merge клиентов: сценарий v2 (integrator → webapp)» — кто и когда это делает, почему это вообще существует, и можно ли устроить так, чтобы ручной мёрдж не требовался никогда.

Панель предназначена администратору в admin mode для случая, когда две записи уже представляют одного человека,

не может: неоднозначные конфликты специально блокируются, а продуктовая политика их автоматического разрешения

# «Очередь синка интегратора» на экране здоровья — что это, и не остаток ли это вырезанного поведения.

Это действующая outbox-очередь для повторной доставки из webapp в integrator двух видов изменений:
системных настроек и правил напоминаний. Webapp сначала пробует немедленный подписанный M2M-запрос, а при
ошибке кладёт последнюю версию события в очередь; worker забирает её пакетами, повторяет с увеличивающейся
задержкой и после исчерпания попыток помечает `dead`. Поэтому по коду это не остаток вырезанного поведения,
а используемый контур согласования двух отдельных приложений.

отсутствие запусков, подписок или настройки. Для ответа по текущему экрану нужен запрос к базе TEST; до него
называть это поломками или особенностью TEST нельзя.
