## Слепой kill-set

Составлен до чтения тестов:

1. `disabled`/`read_only` не допускает вызова платёжного провайдера для нового intent записи.
2. То же ограничение действует для нового intent абонемента.
3. Существующий intent по тому же ключу остаётся доступен после выключения механики.
4. Разрешённая механика сохраняет рабочее создание intent.
5. Настройки приёма платежей скрыты при `disabled`, а при `read_only` видны без работающих элементов изменения.
6. Предоплата записи требует одновременно `booking_prepayment` и `payments`; история и SaaS billing не закрываются этой механикой.

## Вердикт: FAIL

### MUST FIX — переключатели настроек продолжают работать визуально в режиме «только чтение»

Достижимый сценарий: врач открывает сохранённые настройки приёма оплат при `read_only` и нажимает переключатель «Включить оплату записи». `BookingPaymentsSection` оборачивает элементы в `fieldset disabled`, но `LabeledSwitch` реализован пользовательским `span role="switch"`; браузерное отключение fieldset на него не распространяется. Переключатель меняет `aria-checked` с `true` на `false`, хотя экран сообщает, что доступен только для просмотра. Сохранение отдельно заблокировано, поэтому записи в БД нет, но UI не выполняет обязательное read-only поведение и показывает пользователю несуществующее изменение.

Падающее acceptance-доказательство: `apps/webapp/src/app/app/settings/BookingPaymentsSection.ui.test.tsx`.
