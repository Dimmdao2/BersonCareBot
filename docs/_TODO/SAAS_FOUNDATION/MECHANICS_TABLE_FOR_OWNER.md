## Механики, которыми тариф управляет сегодня

| Механика | Что это | Что теряет клиника | Что теряет пациент |
| --- | --- | --- | --- |
| Онлайн-запись | включатель | Пропадает управление филиалами, услугами и расписанием записи | Пропадает весь раздел «Запись» и «Кабинет»: слоты, перенос, отмена своих визитов |
| Каталог упражнений платформы | включатель | Пропадает доступ к готовой платформенной библиотеке упражнений; свои упражнения и шаблоны у клиники остаются | Пропадают упражнения из назначенных программ и дневника ЛФК, которые взяты из платформенной библиотеки |
| Пакеты упражнений платформы | включатель | Пропадают готовые платформенные наборы упражнений для сборки программ | Не установлено — отдельного экрана «пакеты упражнений» у пациента не найдено, эффект только через состав уже назначенной программы |
| Курсы | сегодня в коде — квота (числовой предел работает); по решению владельца должна стать включателем без числа | Нельзя создать курс сверх предела; при выключении раздел «Курсы» пропадает целиком | Пропадает каталог курсов и запись на них — проверка стоит прямо на пациентской странице курсов |
| Страницы сайта (CMS) | сегодня в коде — квота (считает все страницы, включая архивные — поэтому владелец решил её убрать); по решению владельца должна стать включателем без числа | Пропадает раздел управления статьями и страницами сайта; страница профиля, страница записи и виджеты для сайта остаются всегда — это не часть CMS | Пропадают контентные страницы и статьи организации (о клинике, помощь и т.п.), кроме профиля, страницы записи и виджетов |
| Файлы пациентов | включатель (в будущем — объём в байтах) | Нельзя прикреплять и загружать файлы к карточке пациента | Ничего — файлы карточки видит только специалист, файлового раздела в приложении пациента нет |
| Карточка пациента | включатель сегодня; по решению владельца эта механика — критичная и не должна ограничиваться тарифом вовсе | Нельзя вести визиты, анамнез, диагнозы, жалобы и сопутствующие состояния пациента | Саму карточку пациент не видит; данные из неё видны ему опосредованно — например, история визитов |
| Абонементы пациентов | включатель | Нельзя оформлять и продавать пациентам абонементы | Пропадают свои абонементы пациента и их оплата в кабинете |
| Приём оплат (оплата записи) | включатель | Нельзя принимать оплату от пациентов за запись и приём | Пропадает оплата записи и история платежей в кабинете |
| Рассылки | включатель | Нельзя отправлять рассылки пациентам | Пациент перестаёт получать и открывать рассылочные сообщения клиники |
| Приложение пациента | включатель сегодня; по решению владельца это критичная механика — «основная ценность платформы», не ограничивается вовсе | Не установлено — это же и есть механика доступа пациентов клиники к приложению | Пропал бы доступ ко всему приложению целиком, поэтому владелец и решил её никогда не ограничивать |
| Платная подписка пациента | включатель | Нельзя брать с пациента отдельную плату за доступ к приложению | Не установлено — отдельного экрана в коде не нашли, вероятно управляет доступом ко всему приложению целиком |
| Брендирование | включатель (включает и свои шаблоны уведомлений) | Пропадает свой логотип и оформление; уведомления становятся нейтральными платформенными, а не от имени клиники | Не установлено окончательно — код для чтения бренда пациентом существует, но реального показа лого клиники в приложении пациента не нашли |
| Свой домен | включатель | Нельзя открывать приложение на собственном домене клиники | Ничего — влияет только на адрес в браузере, не на работу приложения |
| Режим клиники (места специалистов) | квота: база + цена за каждого следующего | При нехватке мест нельзя пригласить нового специалиста сверх оплаченных | Не установлено прямого эффекта — сегодня ограничение только не пускает добавить специалиста сверх лимита |

## Названы в планах, но в реестре тарифа их ещё нет

- **Внешний календарь** — синхронизация расписания специалиста с внешними сервисами. Пациентской стороны у этой будущей механики нет; в коде есть только отдельная не связанная с ней кнопка «добавить в свой календарь» на странице подтверждения записи.
- **Дневники пациента** — уже существующий полноценный раздел (дневник, симптомы, ЛФК). Пациент при выключении потеряет весь раздел «Дневник».
- **Клинические тесты и наборы** — пациент потеряет прохождение тест-сетов внутри программы лечения; при выключении системные группы тестов пропадут и из самой программы.
- **Онлайн-анкета перед приёмом** — пациент потеряет анкеты перед приёмом (ЛФК, питание) и историю своих заявок в кабинете.
- **Статистика кабинета вместе с источниками записи** — это для клиники и владельца платформы; пациентской стороны нет.
- **Проактивные подсказки** — видны только специалисту; пациент не видит ничего.
- **Задачи специалиста** — видны только специалисту; пациент не видит ничего.
- **Предоплата при записи** — отдельного экрана у пациента нет, эффект проявляется через уже существующий экран оплаты записи.
- **Число пациентов** — это квота для клиники (сколько клиентов можно завести); действующий пациент ничего не теряет никогда, ограничение касается только заведения нового.
- **Число филиалов** — квота для клиники; пациент напрямую ничего не теряет, видит только итоговый список адресов при выборе города для записи.
- **Поддержка** — форма обращения в поддержку у пациента уже работает в коде, но это не полноценный чат с историей переписки, и в реестре тарифа рубильника для неё пока нет.
- **«Сегодня» (настройка пациентской домашней страницы)** — пациент потеряет персонализацию главной страницы: курсы, разминку дня, карусель абонементов, SOS-карточку, порядок и видимость блоков.
- **Разминки** — пациент потеряет карточку «разминка дня» на главной странице.
- **Промо** — пациент потеряет промо-программу лечения, которую клиника назначает по умолчанию без участия врача.

Отдельно, чисто будущие направления без всякой заготовки в коде (справочно из мировой практики, не забытые рубильники):
телемедицина и видеоприём, групповые занятия и классы, лист ожидания, API и вебхуки для клиники, ИИ-заметки.

## Механики, которые в тариф не входят вовсе — решение владельца

**Никогда не ограничиваем (критичные):**

- Карточка пациента — пациент её не видит напрямую, но данные из неё видны ему опосредованно (история визитов).
- Приложение пациента — при ограничении пациент терял бы доступ ко всему приложению целиком.
- Напоминания и уведомления пациенту — пациент потерял бы свой раздел напоминаний и уведомлений в кабинете.
- Двухфакторная аутентификация — пациент потерял бы выбор канала для кода подтверждения при входе и других критичных действиях.
- Журнал операций — своего журнала операций у пациента в коде нет; журнал есть только у платформенного администратора.
- Экспорт своих данных — экспорта данных для пациента в коде нет вовсе, есть только удаление дневника по коду подтверждения.
- Экстренная помощь — пациент потерял бы экран экстренной помощи (сейчас он устроен как обычная контентная страница).

**Рубильника не делаем вовсе:**

- Шаблоны программ лечения — пациент видит не сам шаблон, а свою готовую программу, собранную из него.
- Шаблоны комплексов ЛФК — пациент видит не библиотеку шаблонов, а свой назначенный комплекс в дневнике.
- Переписка с пациентом — пациент потерял бы чат с врачом.
- Правила отмены записи — саму настройку пациент не видит, но её эффект (можно ли отменить или перенести запись) виден в кабинете.
- Оценки материалов — гасятся для платформы целиком, механикой тарифа не становятся; пациент потерял бы виджет оценки материала и разминки.
