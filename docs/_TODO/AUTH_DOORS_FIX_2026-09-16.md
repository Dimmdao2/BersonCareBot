## Границы для всех этапов

Пациентский вход не ломается: каждый этап обязан назвать, что именно продолжает работать как сейчас.
Прод и TEST не трогаются. Миграции из клона на DEV не накатываются — только откатываемый preflight.
Полный CI гоняется, только когда в `feat` приедет исполняемый код, а не markdown. Галочка этапа не
ставится, пока не пройден независимый адверсарный аудит другой моделью, чем автор.

Владелец 16.09: «может лучше если гейт не работает поискать где еще есть маршруты - разными

поиском. Команды и цифры:

- кто зовёт пациентскую сессию напрямую, минуя общий проход
  (`grep -rln "getOptionalPatientSession\|patientClientBusinessGate\|canAccessPatient" --include=route.ts`

  (`patient/support`, `patient/email-change/confirm`, `patient/messenger/request-contact`),

  две двери входа `auth/phone/{start,messenger-bind/start}`, которые по устройству работают до сессии;
- остальные маршруты без общего прохода разложены по первому сегменту пути: `doctor` 176, `admin` 60,
  `auth` 40, `integrator` 29, `internal` 18 — это сотрудничьи и служебные поверхности, другой класс
  двери; `booking/public` 6 и `references`/`brand` — публичные по устройству; `payments/*-webhook` —

  `app/max` и `app/page.tsx` рендерят вход, `app/account` — учётная запись любой роли.

**Вывод переписи:** класс «пациентский маршрут мимо общего прохода» на `feat` больше нигде не

будущее — три круга аудита нашли три разных таких маршрута подряд.
