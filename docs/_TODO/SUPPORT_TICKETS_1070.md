# #1070 — независимая поддержка платформы

**Статус 01.09.2026:** только исследование. Код собственной системы поддержки не разрешён и не начат.

## Действующие решения владельца

- Поддержка должна работать, когда основное приложение или его база недоступны.
- На старте поддержка особенно нужна человеку, который не может войти; обращение без учётной записи обязательно.
- Сначала исследуется простой готовый российский helpdesk. Собственная система — только один из сравниваемых
  вариантов, а не выбранная реализация.
- Размещение на втором физическом сервере не даёт автоматической изоляции: публичная поддержка не получает
  доступ к резервным копиям и журналам безопасности.
- Поддержка помогает пользоваться платформой. Медицинские вопросы направляются врачу в кабинете.
- Первичная обработка и хранение персональных данных — в РФ. Нужны экспорт, управляемое удаление и понятная
  политика хранения.

Эти решения заменяют прежний агентский проект встроенного helpdesk в основном webapp, включая старый запрет
гостевого обращения. Старый проект не является запасным активным чек-листом; его история остаётся в Git.

## Текущий этап — сравнение вариантов

- [ ] Зафиксировать минимальный независимый путь: человек открывает обращение без входа и без работающих webapp,
  основного API и основной PostgreSQL.
- [ ] Сравнить готовые российские продукты и собственный self-hosted вариант по anonymous intake, размещению и
  локализации данных в РФ, email/мессенджерам, API/экспорту, retention/удалению, вложениям, защите от спама,
  стоимости и сложности эксплуатации.
- [ ] Для каждого self-hosted варианта описать отдельный failure/security domain: публичный helpdesk не читает
  backups, security logs, секреты и БД основного приложения даже при одном физическом сервере.
- [ ] Подготовить владельцу короткий выбор с ценой и рисками. До его решения не создавать таблицы, RLS, routes,
  UI или интеграцию собственной поддержки.

## Критерий завершения исследования

Один документ сравнения отвечает человеческим языком: какой продукт можно взять, где он живёт, что продолжит
работать при падении платформы, как принимает обращение без входа, где хранит данные, сколько стоит и что нужно
обслуживать. После выбора владельца этот файл расширяется только выбранным путём; отвергнутые варианты не
остаются открытыми задачами.
