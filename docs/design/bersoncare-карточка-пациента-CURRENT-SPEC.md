## 2. Вкладки

⚑ **Обзора как отдельной вкладки НЕТ. Карта открывается на «Карточке» по умолчанию.** _(owner 2026-07-23.)_

По UI-5b (PLAN.md:190,536) блоки `Overview` (Обзор), `Communications` (Коммуникации) и `Visits` (Визиты/Записи)
**не дублируются отдельными вкладками — их существующие блоки переносятся в тело «Карточки»**, а не переписываются.

- **Коммуникации — ВЫРЕЗАНА как вкладка.** Чат живёт через существующий messaging path внутри карты. _(PLAN.md:190-191,536)_
- **Финансы — ВЫРЕЗАНА как вкладка.** Список абонементов и история переезжают в левую часть card flow. _(PLAN.md:545)_
- **Обзор — ВЫРЕЗАНА как вкладка.** Её содержимое (KPI, сигналы, симптомы/динамика, заметки/задачи, программа) —
  в теле «Карточки». _(owner 2026-07-23 + PLAN.md:192-195)_

**Итоговый ряд вкладок (наслоение спек: бэклог → UI-5b → owner):**

> **`Карточка (старт) · Программа · Файлы · Учётка`** — 4 вкладки.

Выведено наслоением: базовые 6 (Обзор·Карта·Программа·Записи·Файлы·Учётка) → UI-5b:190 переносит блоки **Обзор,
Коммуникации и Записи(Визиты) в «Карточку»** (не отдельные вкладки) → Финансы (абонементы) → в card flow →
owner 2026-07-23: старт на «Карточке», Обзора нет. «Карта» = «Карточка» (клиническое ядро, впитавшее Обзор+Визиты).
Если Записи должны остаться отдельной вкладкой — поправить одной строкой (owner).

## 3. Тело вкладки «Карточка» (по UI-5b)

> **Детальная модель СОДЕРЖИМОГО клинических блоков (БД-модель визитов/жалоб/диагнозов/файлов, формы визита,
> «Программа», «Файлы», «Учётка») НЕ переписывалась и остаётся валидной в бэклоге §2/§3/§5/§6:**
> [`bersoncare-карточка-пациента-бэклог.md`](bersoncare-карточка-пациента-бэклог.md). Здесь — только структура,
> шапка и раскладка (что заменило старое); содержимое блоков — оттуда.

- Поиск при активной карточке доступен; совпадения — dropdown под полем. _(PLAN.md:185,531)_ ⚑ **owner-deferred
  2026-08-20** — «поиск клиента прямо внутри открытой карточки — не надо пока»; не реализовано, не отменено.
- Внутри рабочих вкладок — 50/50 master/detail; на mobile видна одна часть. _(PLAN.md:188,535)_
- Справа выбранная запись о визите **скрыта по умолчанию.** _(PLAN.md:192,538)_
- Сверху справа — **KPI-строка `Визиты / Будущие записи / Абонементы`**; клик открывает данные в левой части над
  диагнозом. _(PLAN.md:192-193,539)_
- Ниже справа: **Заметки · Задачи · Динамика симптомов · Назначенная программа · календарь «Выполнение упражнений».**
  Пустые Заметки/Задачи показывают только действие добавления (без текста «нет …»). _(PLAN.md:194-195,540)_
- Summary программы: только название, дата контроля, этапы с подсветкой активного (без состава упражнений); клик по
  названию открывает саму программу. _(PLAN.md:196-197,541-543)_
- В левом списке визитов оформленная запись предлагает **«Открыть заметки»**, а не повторное создание визита. _(PLAN.md:198,544)_
- Абонементы в левой части: список + история, `Списать` (только активному) · `Пересчитать` · верхнее `Добавить
абонемент` (открывает справа конфигурацию/выбор/оплату; реальная online-оплата — отдельная `#819`). _(PLAN.md:199-200,545-548)_
- **Убрать** поясняющие пустые подписи: про приоритет/выраженность, «диагнозов нет», «по клику …», об отсутствии
  сопутствующих состояний, «травм не внесено». _(PLAN.md:201-202,549-553)_
- Диагноз **не** называется «Актуальный»; preliminary diagnoses входят в единый список (без отдельного bucket).
  Цвета симптомов переиспользуют существующую Overview color logic. _(PLAN.md:203-204,554-555)_
