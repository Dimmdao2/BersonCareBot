## Что из этого следует разобрать

1. **У программы должен быть финальный срок** — не бесконечность. Либо специалист ставит его при
   создании, либо действует срок по умолчанию (кандидат владельца — 90 дней без работы по программе).
2. **Что значит «по ней никто не работает»** — надо назвать измеримо: нет новых отметок пациента, нет
   открытых этапов, нет продления специалистом. Сегодня такого признака нет.
3. **Что происходит при истечении:** новые этапы не открываются, программа закрывается. Открытый вопрос
   — остаётся ли она видимой специалисту как история.
4. **Материалы удаляются** — и вот здесь нужно развести классы, иначе удалим не то:
   - видео, **присланное пациентом** для проверки: оригинал стирается сразу после конвертации (уже так
     работает), удалять по сроку остаётся только наш 480p;
   - видео, **снятое специалистом на приёме** как индивидуальное упражнение этого пациента: принадлежит
     пациенту, лежит зашифрованным; удаление по закрытию программы нужно обсуждать отдельно — это
     материал специалиста, из него сделано назначенное упражнение;
   - **библиотека упражнений** организации к программе не привязана и по сроку программы не удаляется
     никогда.
5. **Юридическая сторона** — сроки хранения заметок практика (не медПО) и то, что удаление должно быть
   предсказуемым для специалиста: он не должен обнаружить пропажу материалов приёма без предупреждения.
6. **Механика удаления** — существующая очередь `media-pending-delete/purge`, а не новый код.

## Почему это не мелочь по деньгам

Хранение оплачивается объёмом (пакеты места, `STORAGE_PACKAGES_2026-09-10.md`). Без финального срока
объём растёт вечно и у арендатора, и у нас: пакеты кончатся, а удалять будет нечего, потому что всё
«ещё нужно». Срок жизни программы — это то, что делает объём ограниченным сверху.
