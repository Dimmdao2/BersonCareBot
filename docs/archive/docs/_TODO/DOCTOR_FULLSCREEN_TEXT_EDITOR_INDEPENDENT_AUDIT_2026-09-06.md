## 1. MUST FIX — в редакторе заметки при открытой клавиатуре footer `Отмена`/`Сохранить` уезжает за экран

Нарушено: `MODAL-TEXT-05` («общий footer … при открытой клавиатуре остаётся непосредственно над ней»),
`PATIENT-NOTE-EDITOR-03` («в нижней панели заметки ВСЕГДА доступны `Отмена` и `Сохранить`»).

**Причина.** `apps/webapp/src/app/app/doctor/patients/[userId]/tabs/PatientTabOverview.tsx:1658` оставил
от старого bottom-drawer строку `bodyClassName="flex min-h-[45dvh] flex-col p-0 md:min-h-0"`. В новом
fullscreen-теле (`DoctorModal.tsx:389-395`) базовый `min-h-0` этим классом ВЫТЕСНЯЕТСЯ (проверено прогоном
`cn()`): средняя область получает жёсткий пол `min-height: 45dvh`. `dvh` по спецификации не реагирует на
виртуальную клавиатуру, а высота модалки задаётся живым `visualViewport.height`. Как только
`45dvh + шапка + footer > visualViewport.height`, flex-строка переполняет контейнер с `overflow-hidden`,
и обрезается именно последний элемент — footer. У анамнеза заболевания и образа жизни этой строки нет
(`min-h-0` сохраняется), там дефекта нет.

**Доказательство (измерение в Chromium 1223, не рассуждение).** Точные классы обеих веток тела вынесены
в статический harness; popup позиционируется так же, как это делает код: `position:fixed`, `height` =
видимая высота. Шапка 43px, footer 61px (без safe-area).

| Сценарий (dvh / видимая высота) | тело заметки | footer заметки | footer анамнеза |
|---|---:|---|---|
| iPhone XR, клавиатура открыта (726 / 390) | 327px | **видно 20px из 61 — обрезан** | 61/61 — цел |
| iPhone SE, клавиатура открыта (553 / 293) | 249px | **видно 1px из 61 — обрезан** | 61/61 — цел |
| Pixel, клавиатура открыта (780 / 440) | 351px | **видно 46px из 61 — обрезан** | 61/61 — цел |
| iPhone XR, клавиатура закрыта (726 / 726) | 622px | 61/61 — цел | 61/61 — цел |

Достижимый сценарий: карточка пациента → «Обзор» → «Новая заметка» на телефоне. Поле получает автофокус,
клавиатура открывается сразу — то есть дефект виден в первую же секунду основного сценария, а не в углу.
На iPhone SE кнопки сохранения физически недоступны, пока доктор не закроет клавиатуру.

**Что чинить.** Убрать из этой строки `min-h-[45dvh]` (пол высоты теперь задаёт сам fullscreen-контракт).
Правка локализована до одной строки.

## 2. MUST FIX — на desktop общее поле схлопывается до двух строк вместо текстового листа

Нарушено: `DISEASE-EDIT-05` («на desktop/right-sheet ТОТ ЖЕ безрамочный текстовый ЛИСТ ориентирован
сверху»), бриф п. 8 («desktop preserves … top-oriented text entry»). Плюс конкретная регрессия
относительно поведения до кандидата.

**Причина.** `DoctorModalTextEditorField` (`DoctorModal.tsx:147-158`) задаёт полю `h-full min-h-0 flex-1`.
Это работает только в mobile-ветке, где контейнер имеет заданную высоту. На desktop `DialogContent` —
flex-колонка с `height:auto` и лишь `max-h`, поэтому высота поля определяется его собственным
intrinsic-размером: `<textarea>` без `rows` = 2 строки. Тело перестало расти под текст.

**Измерение (Chromium, viewport 1440×900, те же классы):**

| Вариант | пустое поле | текст в 30 строк |
|---|---:|---:|
| было: заметка (`rows=5`, `md:min-h-40`) | 160px | 160px |
| было: анамнез заболевания (`rows=1` + авторост до `scrollHeight`) | ~1 строка | рос до текста (748px контента), дальше скроллило тело модалки |
| стало: общее `DoctorModalTextEditorField` | **80px** | **80px** (контент 752px во внутреннем скролле) |

Достижимый сценарий: desktop-кабинет, карта пациента → «Анамнез заболевания» → правка. Раньше доктор
видел весь анамнез, теперь — две строки с внутренней прокруткой. Для заметки видимая область упала
со 160px до 80px.

**Что чинить.** Дать полю desktop-высоту, не ломая mobile: например `rows` по умолчанию + минимальная
высота для не-мобильной ветки внутри самого общего компонента (одно место, не по call site).
