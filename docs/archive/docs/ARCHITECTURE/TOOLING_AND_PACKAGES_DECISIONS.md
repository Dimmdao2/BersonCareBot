## Аналитика — своя, self-hosted; наружу ничего не уходит

**Линия (для медданных — осознанная): аналитика ТОЛЬКО self-hosted, стороннего сервиса нет.**

- **Текущее состояние: своя встроенная product-аналитика уже работает** — инициатива [`PRODUCT_ANALYTICS_INITIATIVE`](../archive/2026-08-initiatives/PRODUCT_ANALYTICS_INITIATIVE/README.md)
  (закрыта 2026-05-27). События (`app_open`, `page_view`, `heartbeat`, `auth_login`, воронка регистрации, push)
  идут в **наши же API-роуты → нашу БД**, агрегируются в докторский дашборд «Использование»
  (`/app/doctor/usage`). Модуль `apps/webapp/src/modules/product-analytics/`.
- **Наружу не уходит ничего.** Никакого стороннего сервиса. В метаданных — **без сырого PII** (оговорено в каноне
  инициативы); тестовые аккаунты исключены из агрегатов.
- **Plausible (из списка) — опционально и только как self-hosted дополнение.** Даже при внедрении: свой сервер на
  нашей инфре, данные третьей стороне не уходят (Plausible cookieless, без PII). Смысл — веб/PWA-трафик (источники,
  воронка установок), которого внутренняя система не покрывает. Не ядро; заводить только если реально понадобится
  маркетинговая трафик-аналитика.

## По месту — узкие библиотеки, без «внедрения платформы»

- **pgvector, НЕ Qdrant.** Векторный поиск по базе знаний/транскриптам — на существующем Postgres. Второй datastore
  (Qdrant) не заводить.
- **Recharts — `^3.8.1` уже установлен и используется** (`MiniStatsChart`, `SymptomChart`, `DiaryLineChartRecharts`,
  дневник пациента). Ставить нечего. Новые графики — по зафиксированному lazy-паттерну
  `next/dynamic(() => import("…Recharts"), { ssr: false })`; recharts не импортировать в серверных компонентах.
- **dnd-kit — `@dnd-kit/core@^6`, `/sortable@^10`, `/utilities` уже установлены** (reorder упражнений/шаблонов).
  Переиспользовать, не добавлять аналогов.

## Редактор контента — единый Tiptap Simple Editor (решение владельца 16.09.2026)

**Один форматированный редактор на всей платформе:** `TiptapEditor`, построенный на полном бесплатном шаблоне
Tiptap **Simple Editor**. Самописный ограниченный markdown-тулбар и отдельные реализации редактора запрещены.

- Исходники UI-компонентов Simple Editor хранятся в репозитории и адаптируются к зональным токенам платформы;
  ядро и расширения self-hosted, содержимое во внешние сервисы не отправляется.
- Доступны возможности Simple Editor: история, заголовки, списки и задачи, цитаты, блоки кода, inline-форматирование,
  цветное выделение, ссылки, верхний/нижний индекс, выравнивание, поиск/замена и изображения. Таблицы и медиатека
  платформы сохраняются как платформенные расширения того же примитива.
- Единственное каноническое хранение форматированного материала — versioned Tiptap JSON (`tiptap-json:v1:`).
  Markdown не импортируется и не рендерится. Оставшиеся старые строки открываются как буквальный plain text и
  после ручного сохранения становятся Tiptap JSON.
- Все reader-пути отображают JSON; отдельной legacy Markdown-ветки нет.
  Лимиты считаются по видимому тексту, а не по размеру сериализованного JSON.
- **Не AI-editor:** Tiptap Content AI — внешний платный сервис и в продукт не подключается.

Rich editor применяется ко всем существующим форматированным write-поверхностям: CMS, рекомендации, рассылки,
цели и задачи лечебной программы, публичные описания организации/специалиста и коммерческие шаблоны. Простые
однострочные поля, обычные заметки и строго типизированные транзакционные шаблоны не превращаются в rich editor.

**Куда Tiptap НЕ идёт (решение владельца 21.07) — транзакционные письма-шаблоны:** тексты уведомлений,
напоминания о записи на приём, проверочные (OTP) коды в email. Здесь **редактора контента не меняем**: текст
остаётся простым шаблоном с переменными (как сейчас, в настройках специалиста/клиники). Визуально настраивается
**только HTML-конверт письма** — см. следующий блок.

### Конверт транзакционных писем (N1B #930), НЕ Tiptap

Разделение **layout + content** (владелец: «не усложнять»):

- **Контент** (заголовок + тело уведомления, код, детали записи) — **данные**, правятся текущим простым
  редактором «Тексты уведомлений» (`/app/doctor/schedule`). Не Tiptap, не меняем.
- **Конверт (обёртка)** — фиксированный server-owned email-safe каркас: брендинг (логотип, аватар специалиста,
  подпись, контакты) + серверные слоты для заголовка и тела уведомления. Организация выбирает только разрешённый
  вариант раскладки и правит типизированные поля/токены бренда с живым превью на синтетике. Пользовательского
  HTML/CSS, визуального email-билдера и внешних ресурсов нет. На отправке: проверенные данные → безопасный каркас →
  финальный email-HTML + обязательный **plain-text fallback**.
- **Безопасность (уже требования N1B, не новый скоуп):** server-enforced schema/allowlist полей и переменных;
  подставляемый контент санитизируется, URL/ассеты проходят readiness-проверку. Script/handlers/raw HTML/CSS не
  принимаются вообще, а не только вырезаются после сохранения.
- **«Один» конверт = на организацию, под entitlement брендинга** (в N1B брендинг гейтится; без оплаты —
  нейтральный платформенный конверт по умолчанию). Мессенджеры/push — свои безопасные поля, HTML-конверт к ним не применяется.

**Синхронизация с планами (не плодить сущность):** и текстовые шаблоны, и HTML-конверт — это **эволюция
существующей системы шаблонов**, а не новый экран. Стадия **N1B «managed notification templates»** (taskdb `#930`,
[`docs/_TODO/RU_PRIVACY_AND_PRODUCTION_READINESS/stages/NTF-01_APP_PUSH_AND_MESSENGER_AUTH_ONLY.md`](../_TODO/RU_PRIVACY_AND_PRODUCTION_READINESS/stages/NTF-01_APP_PUSH_AND_MESSENGER_AUTH_ONLY.md)).
Обязательный reuse (канон N1B, не форкать второй стор): `modules/notif-templates/notifTemplatesService.ts`,
admin/doctor-роуты, настройки `notif_template:*`, редактор «Тексты уведомлений» (`NotificationTemplatesPageClient.tsx`).
**Tiptap в N1B не участвует** — конверт настраивается ограниченными полями поверх серверного каркаса.

**Массовые рассылки врача** (`/app/doctor/broadcasts`, `DOCTOR_BROADCASTS.md`) используют тот же `TiptapEditor`.
При доставке документ преобразуется в поддерживаемый каналом HTML либо plain text; сериализованный JSON получателю
никогда не отправляется. Это по-прежнему не относится к N1B.

## Про «фронтовый стек» из того же списка

Блок «Next.js 16 + React 19 + Tailwind v4 + shadcn new-york … Tiptap как ядро контента, idea-inbox → storyline, kanban,
30 экранов, статистика постинга» — это **язык проекта storylama, не наш**. У нас своя дизайн-система
(раздельные doctor/patient primitives и актуальные зональные темы; эталон каталога — страница упражнений). Оттуда к нам переносится только
точечно и по месту — не как стек. **Исключение — сам rich-text-редактор: конкретные markdown-поверхности его потребовали**
(рассылки, CMS/статьи, рекомендации), поэтому Tiptap **принят** отдельным решением 21.07 — см. раздел
«Редактор контента» выше. Остальной блок storylama-стека это не втягивает.
