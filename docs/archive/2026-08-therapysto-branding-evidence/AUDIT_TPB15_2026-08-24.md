## Findings (`T-1`), все внутри owner scope `TPB-15`

**F-1. Пятое и шестое место есть: `apps/integrator/src/integrations/bersoncare/relayOutboundRoute.ts`.**
Строка 162 — fallback темы письма `'BersonCare'`; строка 189 — fallback заголовка web-push
`'BersonCare'`. Маршрут по своему же заголовку «доставляет сообщение в нужный мессенджер-канал
**пациента**» — то есть это ещё и `TPB-08` (пациенту имя платформы не показываем).

**F-2. Седьмое и восьмое: `apps/integrator/src/integrations/bersoncare/operatorAlertRelayRoute.ts`.**
Строка 95 — fallback темы письма, строка 114 — fallback заголовка push, оба `'BersonCare'`.
Для push этот fallback **достижим**, а не мёртв: во всей цепочке вызова —
`modules/operator-alerts/relayOperatorAlert.ts` и `modules/operator-alerts/dispatchOperatorAlert.ts` —
слово `title` не встречается ни разу (`grep -c title` = 0 в обоих). Значит операционный алерт
приходит персоналу с заголовком `BersonCare`.

**F-3. Правка web-push адаптера показывает персоналу ПАЦИЕНТСКОЕ имя — нарушение §1.2f в обратную
сторону.** Автор поменял `apps/integrator/src/integrations/web-push/deliveryAdapter.ts:133` на
единственный fallback `'Therapygo'`. Но адаптер общий для обеих поверхностей: через него идут и
`sendAdminIncidentStaffWebPush`, и `notifyDoctorPatientMessageToStaff`, и
`notifySpecialistTaskReminder`, и операционные алерты — все персоналу. Один fallback на две
поверхности не может быть верным: он либо покажет пациенту Therapysto, либо персоналу Therapygo.
Сейчас — второе. Плюс для relay-пути эта правка вообще не работает: `relayOutboundRoute` уже
подставил свой `'BersonCare'` выше по потоку, и до fallback'а адаптера дело не доходит.

Рекомендация по форме (не работа — решение оркестратора): имя не должно доставаться из
fallback'а на границе доставки. Поверхность известна вызывающему, и `TPB-15` уже выбрал этот
способ в вебаппе — `mailProfile`, разрешённый на границе запроса, с отказом при отсутствии
(`T-6`). Интегратор — то же самое место, где это лечится одним chokepoint'ом, а не четырьмя
литералами.
