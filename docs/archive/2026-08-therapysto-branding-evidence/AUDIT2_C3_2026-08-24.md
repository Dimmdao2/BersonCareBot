## Находка 1 (FAIL, блокирует land): восьмой пациентский Telegram/MAX-продюсер остался безусловным `clinic_required`

`apps/webapp/src/modules/messaging/doctorSupportMessagingService.ts:127-129`, ветка legacy в
`sendAdminReply`:

```ts
} else if (channelCode && channelExternalId) {
  // Legacy: диалог без platform_user_id — только канал из projection
  const senderScope =
    channelCode === 'telegram' || channelCode === 'max' ? 'clinic_required' : undefined;
  relayOutbound({ ... , ...(senderScope ? { senderScope } : {}) }, opts)
```

Это пациентское уведомление «специалист ответил» в Telegram/MAX — тот же класс интентов, ради которого
круг 2 переводил семь продюсеров на `clinic_if_configured`; сам `notifyPatientDoctorReply.ts:173` (основная
ветка того же сценария) переведён, а legacy-ветка того же метода — нет.

**Почему достижимо:** ветка берётся, когда у диалога нет `platform_user_id`. Колонка nullable —
`pgSupportCommunication.ts:945-967` читает `platform_user_id: string | null` из `support_conversations` и
отдаёт его как есть; условие основной ветки `if (platformUserId && convInfo.organizationId && opts?.…)`
(строка 114) при `NULL` не выполняется. Это ровно тот диалог, что заведён с входящего сообщения в мессенджер
до привязки платформенного пользователя.

**Что происходит у клиники без своего бота:** `relayOutbound` → `relayOutboundRoute.ts:95-100` помечает
такой запрос `broadcast_event`/`clinic_delivery` → `dispatchPort.ts:400` бросает
`CLINIC_CHANNEL_NOT_CONFIGURED:telegram` ДО адаптера. Пациент ответа врача не получает.

**Отказ дорогой и молчаливый:** вызов обёрнут в `.catch((err) => logger.error(...))` (строка 143), а
`sendAdminReply` всё равно возвращает `{ ok: true }` — врач видит «отправлено», сообщение записано в
переписку, пациенту не ушло ничего, и узнать об этом можно только из логов. Прямо против §1.2h: на пути по
умолчанию клиника ничего не настраивает, а здесь отсутствие своего бота гасит доставку.

**Правка локализована** — тот же маркер `clinic_if_configured`, что в семи остальных местах, плюс прогон
затронутых наборов. Исполнителя выбирает оркестратор по §24.1; аудитор своего продуктового fix не делает.
