## 2. Дефолт безопасен: «не задано» ≠ «выключено»

Это главный проверяемый случай пункта, и **авторский набор его не покрывал**. В
`proxy.b5Audit.route.test.ts` тест назван «отсутствующий или выключенный флаг», но обе ветки —
`tenantFor(CLINIC_ONE, ORG_ONE)` и `TENANT_ONE` — это один и тот же хелпер с параметром по умолчанию
`skipPublicCardAtRoot = false`, то есть поле в результате шва **присутствует и равно `false`** оба
раза. Клиника, у которой строки настройки нет вовсе, авторским набором не проверялась.

Поведение при этом верное: `requestSurface.ts:269` берёт `tenant.skipPublicCardAtRoot === true`,
строгое сравнение, любое иное значение падает в «показывать визитку». Пробел был в доказательстве,
не в продукте; закрыт `proxy.b5aAudit.route.test.ts`, где «не задано» строится **отсутствием ключа**
в объекте результата.

| Что вернул шов арендатора | Корень брендированного адреса |
| --- | --- |
| ключа `skipPublicCardAtRoot` нет вообще | `/` → rewrite `/ozero-clinic` (визитка) |
| `false` | `/` → rewrite `/ozero-clinic` |
| `undefined` | `/` → rewrite `/ozero-clinic` |
| `null` | `/` → rewrite `/ozero-clinic` |
| строка `"true"` | `/` → rewrite `/ozero-clinic` |
| число `1` | `/` → rewrite `/ozero-clinic` |
| `true` | `/` → rewrite `/app` |

Нестрогие значения намеренно падают в сторону визитки: дефолт пункта — показывать визитку, и
испорченное значение обязано вести туда же, а не открывать вход. `patient_default` (`/` → `/app`) и
staff-корень (без rewrite) флагом не затрагиваются.

## 3. Изоляция арендаторов

Включённый флаг `sosnovy-bor` не меняет корень `ozero-clinic` **ни в каком порядке запросов** (тест
гоняет обе последовательности в одном загруженном модуле — это ловит модульную память). Значение
приезжает только внутри уже разрешённого контекста своего хоста: в заголовке
`x-bc-resolved-surface` корня `ozero-clinic` лежит его собственная тройка
`{clinicSlug, organizationId, skipPublicCardAtRoot}`.

Изоляция на записи — структурная, не проверкой: `organizationId` в PATCH `/api/admin/settings`
берётся из доверенного гейта `requireClinicManagementApiContext`, тело запроса его не несёт (тело
проверено UI-тестом: `{"key":"clinic_root_skip_public_card","value":{"value":true}}`, без
`organizationId`). Изоляция на чтении — фильтр
`setting.organizationId === workspace.organizationId` в `app/app/settings/page.tsx:236-243`:
платформенная глобальная строка (`organizationId: null`) в кабинет клиники попасть не может.

Флаг нельзя принести запросом: `proxy.ts:155` удаляет входящий `x-bc-resolved-surface` до записи
своего, а `readResolvedSurface` отвергает разбор целиком, если флаг пришёл на непациентской
поверхности (`requestSurface.ts:347-353`).

## 9. Границы аудита

- **Боевой шов арендатора не подключён и в объём не входит.** `proxy.ts:34` по-прежнему отдаёт
  `NO_TENANT_SURFACE` (`status: 'unknown'`) для всякого запроса, где lookup не внедрён явно, поэтому
  сегодня из базы `clinic_root_skip_public_card` не читает никто: путь
  `system_settings → TenantSurfaceLookupResult.skipPublicCardAtRoot` ещё не написан. Это состояние
  досталось от `B5`/`B4a`, автор его не менял, и оно прямо вынесено за скоуп в брифе. **`B5a` доказан
  на уровне резолвера, порта настроек и кабинета, но не сквозным путём до боевой базы.**
- Конструктор страниц и выбор типа страницы пункт прямо запрещает — их отсутствие не находка.
- Галочку `B5a` в план-файле аудитор не ставит: §24.7 оставляет это лиду после собственной проверки
  полноты.
