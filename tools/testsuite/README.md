# Инструменты ревизии тестового набора (29.07.2026)

Замеры к плану `docs/_TODO/TEST_SUITE_AUDIT_2026-07-29.md`. Лежат в репозитории, чтобы цифры из плана
можно было ПЕРЕПРОВЕРИТЬ, а не принимать на веру.

| скрипт | что делает | как звать |
|---|---|---|
| `env-coupling.mjs` | ищет тесты, привязанные к обстоятельствам запуска: путь от текущего каталога, время без подмены таймеров, часовой пояс, локаль, случайность, абсолютный путь бокса, живой хост, текст `.sql` | `node tools/testsuite/env-coupling.mjs . [--list "класс"]` |
| `rename-probe.mjs` | ЗОНД: переименовывает символы, которые тесты упоминают строками. Меняет РАБОЧЕЕ ДЕРЕВО — после прогона откатывать `git checkout -- .` | `node tools/testsuite/rename-probe.mjs . [--dry --list]` |
| `mocked-out.mjs` | тестовые файлы, не исполняющие код приложения (все импорты заглушены либо импортов нет) | `node tools/testsuite/mocked-out.mjs .` |

**Все три дают КАНДИДАТОВ, а не приговор.** Проверено 29.07: ложные срабатывания есть даже в самых
острых классах. Решение по каждому — за человеком; критерий и процедура — в плане и в
`.cursor/rules/tests-check-behaviour-not-circumstances.mdc`.

Покрытие и мутации отдельными инструментами:

```bash
pnpm --dir apps/webapp exec vitest --run --coverage.enabled --coverage.provider=v8 --coverage.all
pnpm --dir apps/webapp exec stryker run stryker.pilot.json
```
